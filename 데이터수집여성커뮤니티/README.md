## 체험 시나리오

**커뮤니티**
1. **출처 구분** — 카드 좌측 색 띠로 구분됩니다. 파란 띠는 크롤링(🔗 출처명), 분홍 띠는 회원 글(✍️).
2. **크롤링 글은 본문이 없습니다 ★** — 제목 + 2~3줄 발췌 + **원문 링크**만 있습니다. 본문을 저장하지 않는 것이 저작권 대응의 핵심입니다.
3. **본인확인 게이트** — 좋아요·댓글·글쓰기를 시도하면 게이트가 열립니다. 동의 2개를 모두 체크해야 진행되고, **저장하지 않는 정보(이름·연락처·휴대폰번호)** 를 명시합니다.
4. **신고 ★** — 6가지 사유 중 **긴급 3종**(개인정보 노출·성적 괴롭힘·불법촬영물 의심)으로 신고하면 **검토 전에 즉시 가려집니다.** 일반 사유는 가려지지 않습니다.

**관리자**
5. **노출 방식 ★ 핵심** — `링크만 / 제목+발췌 / 전문 복제` 세 가지를 고르면 **실제 화면 미리보기가 바뀝니다.** 각 방식의 법적 위험도가 표시되고, 전문 복제를 고르면 4.5억 배상 판례 경고가 뜹니다.
6. **자체 글 비율** — 대시보드 두 번째 KPI입니다. 시장 검증 지표는 조회수가 아니라 이 숫자입니다.
7. **크롤링 설정** — robots.txt 확인 결과, 사이트별 딜레이(2.5~3초), 중복 방지 5단계 파이프라인.
8. **불법촬영물 대응 현황** — 신고 처리 화면 하단. 2026.7.1 이미지 확대 시행에 대한 준비 상태표.

## ⚠️ 착수 전 확인이 필요한 항목

공고 3-2에 **"단순 링크 아웃바운드 또는 요약 형태의 노출 방식 협의 필요"** 라고 적어 주신 것은 정확한 문제 인식입니다. 답을 정리했습니다.

| 방식 | 판단 |
|---|---|
| 링크만 | **자유** — 링크는 복제에 해당하지 않습니다 |
| 제목 + 짧은 발췌 | **조건부** — 원문을 대체할 수 없는 분량이어야 |
| 상세 요약 | **위험** — 원문을 읽지 않아도 될 정도면 "전재"로 판단 |
| 전문 복제 | **권장하지 않음** — 복제권·전송권 + DB제작자 권리 (4.5억 배상 판례) |

그 밖에 —
- **여성 커뮤니티에서 "안전"은 부가 기능이 아니라 제품 자체입니다.** 공고의 회원 기능은 "일반 회원가입, 로그인"뿐인데, 실제로는 누가 들어오는지가 서비스의 본질입니다. → **본인확인(성별) 게이트**를 넣었습니다.
- **2026년 7월 1일부터 불법촬영물 유통방지 조치가 이미지까지 확대**되었습니다. → 1차에는 이미지 업로드를 열지 않는 것을 권합니다.
- **크롤링 글에 달린 댓글은 원문이 사라지면 갈 곳이 없습니다.** → 게시글은 비공개, 댓글은 보존.
- **크롤링으로 채운 데이터는 커뮤니티를 만들지 못합니다.** → 검증 지표를 자체 글 작성률로.

## 기술 구성 (데모)

- 순수 HTML/CSS/JS — 빌드 불필요, 모바일 우선
- 크롤링 게시글 객체에는 **`body` 필드가 아예 없습니다**(발췌만 보유) — 전문 미저장 원칙을 데이터 구조로 강제
- 신고 긴급 사유는 실제로 피드에서 즉시 제거됩니다
- 노출 방식 전환 시 미리보기가 실제로 달라집니다(링크 291자 → 발췌 369자 → 전문 432자)
- 모든 게시글·회원·출처는 **가상 데이터**입니다 (크롤링 출처명도 가상)

실서비스 제안 스택: Next.js + Python 크롤러 + PostgreSQL + 휴대폰 본인확인 ([기획_설계.md](분석/기획_설계.md) 5장)
