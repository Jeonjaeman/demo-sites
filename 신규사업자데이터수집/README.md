# BIZSEED 비즈시드 — 신규 사업자 리드 수집 파이프라인 (데모)

## 체험 시나리오 (데모 포인트)

1. **대시보드** — 오늘 수집 412건, 연락처 확보율 89.2%, 6단계 파이프라인 처리량, 7일 추이 차트, 배치 실행 로그.
2. **사업자 목록** — 상호·주소·사업자번호 검색, 업종/지역 필터, "연락처 확보건만", "두낫콜 제외" 조합 필터.
3. **연락처 마스킹** — 기본 마스킹 상태이며, 해제하면 감사 로그에 기록된다는 안내가 뜹니다(개인정보 안전조치).
4. **엑셀 반출** — 현재 필터 조건 그대로 .xlsx 생성 (진행바 → 반출 이력 `export_logs` 기록).
5. **실패 사유 코드** — E101~E301 코드별 건수와 처리 상태. 두낫콜 등재 건은 "발신 금지"로 분리.
6. **파이프라인** — 스케줄러 5개 잡, 데이터 소스 3종 상태, "지금 실행"으로 로그 실시간 스트리밍.
7. **DB 스키마** — 6개 테이블 정의서 (산출물 「데이터베이스 테이블 정의서」를 화면으로).
8. **컴플라이언스** — 요구사항 문서를 검토하며 발견한 리스크 6건과, 각각에 대해 실제 적용한 대안.

## ⚠️ 착수 전 반드시 확인이 필요한 항목

리서치 결과, 요구사항 문서대로 구현하면 **1차 수집 자체가 성립하지 않습니다.**

- **국세청 API는 신규 사업자 "목록"을 제공하지 않습니다** — 사업자등록번호를 입력하는 진위확인·상태조회 전용입니다. 데모는 주 소스를 **행정안전부 LOCALDATA 인허가 일 변동분**(209종 업종)으로 재설계했습니다.
- **두낫콜 대조가 빠져 있습니다** — 전화권유판매는 방문판매법 §42에 따라 월 1회 이상 수신거부 확인 의무가 있고, 위반 시 과태료 최대 1,000만원입니다. 파이프라인 STEP 05에 넣었습니다.
- **"IP 우회"는 형사 리스크입니다** — 크롤링 차단을 VPN으로 우회한 행위에 정보통신망법상 침입죄가 인정된 판례가 있습니다. 우회 모듈 대신 준법 수집(robots 준수·요청 간격 2.5초)으로 설계했습니다.

자세한 근거와 대안은 [분석/기획_설계.md](분석/기획_설계.md) 2장을 참고하세요.
