# 시나리오 · 사용자 여정 — UNFRAME (데모 69)

> 기능 목록이 아니라 **시간순 사용 흐름**으로 요구사항을 재구성한 문서.
> 근거 리서치·아임웹 발견·레퍼런스는 `기획_설계.md`, 페이지 구조는 `페이지_기획.md`.

## 1. 등장인물

| 인물 | 원하는 것 | 불안해하는 것 |
|---|---|---|
| **대행사 대표/마케팅 담당 (발주자)** | 노후 사이트 해소, 제안서에 당당히 넣을 URL, 인바운드 문의 | IT를 모르는데 오픈 후 혼자 운영할 수 있나. 개발사가 사라지면? |
| **기업 고객 (잠재 광고주 — 핵심 리드)** | "우리 업종·예산대 일을 해봤나"를 3분 안에 판단 | 실적 과장, 문의 후 영업전화 폭탄 |
| **일반 소비자** | 대행사가 여는 이벤트·캠페인 참여 | (리드 아님 — 위계 3순위) |
| **구직자** | 어떤 팀인지, 지금 뽑는지 | 사이트에 채용 정보가 없음 → 이탈 |
| **관리 실무자 (막내 AE)** | 포트폴리오 등록·순서 변경이 5분 안에 끝나기 | 잘못 눌러 사이트가 깨지는 것 |

## 2. 잠재 광고주 여정 (핵심 전환 흐름)

```
발견     검색·제안서 URL·명함 → 대부분 모바일로 첫 진입
         └ index: 히어로 5초 안에 "뭘 하는 회사인지" — 안 잡히면 종료
검증     works: 내 업종 필터 → 상세에서 문제→접근→성과 읽기  ★ 전환의 본체
         └ 필터가 없으면 방문자가 목록 전체를 훑다 이탈 — 필터가 곧 전환율
판단     about: 실체 확인(연혁·위치·일하는 방식) — 오시는 길 = 신뢰 신호
문의     contact: 폼 이탈률 최고 지점 — 필드 최소 + 프리필, FAQ로 불신 선제 해소
대기     접수 확인 없으면 "간 게 맞나" 불안 → 성공 상태 즉시 표시(실구축: 자동 회신 메일)
사후     관리자 문자 알림 — 아임웹 SMS는 내용 미포함이라 회신 우선순위 판단 불가,
         커스텀 알림은 회사·업종·예산대 요약 포함 (관리자 문의함에 비교 시연)
```

## 3. 구직자 여정 (공고의 타겟 3순위 — 구멍)

잡플래닛·원티드에서 회사명 검색 → 홈페이지 → 분위기 확인 → **채용 메뉴 탐색 → 없음 → 이탈.**
공고 사이트맵에 채용 페이지가 없다. 데모에서는 about(팀·일하는 방식)이 임시로 흡수하지만,
**채용 메뉴 신설 여부는 미팅 확인 1순위** (7장 ①).

## 4. 역할별 시야 차이 (권한 설계의 핵심)

| 같은 데이터 | 방문자 (공개 사이트) | 실무자 (관리자) |
|---|---|---|
| 포트폴리오 | 게시 동의 완료 건만, 순서대로 | 전체 + 동의 상태 3단(완료/비공개/게시불가) + 드래그 정렬 |
| 비공개 케이스 | 블러 카드 (브랜드명 마스킹) | 원본 열람 + 동의 상태 변경 |
| 성과 수치 | 근거 각주와 함께 표기 | 근거(측정 도구·기간) 입력 필수 — 비면 공개 화면에서 정성 표현으로 자동 대체 |
| 이벤트 | 진행·예정/종료 목록, 팝업 | 기간 편집 → 상태·D-day·팝업 노출 즉시 재계산 |
| 문의 | 폼 제출만 | 목록 + 광고 수신 동의 필터 + 보유기간 경과 하이라이트·일괄 파기 |

## 5. 기능별 존재 이유 (전수 매핑)

| 데모 기능 | 존재 이유 (여정의 어느 지점을 지키나) |
|---|---|
| 클립 확장 히어로 영상 | 발견 단계 5초 각인 — "맞춤형 디자인"의 즉물적 증거 |
| 포트폴리오 필터 + 딥링크 | 검증 단계 — 업종으로 좁히기, 제안서에 필터 상태째 링크 공유 |
| 게시 동의 마스킹 | 광고주 저작물·NDA 보호 — 공표권 분쟁 예방(기획_설계 발견 ⑩) |
| 성과 근거 각주 | 표시광고법 실증책임(발견 ⑪) — 근거 없으면 수치 자동 강등 |
| 상세 이전/다음 순환 | 검증 단계 체류 연장 — 케이스 간 회유 동선 |
| FAQ 불신 반박 4문 | 문의 직전 이탈 방어 — 업계 불신(성과·계약·보고서·담당자)을 계약 조건으로 응답 |
| 동의 3분리 폼 | 수집·이용/제3자/광고성 분리(발견 ⑧⑨) — 이벤트 발송 적법성의 전제 |
| 팝업 기간 로직 | 이벤트 모객 — 관리자 기간 설정이 공개 화면과 단일 데이터로 연동 |
| 관리자 드래그 정렬 | 실무자 5분 운영 — 아임웹의 "작성시각 수정" 방식과 나란히 체험(발견 ①) |
| 버전 스냅샷·복원 | 발주자 실수 복구 — 아임웹은 복원 수단 없음(발견 ⑦) |
| 운영비 계산기·트래픽 시뮬 | 발주자 의사결정 — A안/B안 비교를 수치로(발견 ③④) |
| 지도 API 무의존 오시는 길 | 발주자 클라우드 계정 등록 전에도 판단 단계가 비지 않게(발견 ⑤) |

## 6. 데모가 증명하는 운영 시나리오 (클릭만으로)

1. 실무자가 새 케이스 등록 → 동의 "비공개" 선택 → 공개 화면에서 자동 블러 확인
2. 드래그로 순서 변경 → "아임웹 방식 체험" 토글 → 미래 날짜 입력 차단 경고 체험
3. 이벤트 기간을 오늘 이전으로 수정 → 공개 목록 "종료" 이동·팝업 소멸 확인
4. 문의함에서 "광고 수신 동의만" 필터 → 미동의자 발송 불가 확인 → 보유기간 경과 일괄 파기
5. 스냅샷 저장 → 순서 뒤섞기 → 원클릭 복원
