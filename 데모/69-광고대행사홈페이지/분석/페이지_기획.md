# UNFRAME — 페이지 기획 (멀티페이지 사이트맵)

> 원칙: 원페이지 랜딩 금지. 공고의 메뉴·페이지별 분리 구조를 독립 HTML 페이지로 구현한다.
> 공고 요구 메뉴: 메인 / 회사 소개 / 포트폴리오(목록+상세) / 이벤트 안내 / 고객 문의 / 관리자

## 사이트맵

```
/ (index.html)  메인 — 허브
├─ about.html   회사 소개
├─ works.html   포트폴리오 목록 (카테고리 필터)
│   └─ work.html?id=<케이스>   포트폴리오 상세 (딥링크 독립 페이지)
├─ events.html  이벤트 안내 (진행·예정·종료)
├─ contact.html 고객 문의 (FAQ + 상담 폼)
└─ admin.html   관리자 — 커스텀 포트폴리오 관리 프로그램
```

## 페이지별 기획

| 페이지 | 목적 | 방문자가 할 일 | 섹션 구성 | 다음 유도 |
|---|---|---|---|---|
| **index** | 5초 안에 "무엇을 하는 대행사인지" 각인 | 브랜드 인상 흡수 → 관심 페이지로 이동 | ① 히어로 스크럽(6s 영상·캡션 4밴드) ② 숫자 3종 카운트업 ③ Works 프리뷰 4건(지그재그)+전체 보기 ④ Services 틸트 카드 4 ⑤ 풀블리드 매니페스토 ⑥ 진행 이벤트 티저 ⑦ CTA 밴드 | works(포트폴리오 전체) · contact(문의) |
| **about** | "실체 있는 회사"라는 신뢰 | 회사가 누군지·어디 있는지 확인 | ① 서브 히어로(비전 에디토리얼) ② 일하는 방식 3원칙 ③ 연혁 가로 스크롤 아카이브 ④ 오시는 길(정적 지도+카카오/네이버 딥링크·주소 복사) | contact |
| **works** | 전환의 핵심 — 내 업종 실적 확인 | 필터로 좁혀 케이스 탐색 | ① 헤더+필터 탭 5종(URL 해시 딥링크) ② 지그재그 그리드(8건·비공개 마스킹 2건 포함) | work 상세 |
| **work** | 케이스 하나를 설득력 있게 | 문제→해결→성과 읽기 | ① 커버 ② Problem/Approach/Result(성과 수치+근거 각주) ③ 이전/다음 케이스 내비 ④ CTA | contact("이런 프로젝트 문의") |
| **events** | 재방문 계기·모객 | 진행 이벤트 확인·참여 | ① 헤더 ② 진행·예정/종료 탭 목록(D-day 실계산) ③ 팝업 배너 연동 안내 각주 | contact |
| **contact** | 단 하나의 CTA 도착지 | 문의 제출 | ① 헤더(하루 안에 답합니다) ② FAQ 4문(광고주 불신 정면 반박) ③ 상담 폼(프리필·동의 3분리·JS 성공 상태) ④ 연락처 | — (종착) |
| **admin** | 커스텀 관리자 증거물 | 발주자 관점 운영 체험 | 대시보드/포트폴리오(드래그 vs 아임웹)/이벤트·팝업/문의함/버전 이력/비용·트래픽 | — |

## 공통 구조
- 공통 헤더: 로고 + Works · About · Events · Contact + [프로젝트 문의] CTA. **현재 페이지 aria-current 표시.**
- 공통 푸터: 가상 브랜드 고지 · 페이지 링크 · 관리자 진입.
- 팝업 배너: 전 페이지 공통(진행 중+popup:true 이벤트, 오늘 하루 보지 않기).
- 공유 파일: `assets/js/data.js`(WORKS·EVENTS 단일 소스) · `assets/js/common.js`(내비·리빌·카운트업·팝업·토스트) · 페이지별 JS.
- 견적·지원서도 이 페이지 수(공개 6 + 관리자 1) 기준으로 산정한다.
