## 1. 명시된 니즈 / 숨은 니즈

- **대형 모니터 상시 표출(풀스크린)** + 무인 자동 새로고침(게이트웨이·스케줄)

### 숨은 니즈 (시나리오에서 도출)
| 단서 | 숨은 니즈 |
|---|---|
| "3곳에 흩어져 매번 수작업 취합" | 사람이 아니라 **ETL 규칙**이 통합해야 재현·일관성 |
| "코드 체계 차이·중복 집계로 오류" | 통합 자체가 **KPI 신뢰의 급소** — 틀리면 대시보드 전체가 거짓 |

| "실패비용 정량화" | 산정 **기준**이 없으면 금액이 임의 → 기준을 화면에 노출·조정 |

## 2. 웹 리서치 — 치명적 발견 (그대로 만들면 실패하는 지점)

> 우선순위: `그대로 만들면 작동하지 않음` > `운영 중 반드시 터짐` > `있으면 좋음`

### ① ERP-QMS 코드 차이 → 부적합 이중 계상 ★ (KPI 신뢰의 급소)
같은 부적합이 ERP(S오더 수입검사)와 QMS(F오더 부적합관리)에 **각각** 등록된다. S오더-F오더 매핑·코드 통일 없이 두 소스를 단순 합치면 **부적합 건수·부적합률·실패비용이 통째로 부풀려진다.** 데모 데이터에서 원시 합산 94건 vs 순 부적합 50건 — **매핑 안 하면 88% 부풀림.**
→ 데모: **오더 매핑 중복 제거 토글**이 대시보드 14개 KPI를 실제로 바꾼다. 끄면 "이중 계상 +90% 부풀림" 경고가 뜨고 부적합 건수가 실제로 튄다. 코드 통일 토글은 유형 분포가 변형 코드로 쪼개지는 것을 보여준다.

### ② 무인 상시 표출에서 새로고침 실패가 "정상처럼 보인다" ★
대형 모니터에 24시간 띄우는 화면은 게이트웨이 새로고침이 실패해도 **겉보기엔 멀쩡하다.** 어제 데이터로 오늘 품질 회의를 하는 위험. 공고의 상태흐름도 "실패(이전 데이터 유지·알림)"을 명시한다.
→ 데모: 새로고침 **실패 재현**을 돌리면 대시보드·현황판에 **명시적 stale 경고 배너 + 마지막 성공 시각**이 뜬다. "최신 아님"을 숨기지 않는다.

### ③ Power BI 상시 표출은 라이선스에 종속된다 (기술 선택의 함정)
Power BI를 공용 대형 모니터에 무인 상시 표출하려면 게시 계정·라이선스(Pro/PPU/Premium)가 화면에 **계정 종속**된다. 계정 만료·세션 로그아웃 시 현황판이 꺼진다. 공고도 "라이선스는 발주처 부담·종류 선정 착수 전 확정"을 리스크로 든다.
→ 제안: 공고가 허용한 **"동등 대안 기술"**로 **라이선스 비종속 웹 대시보드**를 제시. 상시 표출·무인 새로고침이 계정에 묶이지 않아 현황판 안정성이 높다. (Power BI 유지를 원하면 동일 ETL·KPI 로직으로 Power BI 산출도 가능.)

### ④ 실패비용 산정 기준 미확정 → 금액이 임의
"합의된 산정 기준으로 집계"라고 명시. 기준이 없으면 실패비용 KPI는 근거 없는 숫자.
→ 데모: **처분별(재작업·폐기·반품·특채) 단가표**를 운영 콘솔에 노출·편집. 바꾸면 실패비용 KPI가 즉시 재계산.

### ⑤ 소표본 부적합률의 착시
필터를 특정 업체 1곳으로 좁히면 표본 n이 작아 부적합률이 통계적으로 흔들린다. 전년 비교도 검사량 차이를 무시하면 "개선" 착시.
→ 데모: 비교를 **건수가 아닌 율(rate) 기준**으로 병기(전년 KPI 표·월별 율 오버레이).

## 6. 제안 스택 & 견적

### 제안 스택
- **대안 A(권장) — 라이선스 비종속 웹 대시보드**: Node/Python ETL(스케줄러) → PostgreSQL(스타 스키마) → 웹 대시보드(SSR). 대형 모니터 무인 표출이 계정에 종속되지 않음.
- **대안 B — 공고 원안 유지**: Power Query(ETL) + Power BI(DAX) + 온프렘 게이트웨이. 라이선스는 발주처 부담·종류 착수 전 확정.
- 공통: ERP·QMS 직접 DB 읽기 접근, 엑셀 네트워크 공유 경로, 일 1회+ 자동 새로고침, 열람 권한.
