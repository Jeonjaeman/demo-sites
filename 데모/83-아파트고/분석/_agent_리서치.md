**한 사람이 두 역할을 겸하는 지점**
- C1 인테리어 실장이 **본인 이사 때는 개인(C2)으로 구매** → 같은 계정에서 증빙을 사업자/개인으로 전환할 수 있어야 함
- A2 콘텐츠 담당이 소규모 회사에서는 **A3 CS를 겸함** → 권한은 역할 단위로 쪼개되 한 계정에 복수 역할 부여 가능해야 함
- P1 발주 담당자가 **오픈 후 A1 운영자**가 됨 → 관리자 화면의 1차 사용자는 IT 비전문가. 관리자 UI도 설명 없이 쓸 수 있어야 함

- **발견** **[확인]**: 핸드오프 실패의 대표 사례는 「디자이너 머릿속에만 있는 hover·focus·pressed 상태」와 「정의되지 않은 브레이크포인트」. Material Design의 상태 정의 — hover · focused · pressed · dragged · disabled(상호작용에 반응하지 않음), 상태 레이어로 표현. 공고의 우려 「컴포넌트와 상태별 가이드가 명확히」와 정확히 일치.
- **근거**
  - https://figr.design/blog/design-to-dev-handoff-problems
  - https://m2.material.io/go/design-states
  - https://uxcel.com/lessons/component-states-499
- **데모 구현**: **컴포넌트 플레이그라운드** — 버튼·입력·선택·체크·탭·칩·단지 카드·도면 카드·가격·면적·뷰어 툴바·스테퍼·토스트·모달에 대해 `default / hover / focus-visible / pressed / disabled / loading / error / selected` 상태 토글. 각 상태 옆에 토큰명·px 스펙. (6장 5-3 매트릭스와 동일 목록)

### F14 [P2] 「권한 없음」 화면은 권한 모델 없이 그릴 수 없다

- **발견** **[추정]**: 공고는 「권한 없음」 상태 화면을 요구하지만 고객·관리자 권한 모델을 정의하지 않았습니다. 이 서비스에는 최소 3종의 「권한 없음」이 존재 — ① 비로그인 상태로 구매·마이페이지 접근 ② **미구매 도면 원본 접근**(미리보기로 유도해야 함 — F2와 연결) ③ 관리자 역할 부족(CS가 도면 원본·매출 접근). 각각 문구·다음 행동이 다릅니다.

### 5-1. 파일 구조 (Figma)

### 5-4. 반응형 규칙
- 브레이크포인트·컬럼·거터·컨테이너 최대 폭 표
- 컴포넌트별 변환 규칙: 필터 사이드바 → 바텀시트 · 관리자 표 → (관리자는 데스크톱 전용 명시) · 타입 탭 → 가로 스크롤 + 드롭다운 · 뷰어 툴바 우측 세로 → 하단 가로 · 장바구니 요약 우측 고정 → 하단 고정 바
- 「모바일 화면을 따로 그린 화면」과 「규칙으로 대응하는 화면」 목록 분리 (F1 범위 합의와 연결)

### 5-5. 접근성
- 명도 대비: 본문 4.5:1, 큰 글자·UI 경계 3:1 — 토큰 조합별 실측값 표
- 포커스 링: 2px + offset 2px, 모든 인터랙티브 요소
- 타겟: 최소 24px(WCAG 2.5.8), 권장 터치 44px
- 드래그 대안: 뷰어 이동 버튼·키보드(WCAG 2.5.7)
- 오류는 색만으로 표시 금지(아이콘 + 문구), 입력 레이블 상시 노출
- 도면 대체 텍스트 규칙

### 5-6. 네이밍 규칙
- 컴포넌트: `Category/Component` + property는 개발 prop과 동일(`variant=primary`, `size=md`, `state=hover`)
- 레이어: 의미 이름(`price-total`, `area-exclusive`) — `Frame 123` 금지
- 화면 ID: `C-09 단지 상세`, 상태 변형은 접미사 `C-09__empty`, `C-09__loading`
- 아이콘: `icon/24/zoom-in`

### 5-7. 콘텐츠·데이터 규칙
- 최대 길이 테스트 값: 단지명 25자, 타입 18개, 동 84개, 금액 9자리
- 말줄임: 카드 제목 2줄, 표 셀 1줄 + 툴팁
- 숫자: 천 단위 쉼표, 원, ㎡ 소수 둘째 자리, 날짜 `2026.10.17`, 시각 24시간
- 데이터 출처 캡션 형식

### 5-8. 인터랙션 명세 (퍼블리싱 제외이므로 글로)
- 전환·호버·토스트 지속(4초)·모달 진입 수치(ms·easing)
- 뷰어 줌 단계(25~400%), 더블탭 동작, 휠 동작
- 로딩 규칙(NN/g): <1초 표시 안 함 · 1~2초 스켈레톤 · 2~10초 스피너 · 10초+ 진행률

### 5-9. 법적 UI 규칙 (화면에 고정)
- 가격: 첫 노출부터 VAT 포함 총액 (F3)
- 선택 동의 기본 미체크 · 소비자 측 선택지를 흐리게 만들지 않음 · 탈퇴 단계 ≤ 가입 단계 (F3)

- 면적 ㎡ 기본 (F10)
- 사업자 정보 푸터(상호·대표·주소·사업자등록번호·통신판매업 신고번호·연락처)

### 확보하지 못한 것 (정직한 공백)
- **아파트고 실서비스 URL·현행 화면** — 미팅 자료로만 확보 가능

## 7. 메인 세션 참고 — 지원서 「핵심 지적 3건」 후보

1. **F2 디지털 콘텐츠 청약철회** — 미리보기는 법적 시험사용 수단, 장바구니 다건은 미열람분 환불, 사업자 증명책임 → 결제·마이페이지·관리자 흐름으로 구현 완료
2. **F1 화면 수·반응형 기준** — 예전 공고의 「반응형웹」, 시장 관행 PC·모바일 각각 카운트 → 범위 계산기로 첫 미팅에서 합의
3. **F7 + F5 핸드오프 실체** — 뷰어 구현 방식별 기능표 + Dev Mode 없이 읽히는 가이드 → 「개발자 혼선」 우려에 대한 직접 답
