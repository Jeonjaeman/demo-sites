## ① 디자인 검수 — 애플·삼성 공식 웹사이트 시니어 웹디자이너

> 판정 기준: "레퍼런스(Realevate·Cerebrium Awwwards SOTD, RISE ETF GDWEB, 호갱노노·Zillow·Rightmove)를 아는 사람이 보면 같은 급인가."
> 결론부터: **정리는 잘 된 B2B SaaS 템플릿 급.** 토큰·상태 체계는 탄탄하지만, 이 서비스의 주인공인 "도면"이 플레이스홀더처럼 보이고, 한글 조판이 깨지고, 홈 구성은 AI 랜딩 문법 그대로입니다.

- **D1 [상] 전역 · 모든 한글 텍스트 · `word-break` 미지정**
  - 문제: 어절 중간에서 줄이 끊깁니다. 실측 예: 홈 h2 "검색 → 미리보기 → 구매·열 / 람.", 신뢰 섹션 "적습 / 니다.", 사업자 섹션 "증빙 다시 요 / 청하는", 스크럽 문장 "단지 / 를", "함 / 께", 푸터 "타입별 / 로". 한국어 사이트에서 가장 먼저 "아마추어"로 읽히는 신호입니다. 애플 코리아는 keep-all을 씁니다.
  - 수정: `html{word-break:keep-all;overflow-wrap:anywhere}` · 디스플레이·h1~h3에 `text-wrap:balance` · 본문 `text-wrap:pretty`. `.sec-head .display{max-width:22ch}`는 keep-all 적용 후 24ch로 재확인.

- **D2 [상] 전역 · 도면 이미지 `APT.planSVG()` (홈 카드 4 · 검색 카드 12 · 도면함 · 장바구니 · 레일 · 뷰어)**
  - 문제: 모든 도면이 같은 위상(상단 발코니 · 우측 거실 · 좌측 침실)의 박스 몽타주라 검색 카드 12장이 사실상 같은 그림입니다. 문·창·벽 두께 차등·실명이 썸네일에 없어 "도면 판매 서비스"의 상품 이미지가 와이어프레임으로 보입니다. 단지 카드인데 단지가 아니라 타입 도면을 대표 이미지로 씁니다(Zillow·Rightmove는 매물 사진). 방 4개 타입은 빈 칸이 생깁니다 — 관리자 검수 상세 "송도 더블유파크 120" 원본에 라벨 없는 흰 셀이 침실 사이에 노출(`planGeometry`의 `others`가 홀수일 때 2열 격자 마지막 칸 공백). 세로 치수값은 `dimX - 8`(x=10)에 `text-anchor:end`라 4자리 값이 viewBox 밖으로 잘려 "50"만 보입니다(뷰어·비교 캡처). 치수가 이 상품의 셀링 포인트인데 치수가 잘려 있습니다.
  - 수정: ① 생성기에 실별 문 호(r=0.8m)·창(외벽 이중선 + 유리선)·외벽 9 / 내벽 4 stroke 차등·방위표·스케일바를 넣고, 레이아웃 템플릿을 판상형 3bay / 4bay / 타워형 / 코너형 4종으로 `seed % 4` 분기. ② 홀수 침실이면 마지막 침실 `w = bedW`로 확장. ③ 세로 치수는 `transform="rotate(-90)"` + `text-anchor:middle`로 치수선 옆에 세워 쓰기(CAD 관례), pad를 56으로. ④ 단지 카드 대표 이미지는 도면 대신 단지 매스(아이소메트릭 일러스트, 생성 이미지 1종을 지역 톤으로 4색) 또는 배치도 미니맵 + 동 수 오버레이로 교체.

- **D3 [상] 홈·검색 `.complex-card .cc-badges .badge-pill` · 도면함 `.lib-card .lc-media .badge` · 뷰어 `.rail-item .ri-lock`**

- **D4 [상] 홈 섹션 구성 전체 (index.html 이용 3단계 · 최근 등록 · 신뢰 · 사업자)**

## ② 인터랙션 검수 — Dribbble 마이크로 인터랙션·UI 애니메이션 큐레이터

> 강도 전제: 공개 홈 중~강 · 플랫폼 화면 중 · 뷰어 즉답 · 관리자 약 · 폼 최소. 대시보드 장식 모션 제안 없음.
> 총평: 토큰(이징 8종)은 훌륭한데 **실제 화면에 쓰인 곳이 리빌·세그먼트·토스트 정도**입니다. 열리고 닫히는 거의 모든 것이 `display:none↔block`으로 순간이동하고, 상태가 바뀔 때 화면 전체를 다시 그려 깜빡입니다.

- **I1 [상] 검색 `.filterbar .dropdown-f` — 필터가 열리지 않는 것처럼 보임**
  - 문제(실측): `.filterbar-in{overflow-x:auto}` 때문에 `overflow-y`도 auto가 되어, 열린 드롭다운(top 158 · h 140)이 64px 바 안에서 잘립니다. 6px 띠만 보입니다. 지역·세대수·준공년·면적대·보유 포맷 5개가 데스크톱·모바일 모두 사실상 사용 불가입니다.
  - 구현안: 드롭다운을 `document.body`로 포털(버튼 rect 기준 `position:fixed`)하거나, 칩 스크롤 영역만 별도 래퍼로 분리하고 `.filterbar-in`의 overflow를 해제. 열림 `opacity 0→1 · translateY(-4px→0) · 160ms cubic-bezier(.2,0,0,1) · transform-origin:top`. 모바일은 패턴 문서 규칙대로 `UI.sheet()` 바텀시트(500ms `--ease-sheet`), 적용 시 결과 카드 stagger 40ms 재진입.

- **I2 [상] 모바일 메뉴 `.mnav` — 열면 닫을 수 없음**
  - 문제(실측): `inset:var(--header-h-m) 0 0 0`(top 56) 고정인데 데모 배너가 2줄(55px)이라 헤더(55~111)가 메뉴(z 40) 아래에 깔려 X 버튼이 보이지 않습니다. "내 도면함"과 "마이페이지"가 같은 my.html로 중복됩니다.
  - 구현안: 메뉴 top을 `hdr.getBoundingClientRect().bottom`으로 계산하거나 헤더 z-index를 sheet 위로. 열림 `clip-path:inset(0 0 100% 0) → inset(0)` 280ms `--ease-sheet` + 항목 stagger 30ms `translateY(8px)→0`. 햄버거→X는 두 선 `rotate(±45deg)` 모프 200ms. Esc·배경 탭으로 닫힘.

- **I3 [상] 뷰어 방향 패드 `.vw-dir`**
  - 문제(실측): 버튼 5개(↑ ← ⛶ → ↓)인데 CSS가 `nth-child(2)~(6)` 6개 기준이라 ↑(1행1열) ←(1행2열) ⛶(2행1열) →(2행2열) ↓(2행3열)로 깨집니다.
  - 구현안: `:nth-child(1){grid-area:1/2} (2){grid-area:2/1} (3){grid-area:2/2} (4){grid-area:2/3} (5){grid-area:3/2}`. 누름 피드백은 이미 있는 `scale(.92)`에 더해 해당 방향 `translate(±2px)` 100ms.

- **I4 [상] 단지 상세 탭·담기 / 타입 상세 포맷 / 환불 체크 — 전체 재렌더로 깜빡임·포커스 소실**
  - 문제: complex.js의 탭 클릭·담기는 `render()`로 `main.innerHTML`을 통째로 교체해, `[data-reveal-group]` 도면 카드 6장이 opacity 0에서 다시 리빌됩니다(650ms + stagger 최대 900ms). 클릭할 때마다 화면이 깜빡입니다. plan.js 포맷 라디오·my.js 환불 체크박스도 전체 교체라 포커스가 사라져 키보드 화살표 탐색이 끊깁니다. complex.js는 렌더마다 `document` click 리스너를 하나씩 더 붙입니다(누적).
  - 구현안: 부분 갱신으로 전환 — 탭은 `aria-selected`·배치도 하이라이트만, 담기는 해당 카드 버튼만, 포맷은 `.bb-total .price`만 `UI.countUp(from,to,{dur:280})`. 재렌더가 불가피하면 새 그룹에 `is-in`을 미리 붙여 재리빌을 막고, 포커스는 `data-focus-key`로 복원.

- **I5 [상] 장바구니 담기 피드백**
  - 문제: 토스트 하나뿐이고 헤더 `.cart-count`는 숫자만 바뀝니다. "모든 타입 JPG로 담기 (6개)"는 구매함 3개를 빼고 실제로 3개만 담는데 라벨은 6개이고, 토스트의 "묶음 할인 10% 적용"은 n이 1~2일 때도 뜹니다(안내 문구 ≠ 실제 동작).
  - 구현안: 버튼 아이콘 cart→check 모프 150ms + 라벨 "담김" 크로스페이드, 썸네일 복제본이 헤더 카트로 날아가는 fly-to-cart(`transform` 520ms cubic-bezier(.2,.8,.2,1), reduced-motion에선 생략), 배지 `scale(1→1.25→1)` 260ms. 라벨은 담길 수 기준 "남은 3개 타입 담기", 할인 문구는 n≥3일 때만.

- **I6 [중] 탭 인디케이터 불일치 `.tabs .tab`**
  - 문제: `.seg`는 슬라이딩 인디케이터(Cerebrium 이식)인데 단지 타입 탭은 `border-bottom` 색만 바뀌어 순간이동합니다.
  - 구현안: `.tabs`에 인디케이터 1개(`::after` 또는 `i.tab-ind`)를 두고 `transform:translateX(x) scaleX(w)` 220ms `--ease-data`. 탭 넘침 시 활성 탭 `scrollIntoView({inline:'center',behavior:'smooth'})`.

- **I7 [중] 순간이동 팝업 전부 — 자동완성 `.sb-drop` · `.dropdown` · 검토 패널 `.dpanel-box` · 핀 팝업 `.pin-pop`**
  - 문제: `display:none↔block`이라 전환이 없습니다.
  - 구현안: 공통 `.pop{opacity:0;transform:translateY(-4px) scale(.98);visibility:hidden;transition:opacity 160ms,transform 160ms var(--ease-std),visibility 0s 160ms}` / `.pop.open{opacity:1;transform:none;visibility:visible;transition-delay:0s}`. 자동완성 항목 stagger 20ms, 키보드 포커스 항목 배경 120ms.

- **I8 [중] 뷰어 줌 앵커·이징**
  - 문제: 휠·더블탭 확대가 화면 중앙 기준이라 커서 아래 지점이 도망갑니다. 버튼 줌 전환은 `var(--dur-press)` 100ms ease-in-out으로, 기획 문서의 "줌 이징 160ms"와 다릅니다. 줌% 숫자 폭이 바뀌어 툴바가 흔들립니다.
  - 구현안: 휠·더블탭은 포인터 좌표를 앵커로 `px = cx - (cx - px)·nz/z` 보정, 휠은 무전환 + rAF 보간, 버튼 줌 `transform 160ms cubic-bezier(.2,0,0,1)`. `.zv{font-variant-numeric:tabular-nums;width:52px}`.

- **I9 [중] 성공 상태가 정적 — 결제 완료·가입 완료·입금 확인·환불 완료 `.rs-ico.ok`**
  - 구현안: 체크 SVG `stroke-dasharray` 드로잉 420ms cubic-bezier(.65,0,.35,1) + 타일 `scale(.8→1)` 240ms + 링 펄스 1회(600ms, opacity .4→0). 1회 재생, 반복 금지. 실패 아이콘은 모션 없이 색만.

- **I10 [중] 주문서 결제 버튼 → 결제 진행 상태 없음**
  - 문제: 1.4초 버튼 스피너 후 하드 이동이라 PG 결제창·승인 중 단계가 보이지 않습니다. 동의 미체크 오류는 테두리 색만 바뀝니다.
  - 구현안: 버튼 로딩 → 하단 시트 "결제사 승인 중"(결제창 열림 → 승인 → 기록 3단계, 각 단계 체크 전환 200ms). 동의 오류는 consent-box를 `scrollIntoView({block:'center'})` + `box-shadow 0 → 0 0 0 4px var(--danger-tint)` 300ms 1회. 흔들기(shake)는 폼 최소 원칙상 쓰지 않습니다.

- **I11 [중] 스켈레톤 `.skeleton`**
  - 문제: 200% 그라디언트를 깔아 놓고 `background-position` 애니메이션 없이 opacity `pulse`만 돌려 그라디언트가 무의미합니다.
  - 구현안: `@keyframes shimmer{to{background-position:-200% 0}}` 1.4s linear infinite. 스켈레톤 → 실카드는 같은 높이로 크로스페이드 200ms(레이아웃 시프트 0).

- **I12 [중] 홈 히어로 전체가 `[data-reveal]`**
  - 문제: `.hero-in`이 opacity 0에서 시작해 검색창(주 동작)과 LCP 이미지가 650ms 늦게 보입니다. 저장소 규칙("모션 때문에 첫 렌더가 늦어지는 것 금지") 위반입니다.
  - 구현안: `.hero-in`에서 `data-reveal` 제거, h1 라인 리빌(700ms `--ease-editorial`)과 이미지 scale 1.06→1만 유지. 검색창은 즉시 표시.

- **I13 [중] 토스트 `.toasts`**
  - 문제: 쌓임 상한·닫기·스와이프가 없고, 퇴장이 인라인 opacity만(이동 없음)이라 여러 개가 겹치면 덜컥거립니다. "장바구니에서 뺐습니다"에 되돌리기가 없습니다.
  - 구현안: 최대 3개, 퇴장 `translateY(8px)+opacity` 200ms, 모바일 아래로 스와이프 닫기, 삭제류 토스트에 "되돌리기" 액션(5초).

- **I14 [하] 카드 호버 계층 불일치**
  - 문제: `.complex-card`만 lift + 그림자 + 이미지 scale이고, `.plan-card`·`.lib-card`·`.order-card`·`.rail-item`은 그림자 또는 테두리만 바뀝니다.
  - 구현안: 클릭 가능한 카드 전부 `translateY(-2px)` + `--sh-card-hover` 200ms, 썸네일 `scale(1.03)` 800ms `--ease-media`. 터치 기기는 `:active{transform:scale(.98)}` 100ms.

- **I15 [하] 복사 버튼 — 계좌·주문번호·링크 복사**
  - 구현안: 아이콘 copy→check 모프 150ms, 1.5초 후 복귀, `aria-live="polite"`로 "복사됨".

- **I16 [하] 금액 변경 — 환불 예정액·장바구니 총액·관리자 환불 가능액**
  - 구현안: `UI.countUp(이전값→새값, {dur:320})` + 증감 방향 색 플래시 600ms(증가 `--positive`, 감소 `--ink-3`). 관리자도 상태 피드백이므로 허용 범위.

- **I17 [하] 관리자 일괄 처리 바 `.a-bulk` · FAQ `details`**
  - 문제: 행 선택 시 bulk bar가 즉시 붙고 즉시 사라집니다. FAQ는 "+" 회전만 있고 내용이 튀어나옵니다.
  - 구현안: bulk bar `translate(-50%,16px)→(-50%,0) + opacity` 200ms(관리자 약 강도 내). FAQ는 `interpolate-size:allow-keywords` + `::details-content{transition:height 240ms,content-visibility 240ms allow-discrete}`(미지원 브라우저는 즉시).

### 미충족·부분 항목 (지적 목록)

- **R1 [상] 결과물 · Figma 원본 강등** — 공고의 결과물은 "Figma 원본 파일(컴포넌트 가이드 포함)" 단 하나이고 관련 기술도 Figma입니다. handoff.html 리드 "Figma는 보조 산출물로 둡니다", 포함 목록 "Figma 원본(**요청 시**)", proposal "Figma 보조 산출물(요청 시)"은 의뢰 조건을 바꾸는 문장이라, 내부 담당자 검토 단계에서 탈락 사유가 될 수 있습니다.
  - 수정: 프레이밍을 **"Figma 원본(공고 결과물: Components·Variants·Variables·Dev Mode 주석) + 같은 토큰의 기초 HTML(추가 제공)"**으로 뒤집고, "요청 시" 삭제. handoff에 Figma 증거 1개 추가 — 파일 구조 스크린샷(Foundations / Components / Customer-PC / Mobile / Admin / States 페이지) 또는 Button 컴포넌트의 Variants 표(Type × State × Size)를 이미지로.

- **R2 [상] 수행 범위 · 기존 화면 분석 미시연** — 공고 SW 개발 범위의 첫 항목인데, 데모에는 1주차 게이트 체크박스("기존 화면·페이지 리스트 수령")뿐입니다.
  - 수정: proposal에 "현행 화면 진단 양식" 1블록 — AS-IS 캡처 자리 · 발견(휴리스틱 10원칙 중 위반 항목) · 심각도 · TO-BE 화면 ID 매핑 · 데모의 어떤 화면이 이 진단의 답인지. 예시 1행이라도 실제로 채워 보여 주세요(가상 AS-IS 와이어 1장).

- **R3 [상] 결제 흐름 · 직접 진입 막다른 화면** — `pending.html`·`complete.html`·`order.html`·`refund.html`을 쿼리 없이 열면 "주문을 찾을 수 없습니다"만 뜹니다(환불은 버튼도 없음, `.empty` 컴포넌트도 안 씀). 의뢰자가 페이지 목록을 보고 하나씩 열면 결제 흐름 4개 화면을 검토할 수 없고, "입력 없이 클릭만으로 체험" 원칙도 깨집니다. `failed.html`은 장바구니가 비어 있으면 "장바구니 0건은 그대로 보존되어 있습니다"라고 씁니다.
  - 수정: 쿼리가 없으면 `Store.state.orders[0]`(paid) 또는 샘플 pending 주문으로 폴백, 상단에 "예시 주문으로 보는 중" 칩. 진짜 없음 상태는 `.empty`(아이콘 + 설명 + [주문 내역][단지 검색]). 실패 화면 보존 문구는 장바구니 0건이면 숨김.
