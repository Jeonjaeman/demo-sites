# MIYABI Seoul — 시나리오 · 사용자 여정

> 기능 목록이 아니라 시간순 사용 흐름으로 니즈를 재구성한 문서입니다. 모든 인물·데이터는 가상.

## 1. 등장인물

| 인물 | 누구인가 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| 佐藤 結衣 (27·오사카·회사원) | 3박 4일 서울 여행. 퍼스널컬러+촬영+피부관리 목표 | 일본어로 전부 끝내기·일정 안에 알차게 배치 | 말이 안 통함·바가지·예약 펑크·시술 부작용 |
| 결제 카드 | JCB (일본 점유 특성) | 엔화 감각으로 금액 파악 | 환율·해외수수료가 얼마인지 모름 |
| 운영자 (한국·소규모 팀) | 제휴 시설 42곳 관리 | 예약·정산·상태를 한 화면에서 | 노쇼·의료 규제 위반·시설별 정산 누락 |
| 제휴 클리닉 | 외국인 환자 관심 | 통역된 상담 예약만 안정적으로 | 미등록 알선 연루·불법 광고 리스크 |

한 사람이 두 역할을 겸하는 지점: 없음(순수 B2C). 대신 **같은 예약 데이터**를 고객/운영자가 다른 시야로 봅니다(5장).

## 2. 시간순 여정 — 유이의 3박 4일

| 단계 | 상황 | 쓰는 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 발견 (여행 4주 전) | 인스타에서 퍼스널컬러 진단 영상을 보고 검색 "韓国 パーソナルカラー 予約" | 일본어 SEO 랜딩(프로그램 상세) | 구글 재팬에서 안 잡힘 → 유입 자체가 없음 |
| 비교·판단 | 가격이 원화뿐이면 감이 안 옴. 일본어 리뷰를 찾음 | 상세(JPY 병기·리뷰)·特商法 표기 | 엔화 감각 없음→이탈. 特商法 없음→"수상한 해외 사이트" |
| 일정 설계 | 진단→시술 상담→촬영 순서를 어떻게 배치? 시술 다음날 촬영해도 되나? | 여정 플래너(다운타임 경고) | 레이저 다음날 촬영 예약→현장에서 낭패, 리뷰 악화 |
| 예약 (3주 전) | 날짜/시간 선택, 알레르기 기입 | 예약 위저드(캘린더·슬롯·사전 문진) | 슬롯 정원 없으면 더블부킹. 문진 없으면 당일 거절 |
| 결제 | JCB로 사전결제. 취소 규정 확인 | 결제 스텝(JCB·취소 정책 동의) | JCB 미지원=일본 카드 상당수 거절. 규정 미고지=분쟁 |
| 의료 상담 신청 | 클리닉은 "상담 무료" — 결제 없이 신청 | 의료 위저드(3단계) | 시술을 플랫폼 결제로 받으면 미등록 유치업 리스크 |
| 대기 (전일) | 리마인드·길안내를 LINE으로 수신 | (실구축: LINE 공식계정) | 메일만 보내면 일본 사용자는 안 봄 → 노쇼 |
| 실행 (현지) | 폰으로 예약 확인·시설 이동 | 마이페이지(모바일) | PC 전용이면 현지에서 무용지물 |
| 변경·취소 | 동행 사정으로 1건 취소 | 취소 모달(수수료 실계산·환불액 표시) | 수수료 불투명→카드사 차지백 분쟁 |
| 사후 | 영수증 필요(회사 복지포인트)·리뷰 작성 | 영수증 다운로드·리뷰 모달 | 영수증 없음=재방문 동기 하락. 의료 후기 게재=의료법 위반 |

## 3. 운영자의 하루 (admin)

1. 출근 → 대시보드: 오늘 예약 2건·이번 주 매출·상담 대기 3건 확인
2. 주간 캘린더에서 의료(블루)/비의료(브론즈) 일정 파악 → 통역 인력 배치
3. 결제 대기(pending) 1건 → 고객 LINE 확인 후 상태 변경
4. 신규 제휴가 성사된 프로그램 노출 켜기·성수기 가격 조정 (1만원 미만 입력은 차단)
5. 월말: 정산 탭 — 카테고리 매출·PG 수수료(4.5%)·정산 예정액 확인, CSV로 회계 전달
6. 의료 카테고리는 "상담 N건"만 집계 — 시술 매출이 플랫폼 장부에 없어야 정상(유치업 구조)

## 4. 역할별 시야 차이 (권한 설계의 핵심)

| 데이터 | 고객(유이) | 운영자 | 제휴 시설(실구축 시) |
|---|---|---|---|
| 예약 | 본인 것만 | 전체 + 상태 변경 | 자기 시설 것만 (읽기+완료 처리) |
| 결제액 | 본인 결제·환불액 | 전체 매출·수수료·정산 | 자기 시설 정산분만 |
| 문진(알레르기) | 본인 입력 | 열람 (당일 안전 확인) | 당일 해당 예약만 |
| 리뷰 | 작성(의료는 평점만) | 게재 관리·신고 처리 | 답글만 |
| 의료 상담 | 신청·일정 | 일정 관리만 (시술 계약 관여 안 함) | 계약·수납 전체 (직접) |

## 5. 기능별 존재 이유 전수 매핑

| 기능 | 존재 이유 (여정 단계) |
|---|---|
| JA 기본+i18n 구조 | 발견~사후 전 구간. 언어 추가=사전 파일 추가 |
| JPY 병기 | 비교·판단 — 엔화 감각. 결제는 KRW임을 동시 고지(환율 착오 분쟁 방지) |
| 여정 플래너+다운타임 경고 | 일정 설계 — 컨시어지의 실체. "시술 다음날 촬영" 사고 방지 |
| 슬롯 마감 표시 | 예약 — 정원 관리, 더블부킹 방지 |
| 사전 문진(알레르기) | 예약 — 당일 거절·사고 예방, 노쇼 감소 |
| JCB 우선 결제 | 결제 — 일본 카드 대응이 전환율 그 자체 |
| 취소 수수료 단계+실계산 | 변경·취소 — 차지백 분쟁 방어. 特商法 표기와 동일 규정 |
| 의료/비의료 분리 동선 | 전 구간 — 유치업 등록 구조(법)를 UX로 구현 |
| 리뷰 의료 분기 | 사후 — 의료법 §56 방어하면서 신뢰 신호 유지 |
| 特商法 표기 | 비교·판단 — 일본 소비자의 신뢰 판단 기준점 |
| LINE 동선 | 대기·실행 — 일본 표준 메신저. 폼 문의는 보조 |
| 영수증 다운로드 | 사후 — 회사 복지·경비 처리 수요 |
| 관리자 상태 흐름(paid→done 등) | 운영 — 예약 생애주기를 한 화면에서 |
| CSV(BOM) | 운영 — 회계·세무 전달, 엑셀 한글/일문 무손상 |

## 6. 명시 vs 숨은 니즈

- 명시: 공고 12항 (기획_설계.md 1장 표)
- 숨은: ⑴ 의료/비의료 법적 분리 ⑵ LINE 중심 CS ⑶ 다운타임 기반 일정 설계 ⑷ JPY 병기·JCB ⑸ 特商法 신뢰 표기 ⑹ 사전 문진 ⑺ 취소 수수료 투명화 — 전부 데모에서 동작으로 구현

## 7. 비는 구멍 — 미팅에서 확인할 것

1. **유치업 등록**: 누가·언제 등록하나? (등록 전엔 의료 카테고리 오픈 불가 — 비의료 먼저 오픈하는 2단계 런칭 제안)
2. **제휴 계약 형태**: 수수료율? 정산 주기(월 1회/T+7)? 시설이 직접 슬롯을 관리하나, 운영자가 대리 입력하나?
3. **통역 동행**: 자체 인력? 프리랜서 풀? 예약과 통역 배정의 연동 범위
4. **노쇼·지각**: 슬롯은 언제까지 잡아두나? 지각 시 단축 진행인가 취소인가
5. **환불 분쟁**: 카드 차지백 대응 주체·창구 (해외카드는 분쟁 비율이 높음)
6. **리뷰 운영**: 신고·삭제 기준, 시설의 반론권
7. **개인정보 국외이전**: 일본 거주자 정보를 한국 서버에서 처리 — 동의 문구·프라이버시 정책의 일본어 법률 감수
8. **환율 표기**: JPY 환산율 기준(전일 매매기준율 등)과 갱신 주기 — 표기 착오는 分쟁 소지
9. **성수기 가격**: 시즌 변동가 필요 여부 (현 데모는 단일가+관리자 수정)
10. **2언어 확장 시점**: EN·繁中 오픈 기준 (구조는 준비돼 있음 — 번역·감수 비용만 발생)
