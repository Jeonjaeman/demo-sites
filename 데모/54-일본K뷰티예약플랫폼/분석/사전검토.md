## 3. 사전 파악 리스크 — 착수 시 리서치로 확정할 후보

> 아래는 사전 지식 기반 스케치입니다. **근거 URL 확보 전이므로 단정하지 않고, 착수 시 2단계 리서치(최소 4회)로 확정합니다.**

- **① 외국인환자 유치업 등록 (최대 후보)** — "병원" 예약을 중개하면 단순 예약 플랫폼이
  아니라 「의료 해외진출 및 외국인환자 유치 지원에 관한 법률」상 **외국인환자 유치업자 등록**
  대상이 될 수 있습니다(보증보험·자본금 요건, 미등록 알선 시 형사처벌 소지). 병원과
  에스테틱·헤어를 **같은 예약 흐름에 섞으면 안 되는** 구조적 이유 → 데모에서 "의료/비의료
  분리 동선"을 기능으로 보여줄 수 있는 지점.
- **② 리뷰 시스템의 의료광고 이슈** — 의료기관 대상 치료경험담·후기는 의료법상 광고 규제
  대상이 될 수 있음. 비의료(헤어·메이크업) 리뷰와 의료 리뷰의 노출 정책을 분리해야 할 가능성.
- **③ 해외 카드 사전결제** — 일본 카드는 **JCB 대응**이 사실상 필수. 해외카드 PG(엑심베이
  등) 수수료·정산 통화·환불(취소 규정) 정책 설계가 견적 항목. 노쇼 대비 취소 수수료 단계 설계.
- **④ 통신판매·특정상거래법 표기** — 일본 소비자 대상 전자상거래 시 일본 特定商取引法 표기
  페이지 관행(일본 사용자가 신뢰 판단에 실제로 확인하는 요소) 검토.
- **⑤ 일본 SEO 실체** — Yahoo! JAPAN은 구글 검색 엔진 사용 → 구글 최적화가 곧 야후 대응.
  일본어 hreflang·구조화 데이터·현지 표기 품질이 핵심. (리서치로 최신 상태 확인)

## 4. UX 제안 후보 (공고의 "개선 아이디어" 요청 대응)

- **LINE 상담 동선** — 일본 사용자 표준 메신저는 LINE. 문의를 폼이 아니라 LINE 공식계정
  버튼 중심으로. (카톡 아님)
- **의료/비의료 분리 컨시어지 동선** — ①의 법적 구조를 UX로 풀기: 병원은 "상담 신청 →
  제휴 유치기관 연결", 비의료는 "즉시 예약·결제"로 흐름 분리.
- **여정 플래너** — 방한 일정(도착~출국)에 예약을 배치하는 타임라인 뷰. 시술 후 회복
  시간(다운타임)을 고려한 일정 충돌 경고 — "시술 다음날 메이크업 촬영" 같은 실수 방지.
- **환율 병기** — KRW 결제 금액에 JPY 환산 참고 표기.
- **사전 문진/알레르기 정보** — 예약 시 수집해 노쇼·현장 거절 감소.

## 5. 데모 범위 제안 (착수 시)

| 표면 | 내용 |
|---|---|
| 공개(일본어) | 프리미엄 브랜드 홈(풀블리드·텍스트 애니) + 프로그램 목록/상세 + 예약 위저드(날짜/시간/인원→사전결제 시뮬) + 마이페이지(예약 조회·취소) + 리뷰 + LINE 문의 |
| 관리자 | 예약 캘린더·고객·프로그램 CRUD·정산 요약 대시보드 |
| 기능화할 발견 | 의료/비의료 분리 동선 · 리뷰 노출 정책 · 취소 수수료 단계 · 여정 플래너 |

- 언어: 데모 화면은 **일본어 기본 + JA/KO 스위처**(검토자는 한국인 의뢰자이므로).
- 예상 데모 공수: 3~4일 (리서치·실측·레드팀 4종 포함)

## 6. 견적 스케치 (실구축 · 착수 후 정밀 산정)

범위가 회원+예약+결제+리뷰+관리자+다국어 준비+SEO로 **이 저장소 기준 대형**입니다.
일 5만 규칙으로 대략 **70~90일 = 350~450만원(VAT 별도)** 구간 예상.
확정은 착수 시 항목별 공수표로. 유지보수(월)·의뢰자 부담(PG 수수료·해외카드 심사·
유치업 등록은 사업자 명의) 분리 명시.
