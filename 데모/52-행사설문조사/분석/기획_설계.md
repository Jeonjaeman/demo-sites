# CONFETTI 콘페티 — 기획·설계

> 오프라인 행사 부스 전용 모바일 웹 설문조사 페이지 구축 (위시켓, 150만·14일·지원 35) · 제안용 데모
> 행사·문항·응답 데이터 전부 가상

## 0. 공고 요약
- 행사장 **X배너 QR 스캔 → 모바일 전용 반응형 웹 설문** · 로그인·본인인증 생략(즉시 진입)
- 범위: 상세 기획(화면 설계·모바일 최적화) + UI/UX 디자인(**밝은 톤·애니메이션**) + 프론트 + 백엔드(수집 서버·**엑셀 다운로드**) + 서버/DB/인프라
- 2-1 사용자: 세로 모드 최적화 · 비회원 즉시 진입 · 객관식+주관식 · **문항 전환 간 애니메이션** · 응답별 최적 입력 폼(라디오·텍스트박스 등) · 완료 시 전체 응답 서버 전송
- 2-2 관리자: 전체 응답 **엑셀(Excel) 파일 다운로드** · 설문 URL **인쇄용 QR 생성·제공**
- 스택 자유 · 클라이언트가 설문 문항·기획안 제공 · 납품 8/17 이전 · 우선순위 1순위 산출물 완성도
- 관련 기술 태그: AWS · excel export · express.js · MongoDB · Node.js

## 1. 명시 vs 숨은 니즈
| 구분 | 내용 |
|---|---|
| 명시 | 밝고 빠른 모바일 설문 + 엑셀 + QR |
| 숨은 ① | 부스 설문의 성패 = **이탈률** — 문항당 3초, 라디오는 선택 즉시 다음 문항으로 넘어가야 줄이 안 밀림 |
| 숨은 ② | **행사 피크 동시 접속** — QR 스캔이 몰리는 시간대(개장·경품 추첨 직후) 서버 순단 대비 |
| 숨은 ③ | 부스 공용 태블릿·스태프 폰으로도 돌리는 경우 — 제출 후 자동 초기화(다음 방문객) 필요 |
| 숨은 ④ | "엑셀"은 CSV가 아니라 **Excel 포맷 그대로** 기대하는 경우가 많음 — 한글 깨짐·서식 문제 |
| 숨은 ⑤ | 8/17 납품 = 실질 2주 — 기획안이 이미 있으므로 화면 수 고정·범위 밖 차단이 일정의 핵심 |

## 2. 화면 구성 — 공고 조항 → 데모 매핑 (레드팀 ④ 체크리스트)
| 공고 조항 | 판정 | 데모 근거 |
|---|---|---|
| 모바일 세로 최적화 | ✓ | 폰 프레임·실기기 풀스크린 |
| 비회원 즉시 진입 | ✓ | 커버 → 시작 (로그인·인증 없음 문구 명시) |
| 객관식+주관식 | ✓ | 라디오·복수선택·별점·200자 텍스트 |
| 밝은 톤 + 애니메이션 | ✓ | 옐로·코랄 팔레트 · 선택지 stagger 진입 · 별점 바운스 · 완료 콘페티 |
| **문항 전환 간 애니메이션** | ✓ | 카드 슬라이드 전환(진행바 연동) — 라디오는 선택 즉시 자동 전환 |
| 응답별 최적 입력 폼 | ✓ | 문항 유형별 라디오/체크/별점/텍스트카운터 |
| 완료 후 서버 전송 | ✓ | 제출 시 적재(데모 localStorage — 실서비스 Node+MongoDB) |
| 관리자 엑셀 다운로드 | ✓ 문구 그대로 | **.xls(SpreadsheetML) 실생성** — 헤더 스타일·숫자 타입, 한글 무손상 (+CSV BOM 병행) |
| 인쇄용 QR 생성·제공 | ✓ | 실스캔 QR + **인쇄용 PNG 다운로드** |
| 기술 태그(Node·MongoDB·AWS) | 제안 일치 | 지원서 스택 제안에 반영 |
