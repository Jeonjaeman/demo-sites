[1] 요구대로 만들면 놓치는 지점 3곳

1. 브라 속 센서 1개가 알려주는 "좌우"는 팔의 좌우가 아닙니다
상부 몸통 IMU 1개는 왼팔·오른팔의 차이를 구분하지 못합니다(상부 몸통 IMU로 편측·양측 부상군을 구분하지 못한 연구, Bournemouth 2022). 1개로 나오는 것은 몸통이 좌우로 기운 시간·최대각(roll)과 좌우로 돈 각(yaw)의 분포이고, 그중 회전은 자기센서에 의존해 실내 철골·금속에서 왜곡됩니다. "좌우 움직임 비교 그래프"를 이 정의로 먼저 합의해야 하고, 왼팔 vs 오른팔을 원하시면 센서가 양팔·양 견갑에 최소 2개 필요합니다(센서 업체 확인 항목).
→ 데모 세션 상세의 「좌/우」: 기울기 부호별 시간·최대각 미러 막대, 축을 「절단측·건측」으로 바꿔 왼쪽 절단 선수와 오른쪽 절단 선수를 같은 축에서 읽기, 자기장이 불안정한 구간은 회색 음영 + 회전 신뢰도 낮음 표기. 센서를 앞뒤로 뒤집어 달기만 해도 결론이 반대가 되므로, 업로드 때 시작 보정 동작(5초 정지 + 왼쪽 기울이기 3초) 구간의 부호를 계산해 반전을 잡아냅니다.

2. CSV를 정확한 세션에 붙이는 것만으로는 부족합니다 — 조건이 다르면 v1↔v2 비교가 허상입니다
의수 착용 여부만으로 흉곽·골반 회전이 달라지고(일본 체육대·JISS), 의복에 붙인 센서는 밀착 센서와 자세 편차가 생기며(DFKI 2023), 펌웨어·샘플링이 바뀌면 같은 시스템이 아닙니다. 브라 v2의 개선 효과를 말하려면 같은 조건에서 잰 세션끼리만 비교해야 합니다.
→ 세션마다 측정 조건(센서·펌웨어·Hz·장착 위치·방향·의수·보정 동작)을 기록해 지문을 만들고, 비교 화면이 다른 항목을 빨간 칩으로 먼저 보여 줍니다. 「공정 비교」를 켜면 같은 조건만 남고, 「버전 비교 프리셋」은 조건이 같은 쌍만 자동으로 짝지어 줍니다. 기간 추이는 버전 변경 시점을 세로선으로, 조건이 다른 세션은 속이 빈 점으로 분리합니다.

3. 컬럼 이름이 같아도 단위가 바뀌면 "형식 자동 확인"은 통과합니다
센서 앱은 별도 업체가 개발 중이고 실데이터는 납품 뒤에 들어옵니다. 펌웨어가 바뀌어 자이로가 °/s에서 rad/s로, 가속도가 g에서 m/s²로 바뀌어도 컬럼 이름이 그대로면 매핑 검사로는 걸러지지 않습니다. 엑셀로 한 번 열었다 저장한 CSV는 13자리 타임스탬프가 1.79E+12로 바뀌어 복원이 안 됩니다.
→ 업로드 3단계(매핑 → 물리 검사 → 연결): 정지 구간 가속도가 1g인지, 최대 각속도로 단위가 맞는지, 실제 샘플링이 몇 Hz인지, 세션 시간과 9시간 어긋나면 UTC 기록인지, 같은 파일이 이미 다른 세션에 붙었는지, 지수 표기가 있는지를 값으로 판정해 통과·경고·차단으로 나눕니다. 불량 CSV 8종을 미리 넣어 두었고, 센서 업체가 실데이터 접근 없이 샘플만 넣어 규격을 맞추는 「규격 검증기」를 함께 드립니다.

그 외 — 익명 ID를 써도 대응표가 있는 한 법적으로는 가명정보라 장애·신체 정보는 민감정보 별도 동의가 필요하고(동의 전엔 업로드가 실제로 차단), 접속기록 2년 보관·매핑 보관함 열람 사유 기록·준식별자 제외 내보내기(k<3 경고)를 넣었습니다. 엑셀은 세션 요약용, 원본은 CSV로 분리해 104만 행 한도·수식 주입을 피했고, 모든 지표에 "기술 통계 — 의학적 판단 아님"을 고정해 의료기기 판단 기준에 걸릴 문구를 쓰지 않았습니다. 입력하는 선수 본인이 한 손을 쓰기 어려울 수 있어 선수 웹은 드래그·핀치 없이 탭만으로 업로드·평가·그래프 확대가 되게 만들었습니다.

[2] 제안 필수 사항에 대한 답

적합한 기술 스택
PostgreSQL(Supabase 서울 리전) + 행 단위 권한(RLS) + React/TypeScript 정적 배포. "선수는 본인 데이터만"을 화면이 아니라 DB가 강제하고, 표준 SQL이라 다른 업체가 그대로 인수합니다. 국내 리전이라 개인정보 국외 이전 쟁점이 없고, PostgREST가 API 명세(OpenAPI)를 자동 생성해 후속 센서 앱 자동 연동이 같은 API를 씁니다. 무료 플랜은 1주 비활성 시 정지·백업 없음·업로드 50MB라 월 $25 플랜을 권합니다(의뢰사 부담).

성공적으로 마무리되었다고 보는 기준
① 가상 선수·세션으로 등록→동의→업로드→조회→비교→추출이 검수 체크리스트(공고 조항 21항목) 상 오류 0건 ② 선수 계정으로 타 선수 세션 주소·API를 호출해도 0건 ③ 불량 CSV 8종이 각각 정확한 사유로 경고·차단 ④ 조건이 다른 세션 비교 시 100% 경고 ⑤ 요약 xlsx·원본 CSV가 엑셀에서 한글 깨짐·수식 실행 없이 열림 ⑥ 비참여 개발자 1명이 README만 보고 1시간 안에 로컬 실행 ⑦ 11/30 전 결과물 5종 + 증빙사진 포함 검수조서, 모든 계정이 의뢰사 명의.

아직 정하지 않은 범위 3개
좌우 비교 그래프 — 포함(단, "몸통 좌우 분포"로 정의 한정, 판정·점수는 후속). 빼더라도 절단 측과 측정 조건, 세션 지표 테이블은 지금 만들어 두어야 나중에 과거 세션을 다시 정리하지 않습니다. 기간별 추이 — 포함(가장 싸고 결과보고 효과 큼, 1~2일). 빼면 세션 요약 엑셀로 피벗 차트 대체가 가능합니다. 업로드 형식 자동 확인 — 반드시 포함. 빼면 첫 실데이터의 문제가 센서 업체·유지보수 업체·의뢰사 사이의 책임 공방이 됩니다.
확인이 필요한 것: CSV 샘플(가상이라도)·컬럼·단위·Hz, 자세값(쿼터니언/오일러) 포함 여부(원시값뿐이면 자세 계산은 공고가 제외한 센서 분석 영역), 센서 개수·위치, 타임존, 의수 착용 기록, 실증 선수 수, 동의·IRB 계획, 14세 미만 포함 여부, 과제 협약 종료일·검수 방식, 서버 계정 명의·월 비용 부담 주체.

인수인계 구조
모든 계정(클라우드·저장소·도메인·메일)은 처음부터 의뢰사 명의로 만들고 저희는 초대 멤버로 들어갑니다. 번호순 SQL 마이그레이션(스키마·권한 정책·컬럼 설명 전부), 가상 데이터 시드 생성기(센서 앱 없이 전 흐름 재현), CSV 규격서 v0.1 + 샘플 + 불량 픽스처, ERD·데이터사전·운영 매뉴얼·계정 소유표·검수조서를 납품하고, 비참여 개발자의 1시간 로컬 실행 리허설을 검수에 포함합니다.
