## 체험 시나리오 (타이핑 없이 클릭만)

1. 상단 **역할 전환**을 비회원→일반회원→한의사로 바꿔 보세요 — 같은 커뮤니티 목록이 [메타만 → 임상 숨김 → 전문]으로 실제로 바뀝니다.
2. `강의 → 견비통 침구 치료 실전` — 재생을 누르면 회원번호 워터마크가 떠다니고, 「이 링크가 유출되면?」에서 유튜브 연동의 한계를 확인한 뒤 회원 수 슬라이더로 대안 비용을 비교하세요.
3. `가입 신청 → 증빙 제출 → 샘플 서류로 체험` — 주민번호를 가리기 전에는 제출 버튼이 잠겨 있습니다.
4. 역할을 **관리자**로 바꾸고 `관리자 콘솔 → 승인 큐` — 강민재를 승인하고, 임초원(판독 불가)을 반려 코드로 반려해 보세요.
5. `게시판 관리` — 임상 증례의 「일반회원」 칸을 클릭하면 의료법 고위험 경고가 점등됩니다. 「게시판 생성」을 누르면 사용자 화면 탭에 즉시 나타납니다.
6. `열람 로그` — 무결성 검증 → 변조 시뮬레이션 → 재검증으로 위·변조 검출을 확인하세요.

역할 딥링크: `?as=doctor` `?as=admin` 등.

## ⚠️ 착수 전 확인 (요약 — 상세는 분석/기획_설계.md)

1. **영상 호스팅** — 유튜브 한정공개로는 워터마크·유출 통제가 성립하지 않음 (약관·기능 충돌)
2. **일반회원의 정의** — 비의료인 포함 여부가 의료법 §56 리스크를 결정
3. **증빙 서류** — 면허증 사본 수취 시 주민번호 마스킹이 전제 (개인정보보호법 §24-2)
4. 소셜 로그인 검수 리드타임(카카오 비즈앱·네이버 약 1주)을 일정 초반에 배치
5. Supabase 채택 시 RLS 정책 전수 작성·검증이 프로젝트의 본체
