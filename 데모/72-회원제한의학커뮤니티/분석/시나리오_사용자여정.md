# BONCHO 본초 — 시나리오 · 사용자 여정

## 1. 등장인물

| # | 인물 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| A | **강민재** — 승인 대기 신규 가입자 (개원 한의사) | 빨리 승인받고 안을 보고 싶다 | "며칠 걸리나" 안내가 없으면 이탈. 면허증 사본이 어디에 어떻게 저장되는지 |
| B | **김서연** — 한의사회원 (임상 12년, 강의도 함) | 동료끼리만 보는 임상·처방 논의, 강의 수익 | 자기 글·강의가 커뮤니티 밖으로 새는 것 (캡처 → 단톡방 → 의료법 문제로 자기가 걸림) |
| C | **박지호** — 일반회원 (한의대 본과 3년) | 국시 강의, 선배들의 진로 조언 | 어디까지 볼 수 있는지 몰라 매번 "권한 없음"만 만나는 것 |
| D | **정수민** — 방금 신청한 승인 대기자 | 지금 뭐라도 보고 싶다 | 빈 화면. 신청이 접수는 됐는지 |
| E | **이운영** — 관리자 (2~3명 중 1인, 비개발자, 본업 있음) | 승인·신고를 몰아서 빨리 처리 | 판단 기준 없이 개인 판단으로 승인하는 것. 실수로 비한의사를 들이는 것 |
| F | **운영사 대표** | 회원 증가, 콘텐츠가 쌓이는 것 | 유출 사고 1건 = 신뢰 붕괴. 개인정보·의료법 리스크 |
| G | 외부인 (비회원·유출 링크 수신자) | — | 서비스가 통제해야 할 대상 |

**역할 겸임 (공고가 놓친 지점)**
- C→B 승격: 한의대생이 국시 합격 후 한의사가 된다 — 등급 승격 절차 필요 (데모: 관리자 권한 변경 + 재확인 주기)
- B↔강사: 강의를 올리는 사람도 한의사회원 — 강사의 수강 통계 열람 범위는 미팅 확정 항목
- E↔B: 관리자가 한의사회원을 겸하면 자기 글 신고를 자기가 처리하는 이해충돌 → **데모: 본인 게시물 처리 차단 가드 구현** (admin/reports)

## 2. 전체 타임라인 (발견 → 사후)

| 단계 | 상황 | 쓰는 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 발견 | 동료 추천으로 유입. 로그인 전 | index — 티저(잠긴 게시판 카드 + 게시글 수·조회수 메타) | 보여줄 게 없어 가입 동기가 안 생김. 승인제 사이트 최대 난점 |
| 가입 | 카카오/네이버 3초 가입 → 유형 선택 | join 1~2단계 | 소셜 프로필만 있고 신원 없는 계정이 쌓임 |
| 증빙 | 면허증 업로드 — 주민번호를 브라우저에서 가림 | join 3단계 (마스킹 에디터) | 주민번호 원본이 서버에 쌓임 = 과태료 3천만원 리스크 |
| 대기 | "언제 되나" | join 4단계 · mypage (타임라인·평균 9.4시간) | 로그인해도 빈 화면 → 절반이 이탈 |
| 승인/반려 | 관리자 심사 | admin/members (승인 큐) | 반려 사유가 없으면 문의가 관리자 개인 연락처로 옴 |
| 활동 | 게시판·강의·갤러리 | community/post/write/lectures/lecture/gallery | 권한 처리(숨김 vs 메타만 vs 전문)가 안 정해져 있으면 매번 오류처럼 느껴짐 |
| 위반·신고 | 개인정보 노출 글 발견 | post 신고 모달 → admin/reports | 신고가 이메일로 오면 §44-2 공시·통지 의무가 누락됨 |
| 제재 | 임시조치 → 이의 → 확정 | admin/reports (D-30 링) | 30일 관리가 없으면 무기한 차단 → 분쟁 |
| 유출 사고 | 강의 캡처가 단톡방에 돈다 | admin/logs (역추적·이상 패턴) | 로그가 기록만 되고 역추적 화면이 없으면 사고 시 아무것도 못 함 |
| 갱신 | 면허신고 주기 도래(3년) | admin/members 재확인 · mypage 상태 카드 | 효력정지 한의사가 전용 게시판에 남음 |
| 탈퇴 | 회원 탈퇴 | (미팅 확정) | 접속기록 법정 보관과 삭제 요구 충돌 → 약관 명시 필요 |

## 4. 기능별 존재 이유 전수

| 기능 | 존재 이유 (어느 인물의 어느 순간) |
|---|---|
| 역할 전환 바 | 발주자가 "권한별로 정말 다르게 보이는가"를 타이핑 없이 검증하는 창구 |
| 신뢰 카운터(로그인) | A가 가입을 결심하는 순간 — 업계 표준 문법(메디스트림·모어덴 실측) |
| 마스킹 업로더 | A의 증빙 제출 순간 = F의 과태료 리스크가 생기는 순간 |
| 승인 큐 SLA 타이머 | E가 "오늘 몇 건 밀렸나"를 한눈에 |
| 반려 사유 코드 | E의 판단 기준 통일 + A에게 재신청 경로 안내 |
| 제목 서버 마스킹 티저 | G에게 내용은 0, "안이 활발하다"는 증거만 (모어덴 실측 문법) |
| 임상 게시판 목록 숨김 | B의 글이 C·G에게 닿는 순간 의료광고가 되는 것을 구조로 차단 |
| 의료법 작성 가드 | B가 무심코 병원명·후기를 쓰는 순간 — 차단이 아니라 선택지 제시 |
| 60초 서명 URL | B가 받은 링크를 G가 재사용하는 것을 만료로 차단 |
| 이동 워터마크 | 캡처 유출 시 화면의 회원번호로 역추적 |
| 유출 시뮬레이터 | 발주자가 "유튜브+워터마크" 요구의 충돌을 눈으로 확인하는 장치 |
| 30일 링 게이지 | E가 임시조치 만료를 놓치지 않게 (§44-2) |
| 해시 체인 로그 | 분쟁 시 "기록이 조작되지 않았다"는 증명 |
| 게시판 CMS | F가 7번째 게시판을 개발자 없이 만드는 순간 |
| 면허 재확인 컬럼 | 3년 뒤 효력정지 회원이 전용 게시판에 남는 사고 예방 |

## 5. 비는 구멍 — 미팅 확인 필요 (13)

1. 승인 기준·제출 서류 종류 (면허증? 면허자격증명서? — 마스킹 전제)
2. **"일반회원"의 정체** (한의대생? 환자? 업계 종사자?) — 의료법 분기점
3. 반려 후 재신청 횟수·대기기간, 소셜 계정 재사용
4. 게시판 6종 확정 목록과 권한 매트릭스 (데모 매트릭스를 초안으로)
5. 열람 로그(IP) 수집 고지 — 처리방침·동의서 문안
6. 워터마크 대상(영상만? 첨부도?)과 방식 — **영상 호스팅 확정이 선행**
7. 탈퇴 회원 게시물(삭제 vs 익명화) + 접속기록 법정 보관 충돌 약관
8. 신고 처리 SLA·판단 주체·이의신청 창구
9. 첨부 정책 (용량·확장자·HWP 악성코드 검사)
10. 관리자 2~3명 권한 분리 (개인정보 열람·마스킹 해제 권한, 행위 로그 열람자)
11. 한의대생 → 한의사 승격 절차 / 면허 3년 재확인 운영 방식
12. 유료화 로드맵 (강의 결제·PG — 이번 범위인가 2차인가, DB는 지금 열어둠)
13. 알림 채널 (이메일 vs 카카오 알림톡 — 알림톡은 템플릿 심사 리드타임)
