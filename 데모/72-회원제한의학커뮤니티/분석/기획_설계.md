## 1. 니즈 분석

### 1-1. 명시된 니즈
- 3단계 권한(일반회원/한의사회원/관리자) + 권한별 콘텐츠·메뉴 접근제어
- 게시판 약 6종(작성·수정·삭제·댓글·첨부 PDF/HWP/XLSX/이미지·조회수·북마크·신고·블라인드)
- 유튜브 연동 강의 게시판 + 열람 이력 기록, 이미지 갤러리
- 관리자 백오피스(2~3명): 승인/반려·권한·게시물·신고·공지 CMS·열람 로그
- 콘텐츠 열람 추적(회원/일시/콘텐츠/IP) + 회원번호 워터마크(협의) + 개인정보 마스킹
- Supabase 우선 검토(필수 아님) · RLS 기반 접근제어 고려

## 2. 웹 리서치 — 치명적 발견 10건 (근거 URL 전수)

우선순위: 그대로 만들면 작동하지 않음 > 법 위반 소지 > 운영 중 반드시 터짐.

### ① 한의사 면허 진위를 실시간 확인할 수단이 없다 [작동하지 않음]
- 복지부 면허조회는 주민번호+간편인증 **본인 조회 전용**. 기관조회는 기관 인증서+본인 동의 전제.
  업계 표준(메디게이트)도 서류 제출 → 관리자 수동 승인이다.
- 근거: https://dataapi.co.kr/upload/dLab/20230817-170157-67440.html · https://lic.mohw.go.kr/instt/instt_useguid_guid.do?MENU_ID=O-01-01 · https://www.medigate.net/help/customer/mem_cert.jsp
- **→ 구현**: admin/members 승인 큐 — 사람이 판단할 부분만 남기고 형식·체크섬/중복 대조/성명 대조를 자동화. "자동 검증 불가" 배너에 대안을 명시.

### ② 면허증 사본 수집 = 주민등록번호 수집 — 과태료 3천만원 [법 위반 소지]
- 면허증에는 주민번호가 인쇄돼 있고, 법령 근거 없는 주민번호 처리는 금지(개인정보보호법 §24-2).
- 근거: https://casenote.kr/법령/개인정보_보호법/제24조의2 · https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=1257&ccfNo=2&cciNo=3&cnpClsNo=2
- **→ 구현**: join 3단계 — **브라우저 내 마스킹 에디터**(canvas). 주민번호를 가리기 전에는 제출 버튼이 실제로 잠기고, 마스킹본만 전송. 관리자 화면에 "원본 미보관 · D+90 파기" 표기.

### ③ 「유튜브 연동」과 「회원번호 워터마크」는 동시에 성립하지 않는다 [작동하지 않음 · 미팅 1순위]
- 한정공개 영상은 링크를 가진 누구나 시청·재공유 가능. 임베드 플레이어 변형은 약관 금지 →
  워터마크는 페이지 오버레이가 한계이고 유출된 원본 URL에는 무력.
- 근거: https://support.google.com/youtube/answer/157177 · https://www.youtube.com/static?template=terms · https://swarmify.com/blog/youtube-unlisted-vs-private/
- **→ 구현**: lecture — ⓐ 4초마다 위치가 바뀌는 회원번호 워터마크 ⓑ 「이 링크가 유출되면?」 2창 비교 시뮬레이터 ⓒ 3방식(유튜브/상용 호스팅/자체 HLS+서명 URL) **월 비용 실계산 비교**(회원 수·시청시간 슬라이더 연동, 규모별 권장안 자동 전환).

### ④ Supabase RLS 미설정 = anon 키만으로 전체 노출 [운영 중 터짐]
- CVE-2025-48757: 170개 프로젝트·303개 엔드포인트가 anon 키로 읽힘. Storage 서명 URL은 발급 시점에만 정책 검사.
- 근거: https://vibeappscanner.com/supabase-security · https://deepstrike.io/blog/hacking-thousands-of-misconfigured-supabase-instances-at-scale · https://supabase.com/docs/guides/storage/security/access-control
- **→ 구현**: 전 페이지 역할 전환 바(권한 시뮬레이터) + admin/boards **RLS 정책 매트릭스**(누락 칸 클릭 → anon 조회로 새는 데이터 재현 + 정책 SQL) + 첨부 60초 만료 서명 URL.

### ⑤ 신고·블라인드 = 정보통신망법 §44-2 절차 전체 [법 위반 소지]
- 임시조치 30일 이내 · 게시판 공시 · 양측 통지 · 약관 명시 — 4가지 의무의 묶음.
- 근거: https://casenote.kr/법령/정보통신망_이용촉진_및_정보보호_등에_관한_법률/제44조의2 · https://www.lawtimes.co.kr/news/166260
- **→ 구현**: admin/reports 상태 머신(접수→검토→임시조치→이의→확정) + D-일수 링 게이지 + 사용자 화면 공시 블록 + 관리자 본인 글 처리 차단(이해충돌 가드).

### ⑥ 열람 로그는 법정 의무 — 보관 1년·위변조 방지·IP는 개인정보 [법 위반 소지]
- 개인정보의 안전성 확보조치 기준 §8. 탈퇴 회원도 접속기록은 보관기간 내 삭제 불가(약관 명시 필요).
- 근거: https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준 · https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=1257&ccfNo=3&cciNo=2&cnpClsNo=1
- **→ 구현**: admin/logs — 보관 정책 카드(D-일수) · **해시 체인 + 무결성 검증**(변조 시뮬레이션 포함) · 이상 패턴 탐지(다중 IP·대량 순회) · IP 뒷자리 마스킹 · 수집 고지 표기.

### ⑦ "일반회원"의 정의가 의료법 §56 리스크를 결정한다 [법 위반 소지]
- 비의료인이 열람 가능한 공간의 임상·치료 게시물은 의료광고로 해석될 수 있음. 규모 10만 DAU부터 사전심의 대상.
- 근거: https://ad.akom.org/ad/tmpl/sub_main.php?main_cd=7&sub_cd1=12&sub_cd2=13 · https://www.mohw.go.kr/board.es?mid=a10503010100&bid=0027&act=view&list_no=371102
- **→ 구현**: 일반회원 = 한의대생으로 정의, 임상·처방·경영 게시판은 **목록부터 숨김**. admin/boards 공개범위 매트릭스 — 임상 게시판을 일반에 열면 **고위험 경고가 실시간 점등**. write 에디터에 위험 표현 실시간 가드. 대시보드에 사전심의 트리거 게이지.

### ⑧ 소셜 로그인 검수가 60일의 숨은 크리티컬 패스 [운영 중 터짐]
- 카카오 비즈앱 전환(사업자 필요)·네이버 검수 약 1주. 승인제 사이트는 심사자가 내부를 못 봐 반려되기 쉽다.
- 근거: https://kakaobusiness.gitbook.io/main/undefined/untitled · https://help.campaignus.me/ko/articles/네이버-아이디로-로그인-심사-거절-유형-및-대응-방법-60da8c1d
- **→ 구현**: 소셜 → 자격 신청 → 승인 대기 3화면(검수 스크린샷 그대로 사용 가능) + 일정표에 검수 선착수 배치.

### ⑨ 면허는 3년마다 갱신된다 — 1회 승인으로 끝나지 않는다 [운영 중 터짐]
- 한의사 면허신고 3년 주기, 미신고 시 효력 정지.
- 근거: https://www.akom.org/Home/AkomArticleNews/1151150?NewsType=1
- **→ 구현**: 회원 표에 `면허 재확인 예정일`(승인일+3년 자동 계산) + **강등 시뮬레이션**(누르면 실제로 임상 게시판 접근이 사라짐) + 마이페이지 면허 확인 상태 카드.

### ⑩ 게시판을 6개 하드코딩하면 7번째에 개발자를 부른다 [운영 중 터짐]
- 공고 문구가 "약 6종" = 미확정. 업계 동일 서비스(메디스트림)는 게시판·강의·구인을 등급별 데이터로 운영.
- **→ 구현**: admin/boards 게시판 CMS — 「게시판 만들기」가 실동작(생성 즉시 사용자 GNB·매트릭스 합류). 공지 CMS 작성분도 사용자 화면에 즉시 반영.
