# WRAPLY 랩리 — 시나리오·사용자 여정

> 기능 목록을 시간순 사용 흐름으로 재구성. “이 기능이 없으면 무슨 일이 벌어지는가”를 중심으로.

---

## 1. 등장인물

| 인물 | 누구 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **의뢰자(서비스 운영자)** | 이미 모바일웹을 운영 중 | 앱으로 접근성↑ · 푸시로 재방문↑ · 빠르고 싸게 | 반려되면 어쩌지 / 유지보수가 두 배 되면 어쩌지 / 푸시가 진짜 올까 |
| **최종 사용자** | 앱을 설치한 고객 | 앱이 웹처럼 매끄럽게 · 로그인 유지 · 알림 받기 | 첨부가 안 됨 / 다시 켜면 로그아웃 / 뒤로가기 먹통 |
| **개발자(지원자=나)** | 하이브리드앱 제작 | 반려 없이 게시 · 푸시 실발송 · 깔끔한 인수 | 기존 서버/웹 구조 모름 → 미팅으로 확인 필요 |

> 한 사람이 두 역할: 의뢰자는 **운영자이자 서버(PHP) 소유자**. 그래서 “PHP 수정”이 실제로 얼마나 되는지는 기존 코드에 달려 있다 → 착수 전 확인 필수.

## 2. 시간순 여정 (제작 → 심사 → 운영)

| 단계 | 상황 | 쓰는 화면/기능 | 없으면 벌어지는 일 |
|---|---|---|---|
| 발견 | 웹은 있는데 앱이 없다 | WebView 셸 | 앱 스토어 노출·푸시 채널을 통째로 잃음 |
| 감쌈 | 웹을 앱 안에 로드 | JS·DOM스토리지 설정 | 웹이 흰 화면·기능 먹통 |
| 첫 벽 | 파일 첨부가 안 됨 | onShowFileChooser·다운로드 | 게시글 첨부·증빙 업로드 불가 → 핵심 플로우 붕괴 |
| 둘째 벽 | 다시 켜면 로그아웃 | CookieManager.flush() | 매번 재로그인 → 이탈 |
| 셋째 벽 | 뒤로가기가 앱을 꺼버림 | canGoBack/goBack + 더블탭 종료 | 사용자가 실수로 앱 종료 |
| 넷째 벽 | 오프라인에 흰 화면 | 오류/로딩 오버레이 | “앱이 고장났다”는 인상 |
| 재참여 | 푸시로 다시 부름 | FCM 토큰·표시·**딥링크** | 재방문 유도 수단 없음(웹의 한계) |
| 발송 | 서버에서 푸시 쏨 | PHP → HTTP v1(서비스 계정) | Legacy면 **발송 자체가 안 됨** |
| 심사 | Play에 올림 | 서명·타깃API36·DataSafety·개인정보처리방침 | **반려**로 게시 지연·무산 |
| 운영 | 웹을 고치면 | 하나의 코드베이스 | 앱을 매번 다시 빌드/심사(고도화 부담) |

## 3. 역할별 시야 차이

| 데이터/동작 | 사용자 시야 | 운영자 시야 | 개발자 시야 |
|---|---|---|---|
| 푸시 | “알림이 왔다/안 왔다” | “재방문이 올랐나” | 토큰 등록·권한·채널·딥링크·반송 토큰 정리 |
| 로그인 | “유지된다/풀렸다” | “이탈률” | flush·세션/영속 쿠키·서버 만료 |
| 심사 | (모름) | “왜 반려됐지” | 최소기능·등록정보·데이터안전·타깃API |

## 4. 기능별 존재 이유 (전수 매핑)

- **WebView 설정** — 웹을 ‘정상 웹’으로 돌리는 최소 조건. 없으면 전부 무너짐
- **파일 처리** — 웹 input[file]을 앱이 가로채야 열림. 업로드/카메라/다운로드 각각 별도 처리
- **로그인 유지** — flush로 쿠키 영속. 서버 세션 정책과 맞물림
- **뒤로가기/오류/로딩** — “앱다움”. 최소기능 심사의 근거
- **FCM(딥링크 포함)** — 재참여 목표의 실효 조건
- **HTTP v1 전환** — legacy 종료로 인한 필수. 서버 재작성
- **서명/배포/등록정보** — 게시의 관문. 기능이 있어도 여기서 막힘

## 5. 비는 구멍 (미팅에서 반드시 확인)

1. **기존 PHP 발송 코드가 legacy(서버키)인가 v1인가?** → 공수(3.5일)의 전제. legacy면 이미 발송 중단 상태일 수 있음
2. **모바일웹의 로그인/세션 방식**(세션 쿠키? 토큰?) → 로그인 유지 구현 방식이 갈림
3. **파일 첨부의 실제 형태**(단일/다중/카메라 필요?) → onShowFileChooser 분기 범위
4. **개인정보처리방침 문서 유무 / 수집 항목** → Data Safety 선언과 일치해야 반려 안 됨
5. **iOS도 필요한가?**(공고는 Android만) → 고도화 범위에 영향
6. **Play 개발자 계정 보유 여부**($25 1회, 의뢰자 명의)
7. **웹 도메인/서버 접근 권한**(PHP 수정·테스트용)
