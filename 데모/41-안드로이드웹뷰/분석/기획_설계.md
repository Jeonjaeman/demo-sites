# WRAPLY 랩리 — 기획·설계

> 안드로이드 하이브리드(WebView) 앱 제작 및 Google Play 배포 (위시켓 공고)
> 제안용 데모 · 모든 수치·데이터는 시연용 가상값

---

## 1. 한 줄 정의

이미 운영 중인 **모바일웹을 다시 개발하지 않고** Android 하이브리드(WebView)로 감싸
**Google Play에 ‘심사 통과하는’ 앱**으로 배포하고, 웹으로는 어려운 **FCM 푸시**로 재방문을 만든다.

---

## 2. 명시된 니즈 vs 숨은 니즈

| 구분 | 내용 |
|---|---|
| **명시된 니즈** | WebView 앱(API 36) · 파일 업로드/다운로드 · 로그인 유지 · 뒤로가기 · 네트워크 오류 안내 · 런타임 권한(Android 13+ 알림) · 신규 Firebase + FCM 연동 · 기존 PHP를 HTTP v1로 수정 · 서명·Play 등록 |
| **숨은 니즈 ①** | “그냥 웹뷰”가 아니라 **반려되지 않는 앱**. 의뢰자가 네이티브 동작을 나열한 건, 무의식적으로 Play 최소기능 정책을 피하려는 요구 — 이걸 명시적으로 증명해야 한다 |
| **숨은 니즈 ②** | “기존 PHP 소스 수정”은 **가벼운 수정으로 인식**돼 있지만, 기존이 Legacy면 인증 체계 전면 교체 + 이미 발송 중단 상태일 수 있다 |
| **숨은 니즈 ③** | 재방문·재참여가 목표 → 푸시는 **딥링크(알림 탭 → 해당 화면)** 까지 돼야 실효. 단순 알림 표시로는 목표 미달 |
| **숨은 니즈 ④** | 고도화 프로젝트 예정(공고 명시) → **1차는 얇은 셸로 빠르게, 코드베이스 하나로 유지보수 부담 최소화** 하는 구조가 이후 확장에 유리 |

## 3. 요구사항 커버리지

| 공고 요구 | 데모 반영(동작하는 기능) |
|---|---|
| WebView 셸(JS·DOM스토리지·오류/로딩) | 폰 프레임의 WebView 화면 + 오프라인/로딩 오버레이 |
| 파일 업로드/다운로드 | 📎 파일 첨부 시트(카메라/갤러리 분기) + 다운로드 토스트 |
| 로그인 유지 | 로그인 유지 ON/OFF + 앱 재시작 → flush 유무에 따라 유지/로그아웃 재현 |
| 뒤로가기 | ◀ 뒤로가기(스택 pop) + 루트에서 더블탭 종료 |
| 런타임 권한(알림) | 리스크·심사 진단에 POST_NOTIFICATIONS 반영 |
| FCM 연동(토큰·표시·딥링크) | 🔔 푸시 발송 → 배너 → 탭 시 딥링크 화면 이동 |
| 기존 PHP → HTTP v1 | FCM 전환 진단(legacy 종료 판정 + v1 코드/절차 + 발송 시뮬) |
| 서명·Play 배포 | Play 심사 진단(가중 점수 + 필수 항목) |

## 4. 웹 리서치 — 치명적 발견 (근거 URL)

| 우선순위 | 발견 | 근거 |
|---|---|---|
| **그대로 만들면 반려** | Play 정책 **4.3 최소 기능** 강화 — 웹만 감싼 앱은 반려·삭제. 네이티브 가치(푸시·파일·오프라인·내비)가 있어야 통과 | [Play Developer Policy](https://play.google/developer-content-policy/) · [WebView 승인 가이드](https://code2native.com/blog/webview-app-google-play-approval-2026) |
| **작동 불가** | **FCM Legacy HTTP API 셧다운(2024.7.22)** — 서버키 인증 폐기, 서비스 계정으로 대체. 기존 코드가 legacy면 지금 발송 중단 | [Firebase 마이그레이션](https://firebase.google.com/docs/cloud-messaging/migrate-v1) |
| **운영 중 터짐** | **Android 13+ POST_NOTIFICATIONS** 런타임 미요청 시 푸시 미표시, 권한 승인 전 알림 유실 | [Android 알림 권한](https://developer.android.com/develop/ui/compose/notifications/notification-permission) · [FCM Android](https://firebase.google.com/docs/cloud-messaging/android/get-started) |
| **자주 깨짐** | WebView 파일 업로드는 **onShowFileChooser** 구현 필요, 카메라는 **FileProvider**, 다운로드는 **DownloadManager + scoped storage** | [WebView 파일 핸들러](https://github.com/mgks/android-webview-file-handler) |
| **자주 깨짐** | 로그인 유지 — **CookieManager.flush()** 미적용 시 종료 시 메모리 쿠키 유실, 세션 쿠키는 종료 즉시 폐기 | [영속 쿠키 가이드](https://www.javathinking.com/blog/how-to-save-a-cookie-in-an-android-webview-forever/) |
| **등록 차단** | **Data Safety 폼 + 개인정보처리방침 URL** 필수(FCM 토큰=식별자 수집). 2026.8.31부터 신규 앱 **타깃 API 36** | [타깃 API 요건](https://support.google.com/googleplay/android-developer/answer/11926878) |

> 우선순위: `그대로 만들면 반려` > `작동 불가` > `운영 중 터짐` > `있으면 좋음`

## 7. 제안 스택 · 일정

- **앱**: Android(Kotlin) · WebView · WebChromeClient(onShowFileChooser) · DownloadManager · CookieManager
- **푸시**: Firebase FCM · HTTP v1 API · 서비스 계정(OAuth2)
- **서버**: 기존 PHP 발송부 → HTTP v1 재작성(토큰 캐시·NotRegistered 정리)
- **배포**: 키스토어 서명 · AAB · Play Console · Data Safety · 개인정보처리방침
- **일정**: 총 **22일**(견적 표 참조). 계약 직후 착수, 온라인 미팅으로 기존 웹/서버 구조 확인 선행
