[1] 핵심 지적 3가지

지적 1 · "그냥 웹뷰"는 Google Play에서 반려됩니다
    Play 정책 4.3(최소 기능)이 강화돼, 웹을 상자에 담기만 한 앱은 반려·삭제됩니다.
    다행히 공고에 적어주신 푸시·파일·뒤로가기·오류화면이 바로 통과의 근거입니다.
    → 데모의 [Play 심사 진단]에서 항목을 켜고 끄면 통과 가능성이 실제로 계산되고,
      필수 항목(개인정보처리방침·Data Safety·타깃API36)이 비면 즉시 반려 위험으로 바뀝니다.

지적 2 · "기존 PHP 수정"이 사실은 인증 체계 전면 교체일 수 있습니다
    FCM Legacy(서버키) 방식은 2024년 7월 22일 셧다운됐습니다. 기존 발송 코드가
    legacy면 지금 이미 푸시가 나가지 않고 있고, 단순 수정이 아니라 서비스 계정(OAuth2)
    기반 HTTP v1 재구축이 필요합니다.
    → 데모의 [FCM 전환]에서 legacy 종료 판정과 v1 코드·전환 절차를 보여 드립니다.
      착수 전에 "기존 코드가 어느 방식인지"만 확인하면 공수가 확정됩니다.

지적 3 · Android 13+ 알림 권한과 로그인 유지, 조용히 실패하는 지점입니다
    타깃 API 36에서는 알림 권한(POST_NOTIFICATIONS)을 직접 요청해야 하고, 승인 전
    도착한 알림은 유실됩니다. 로그인 유지도 CookieManager.flush()를 빼면 앱을 다시
    켤 때 로그아웃됩니다. 둘 다 "사용자는 안 된다고만 느끼는" 버그입니다.
    → 데모 폰에서 [로그인 유지 OFF + 앱 재시작]으로 로그아웃 버그를 그대로 재현했습니다.

그 외 - 파일 첨부(onShowFileChooser)·카메라(FileProvider)·다운로드(DownloadManager,
    scoped storage), Data Safety 폼·개인정보처리방침 URL(FCM 토큰=식별자 수집), 타깃
    API 36까지 등록 요건을 데모 [리스크 검토] 6건에 근거 링크와 함께 정리했습니다.

[3] 강점

- 하이브리드앱의 실패 지점(반려·푸시 종료·권한·세션)을 먼저 짚고 설계합니다.
- 수정 요청은 화면 단위로 당일 반영합니다. 재작업이 빠릅니다.
- 인수 후를 생각합니다 - 빌드·배포·푸시 발송 운영 매뉴얼을 함께 드리고,
  코드베이스는 하나로 유지해(웹 수정 시 앱도 반영) 고도화 때 부담이 적습니다.
- 웹디자이너 출신 - 앱은 사용자가 "웹처럼 매끄럽다"고 느껴야 이탈이 없습니다.
  오류·로딩·시트·전환 화면까지 앱답게 마감합니다.
