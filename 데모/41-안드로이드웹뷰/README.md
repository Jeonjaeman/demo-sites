# WRAPLY 랩리 — 모바일웹 → Google Play 하이브리드(WebView) 앱 (제안용 데모)

이미 운영 중인 모바일웹을 **심사 통과하는** Android 하이브리드 앱으로 감싸고,
**FCM HTTP v1 푸시**로 재방문을 만드는 과정을, 코드가 아니라 **동작하는 화면**으로 증명하는 제안 데모.

공개 URL(별칭): `https://jeonjaeman.github.io/demo-sites/wraply/`

---

## 화면

| 영역 | 무엇을 보여주나 |
|---|---|
| 히어로 + **인터랙티브 폰** | WebView 셸 시뮬 — 실제로 눌리는 앱 동작 |
| ② 풀블리드 statement | “웹을 감싸는 건 쉽다 / 심사를 통과하는 앱은 다르다” |
| ① 마우스 반응 카드 | SHELL · PUSH · FILE·SESSION · DEPLOY 4기둥 |
| **Play 심사 진단** | 항목 토글 → 통과 가능성 가중 계산 + 필수 누락 반려 판정 |
| **FCM 전환 진단** | Legacy 종료 판정 / v1 코드·절차 / 폰으로 발송 시뮬 |
| **리스크 검토** | 6건(발견 → 대응 → 근거 링크) |
| 견적 | 공수표(22일 · 220만원) + 산출물 |

## 체험 시나리오 (폰에서 직접)

1. **로그인 유지 OFF** → **앱 재시작** : 재실행 시 로그아웃되는 흔한 버그 재현. ON이면 유지.
2. **📎 파일 첨부** : 카메라/갤러리 분기 시트(onShowFileChooser 시뮬).
3. **🔔 푸시 발송** → 상단 배너 → **탭하면 주문 화면으로 딥링크**.
4. **📴 오프라인** : 흰 화면 대신 오류 화면 → 다시 시도 시 로딩.
5. **◀ 뒤로가기** : 웹 이전 화면 이동, 루트에서 더블탭 종료.
6. **Play 심사 진단**에서 필수 항목(개인정보처리방침·Data Safety·타깃API36·푸시)을 끄면 즉시 **반려 위험**으로 바뀜.

## ⚠️ 착수 전 확인 (미팅)

- 기존 PHP 발송 코드가 **Legacy(서버키)인지** — 맞으면 인증 체계 전면 교체(이미 발송 중단일 수 있음)
- 모바일웹 **로그인/세션 방식**, **파일 첨부 형태**(단일/다중/카메라)
- **개인정보처리방침 문서·수집 항목**(Data Safety와 일치 필요)
- **Play 개발자 계정**($25, 의뢰자 명의), 웹/서버 접근 권한, iOS 필요 여부(고도화)

## 디자인 실측

- 도메인: **Median.co**(웹→앱 · 다크 #0c0c0c · DM Sans · 히어로 96px/−0.07em · IA: App Store Approval·One Codebase·Secure·Push), **Firebase**(HTTP v1 절차)
- 디자인: **Linear.app**(#08090a · Inter 510 · h1 64px/−0.022em · pill 버튼), **Vercel.com**(Geist · 64px/−0.06em · radius 4px)
- 시스템: 근-흑 배경 + 단일 그린 액센트(안드로이드 연상·로고색 미사용) + 시안(푸시) + 모노 수치

## 기술 구성

- 정적 HTML/CSS/JS (빌드 없음) · Pretendard · 외부 라이브러리 미사용
- 리빌·패럴랙스·틸트·카운트업·마스크 텍스트는 `transform` 기반, `prefers-reduced-motion` 존중
- 100vw 풀블리드: `width:100vw; margin-left:calc(50% - 50vw)` + `overflow-x:clip`

## 검증 결과

- 콘솔 에러 0 · 데스크톱/모바일(375) 가로 오버플로 0 · 이미지 5장 로드
- 심사 진단 가중 계산 14%↔100%·필수 누락 반려 로직 동작
- 폰: flush OFF 재시작→로그아웃 재현 · 푸시→딥링크 · 파일 시트 · 오프라인 · 뒤로가기 모두 동작
- FCM 세그먼트/발송 시뮬 · 리스크 6건 렌더
