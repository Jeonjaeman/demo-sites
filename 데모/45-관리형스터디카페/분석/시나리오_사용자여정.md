# MOLIP — 시나리오·사용자 여정

---

## 1. 등장인물

| 인물 | 누구 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **학생** | 스터디카페 이용 | 내 자리·집중 환경 | 관리가 잔소리로 느껴짐 |
| **학부모** | 결제·보호자 | 아이가 잘 공부하는지 | 돈만 내고 방치되는 것 · 내 아이 정보 안전 |
| **사장/실장** | 운영 | 신청 접수·출석 관리·리포트가 자동으로 | 도구 여러 개 관리·월 구독료·연결 끊김 |
| **개발자(지원자)** | 구축 | 안정적·저비용·인계 쉬움 | 노코드 스택의 유지 부담 |

> 사장은 **운영자이자 미성년 개인정보 처리자이자 마케터**. 홈페이지 문구·데이터·발송이
> 모두 사장의 책임으로 걸립니다.

---

## 2. 시간순 여정

| 단계 | 상황 | 표면·화면 | 없으면 벌어지는 일 |
|---|---|---|---|
| 발견 | 브랜드 검색·유입 | 공개 홈(브랜드) | 무엇이 다른지 안 보이면 이탈 |
| 신청 | 가입 신청서 작성 | 가입 폼 | 미성년 정보 동의 없이 받으면 위법 |
| 적재 | 접수 데이터 저장 | → 자체 DB + 구글시트 백업 | 도구 연결 끊기면 유실 |
| 관리 | 실장이 출석 체크 | 관리자 출석 슬롯 | 엑셀 수기 → 집계 불일치 |
| 리포트 | 학부모에게 발송 | 관리자 리포트 | SPF/DKIM 없으면 스팸행 |
| 수정 | 요금·공지 변경 | 관리자 편집기 | 매번 개발자 요청 |
| 비용 | 매달 정산 | (설계) 통합 | 도구별 구독료 누적 |

---

## 3. 표면별 시야 차이

| | 공개 홈(브랜드) | 통합 관리자(대시보드) |
|---|---|---|
| 성격 | 소개·전환 | 운영·입력·조회 |
| UI | 히어로·이미지 단락·요금·폼 | KPI·표·출석 슬롯·리포트·편집기 |
| 이용자 | 학생·학부모 | 사장·실장 |

→ 같은 프로젝트라도 **표면에 맞게 다른 UI**로 설계(하이브리드).

---

## 4. 기능별 존재 이유

- **가입 폼(+구글시트 백업)** — 접수 자동화, 도구 없이도 백업
- **출석 슬롯** — 엑셀 수기를 대체, 누적 학습시간 자동 계산
- **리포트 자동 발송** — 학부모 신뢰(도달 보장이 핵심)
- **편집기** — 사장 자가 수정(요금·공지·이벤트)
- **통합 설계** — 월 구독료 0원·단일 장애점 제거

---

## 5. 비는 구멍 (미팅에서 확인 — 견적 확정 3문항)

1. 출석·학습 **기록 항목**(출석시간 / 과목·진도 / 자습시간 등)
2. 리포트 받을 **학부모 인원 규모**와 리포트에 넣을 내용
3. 사장님이 **직접 수정**할 콘텐츠 범위(요금·공지·이벤트·사진 등)
4. (추가) 미성년 개인정보 동의 문안 · 학원법 관점의 마케팅 문구 수위 · 이메일 발송 도메인/인증
