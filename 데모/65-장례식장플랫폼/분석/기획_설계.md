# 장례식장 예약·용품견적 플랫폼 — 기획 설계

> 위시켓 공고 「장례식장 예약 및 용품 견적 플랫폼 구축」 대응 제안용 데모.
> 예산 20,000,000원 · 75일 · 의뢰자 경남 창원 · 우선순위 **산출물 완성도 > 금액 > 일정**.
> 분석일 2026-08-15. 데이터는 전부 가상.

---

## 0. 한 줄 결론 — 이 데모가 증명하는 것

"예약·견적·부고장 화면을 예쁘게 만들 수 있다"가 아니라, **의뢰자가 아직 정하지 않은 두 갈래(사업모델·자금흐름)에서 잘못 정하면 서비스가 안 열리거나 법에 걸린다는 것을 미리 봤고, 그 분기를 화면으로 구현해 놓았다**를 증명한다.

핵심 통찰 두 가지:
1. **"전국 장례식장 실시간 빈소 현황"은 사업모델에 따라 성립 여부가 갈린다.** 독립 장례식장을 모으는 오픈 마켓플레이스라면 실시간 데이터 출처가 없어 **성립 불가**, 자사 브랜드 지점망(본부-지점)이라면 **성립 가능**. → 데모는 **본부-지점을 1순위 가정**으로 잡아 간판 기능이 실제로 돌게 한다.
2. **"예약금 또는 전액 선결제"는 잘못 확장하면 상조업(선불식 할부거래) 규제(자본금 15억·선수금 50% 예치)에 걸린다.** 단 "3일장 즉시결제=제공시기 확정형"으로 한정하면 비해당. → 데모에 **선불/즉시결제 판정기**를 내장해 이 경계를 화면으로 긋는다.

## 1. 사업모델 전제 — 본부-지점 1순위, 오픈마켓 확장 가능

공고 문구("전국의 장례식장", "입점사 관리", "파트너 계정 권한")는 **오픈 마켓플레이스**와 **본부-지점 체인** 양쪽으로 읽힌다. 다음 근거로 **본부-지점을 1순위 가정**으로 둔다.

- 초기 시장 검증을 **한 사업자가 단독 추진**(PM 1명, 아이디어 단계).
- 파트너/마스터 3단 권한이 본부-지점 구조에 더 자연스럽다.
- "**자사에서** 취급하는 용품·단가 설정"의 "자사"가 지점을 가리킨다.

| 축 | 오픈 마켓플레이스(독립 장례식장 입점) | **본부-지점(직영/가맹) — 1순위 가정** |
|---|---|---|
| 실시간 빈소 현황 | 데이터 출처 없음 → **치명적 결함** | 본부 중앙 DB가 전 지점 상태 소유 → **실시간 성립** |
| 사업 모델 | 경쟁 장례식장 aggregator(고이와 경쟁) | 자사 체인 D2C 예약·운영(경쟁상대는 지점 전화·오프라인 접수) |
| 권한 | 서로 불신하는 독립 셀러 | 본부(전 지점 통합) ↔ 지점장/직원(담당 지점만) |
| 용품 단가 | 입점사 각자 | **본부 표준가 + 지점 오버라이드(밴드·승인제)** |
| 법적 추가축 | — | 가맹이면 **가맹사업법**(직영이면 소멸) |
| 선불식 할부거래 | 리스크 有 | **리스크 확대**(본부 중앙수금 시 규모↑) |

**데이터 모델 권고**: `지점.유형 ∈ {직영, 가맹, 제휴입점}`을 두어, 본부-지점으로 구축하되 나중에 **독립 장례식장 제휴 입점(오픈마켓)으로 확장 가능**하게 설계한다. 어느 가정이 맞든 재작업을 최소화한다.

**착수 미팅 1순위 질문**: ① 본부-지점(직영/가맹) vs 오픈마켓 ② 지점이 직영인가 가맹인가(가맹이면 정보공개서·가맹금·가격강제 축 발생) ③ 선수금을 본부가 중앙 수금하는가(할부거래법 강도 결정) ④ 지점의 기존 현황판/POS 유무(연동 vs 대체).

## 2. 니즈 — 명시 vs 숨은

**명시된 니즈**: 실시간 빈소 현황 / 예약·PG결제 / 용품 견적산출기 / 모바일 부고장(카톡) / 파트너 오피스 / 마스터 백오피스 / 반응형 웹(Mobile First).

**숨은 니즈** (단서: "아이디어 단계", "초기 시장 검증", "PM 1명", "산출물 완성도 1순위", "창원 소재·오프라인 미팅 우대"):
- **되는지부터 보고 싶다** — 완성도 높은 데모로 투자·지점 설득용. 실데이터·실지점 없이 화면으로 컨셉 증명.
- **밀착 커뮤니케이션·빠른 수정 대응**을 중시(오프라인 미팅 우대).
- "산출물 완성도" 1순위 = 예쁜 껍데기가 아니라 **실제로 도는 것처럼 보이는** 데모.

## 3. 리서치 — 치명적 발견 (근거 URL 포함)

우선순위: `그대로 만들면 작동 안 함` > `법 위반 소지` > `운영 중 반드시 터짐` > `있으면 좋음`.

### 발견 ① [법 위반 소지·경계 방어 가능] 선불식 할부거래(상조업) 경계
- **근거**: 할부거래법 제2조 — 선불식 할부계약은 "대금을 2개월 이상·2회 이상 나눠 지급하고 재화·용역을 대금지급 후 받는" 계약이며, 그 대상이 **"장례·혼례 용역(제공시기가 확정된 경우는 제외)과 부수 재화"**. 등록 시 **자본금 15억 상시 유지 + 선수금 50% 예치**.
  - 할부거래법 제2조: https://casenote.kr/%EB%B2%95%EB%A0%B9/%ED%95%A0%EB%B6%80%EA%B1%B0%EB%9E%98%EC%97%90_%EA%B4%80%ED%95%9C_%EB%B2%95%EB%A5%A0/%EC%A0%9C2%EC%A1%B0
  - 서울시 선불식 할부거래업 등록안내: https://news.seoul.go.kr/economy/archives/137
  - 자본금 15억 유지의무(정책브리핑): https://www.korea.kr/news/policyNewsView.do?newsId=148891524
- **판정**: 임종 직후 3일장(**제공시기 확정**)을 위한 즉시결제는 선불식 할부거래 **비해당**(전자상거래 선결제에 가까움). 그러나 "미리 가입·적립하는 상조상품/멤버십"으로 확장하면 **상조업 규제 직격**. 본부-지점에서 **본부가 전 지점 선수금을 중앙 수금하면 규모가 커져 리스크 확대**.
- **데모 기능**: 결제 화면에 "**제공시기 확정형 즉시결제 — 선불식 비해당**" 배지 + 정책 화면에 **선불/즉시결제 판정기 위젯**(토글 시 상조업 등록 요건 온오프를 근거 조문과 함께 표시). "미리 가입/적립" 옵션은 의도적 잠금 + "상조업 등록 대상" 뱃지.

### 발견 ② [사업모델 의존] "실시간 빈소 현황"의 성립 여부
- **근거**: 공공데이터 「전국 장례식장 현황」은 **정적 시설정보만**(빈소수·안치구수), 실시간 점유 아님. e하늘이 실시간 제공하는 건 **화장장 예약**이지 빈소 점유가 아님.
  - 전국 장례식장 현황 API: https://www.data.go.kr/data/15122367/openapi.do
  - e하늘 장사정보서비스: https://www.15774129.go.kr/portal/esky/main/main.do
- **판정**: 오픈마켓이면 통합 API 부재로 **치명**. **본부-지점이면 본부 중앙 DB로 실시간 성립(치명 → 관리 가능)**. 병목이 "API 부재"에서 "**지점 직원이 안치·발인 순간 곧바로 갱신하는가**"로 이동.
- **남는 관건**: ① 지점 단말 **초경량 입력**(탭 한 번: 가용/예약중/입관/발인) ② 기존 현황판·POS와 **이중입력 방지**(플랫폼을 단일 소스로) ③ 직영 vs 가맹 자체시스템 혼재 시 신뢰 편차.
- **데모 기능**: 지점 오피스 **원터치 빈소 상태 토글** → 본부 대시보드 전국 지점 지도에 **즉시 반영**. **지점 유형 배지**(직영=실시간·본부관제 / 가맹·제휴=최종확인 시각 + 전화확인 CTA)로 신선도 근거 구분.

### 발견 ③ [운영 중 반드시 터짐] PG 자금흐름·중개책임
- **근거**: 플랫폼이 결제대금을 직접 수령·정산하면 **PG 등록 의무 및 중개자 책임** 발생. 현금결제는 **에스크로 의무**(신용카드 제외).
  - 에스크로 vs 지급대행(PortOne): https://blog.portone.io/ps_escrow-vs/
  - 전자상거래법(국가법령정보센터): https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=282793
- **판정**: "PG 연동" 한 줄이지만 **자금흐름(플랫폼 수령형 vs 지점 직수령 대행형)**에 따라 법적 지위·수수료·정산주기·환불책임이 통째로 달라진다. 본부-지점에선 "본부 중앙 수금 vs 지점 직수령"이 곧 발견 ①의 선불식 강도와 연결.
- **데모 기능**: 마스터 결제관리에 **자금흐름 다이어그램 토글**((a)본부 중앙수금 (b)지점 직수령 대행 → 필요 등록·책임주체·에스크로·선불식 리스크가 바뀌어 표시). 결제 흐름에 **"예약금 PG 예치 → 지점 승인 시 확정, 미승인 자동환불"** 상태머신 실동작.

### 발견 ④ [수요 리스크·도메인 실무] "예약"보다 즉시배정 관행
- **근거**: 선행 O2O 고이는 "예약"이 아니라 **비용·시설 비교 + 알고리즘 견적**으로 진입. 임종 순간엔 병원 영안실·연계 상조가 이미 개입해 사실상 즉시 배정.
  - 한국경제(고이장례연구소): https://www.hankyung.com/society/article/2022042005031
  - 고이: https://www.goifuneral.co.kr/
- **데모 기능**: 홈 동선을 **"비교·견적 먼저 → 예약은 그다음"**으로. "지금 임종하셨나요?" 원클릭 → **즉시 상담연결 + 인근 가용 빈소 3곳** 응급 플로우. 예약은 "**보류(hold) 15분**"으로 완화해 더블부킹·수요괴리 동시 방어.

### 발견 ⑤ [개인정보·정책] 모바일 부고장

  - 카카오 알림톡 가이드: https://kakaobusiness.gitbook.io/main/ad/infotalk
  - 카카오 개인정보 보호정책: https://privacy.kakao.com/policy?lang=ko
- **데모 기능**: 부고장은 **링크 공유** 방식 명시 + **비공개 항목 토글**(조의계좌·유족연락처 숨김/열람 시 확인), **링크 유효기간·조회수** 표시, 발인 후 자동 만료. "가상 데이터" 워터마크.

### 발견 ⑥ [본부-지점 신규] 가맹사업법 — 직영이면 소멸, 가맹이면 발생
- **근거**: 가맹본부는 **정보공개서 등록·제공 의무**, 가맹금 **예치** 의무, 그리고 **판매가격 부당 지정·강제 금지**(재판매가격유지 위반 시 시정·과징금).

  - 서울시 정보공개서 신규등록 안내: https://news.seoul.go.kr/economy/archives/501229
  - 공정위 정보공개서 제도(kofair): https://www.kofair.or.kr/home/content.do?menu_cd=000023
  - 가맹본부 준수사항(찾기쉬운 생활법령): https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=647&ccfNo=3&cciNo=2&cnpClsNo=2
- **데모 기능**: 지점 관리에 **유형(직영/가맹/제휴) 필드** → 가맹 선택 시 정보공개서·가맹금 상태 필드 노출. 정책 화면에 **가맹/직영 규제 온오프 위젯**.

### 발견 ⑦ [본부-지점 신규] 용품 단가 정합성(브랜드 가격 일관성)
- **문제**: 지점별 자유설정이면 같은 브랜드에서 관 80만↔120만 편차 → 신뢰·견적 정합성 붕괴. 반대로 본부 완전강제는 가맹에서 위법 소지(발견 ⑥).
- **해법**: **본부 표준(권장)가 + 지점 오버라이드(±밴드·승인제)**. 밴드 안=자동승인, 밖=본부 승인요청. 가맹은 강제 아닌 밴드라 위법 회피, 직영은 밴드 0으로 통일.
- **데모 기능**: 마스터 「용품 표준단가」 항목별 권장가+밴드 → 지점 오피스엔 **밴드 슬라이더**(밖은 빨강+승인요청) → 견적산출기는 선택 지점 확정가로 실시간 합산. 본부 대시보드 **지점 간 가격 편차 히트맵**.

7. 마이페이지(예약/결제/상담 내역)

**파트너(지점) 오피스** — 담당 지점만
8. 예약 캘린더(승인/취소·더블부킹 방지) + **원터치 빈소 상태 토글**
9. **용품 단가 — 본부 표준 + 지점 밴드 오버라이드(승인제)** — 발견 ⑦
10. 상담 관리(문의·답변)

**마스터 백오피스(본부)** — 전 지점 통합
11. 대시보드(예약건수·거래액·트래픽 카운트업·차트 + **전국 지점 실시간 지도**)

13. 결제·취소·환불 원장 + **자금흐름 다이어그램(본부수금/지점직수령 토글)** — 발견 ③
14. **용품 표준단가 + 지점 편차 히트맵** — 발견 ⑦

**정책/리스크 검토 화면(차별화 핵심 — 앱 내장)**
15. **선불식 할부거래 판정기**(즉시결제 vs 선불적립 토글 → 상조업 등록 요건 온오프) — 발견 ①
16. **가맹/직영 규제 위젯**(직영=가맹사업법 소멸 / 가맹=정보공개서·가맹금·가격강제 표시) — 발견 ⑥
17. **데이터 출처 고지**("실시간·본부관제" vs "최종확인 시각+전화확인" 구분) — 발견 ②

## 6. 제안 스택 · 일정 · 견적

**스택(데모)**: 순수 HTML/CSS/JS 단일 앱(외부 라이브러리 없이 canvas 차트·상태머신). 실제 구축 제안 스택은 프론트 택1(React **또는** Vue) + Node/Spring + MySQL + PG(에스크로 지원사).

**일정(공고 마일스톤 준용, 75일)**: 3주 기획/화면설계 → 5주 디자인 → 8주 개발·결제연동 → 10주 통합테스트·오픈. (공고가 10주 마일스톤이나 최종 75일=약 10.7주.)

**견적(예산 2,000만원에 맞춰 산정 — VAT 포함/별도는 미팅 확인)**: 공수표는 지원서 작성 단계(6단계)에서 작업별 일수·단가 합계가 총액과 맞도록 정렬해 확정. 헤드라인에 절감률을 쓰지 않고 "이 범위를 이 금액에" 프레이밍.

**의뢰자 부담**: 서버·호스팅 / PG 종량 수수료 / 카카오 공유 SDK·비즈채널 / 각종 신고·등록(통신판매·필요 시 상조업·가맹 정보공개서, 사업자 명의) / 법적 판단 책임 / 유료 폰트·이미지 라이선스(단 본 데모 폰트는 무료).

## 7. 자기 검열 체크(4단계 착수 전 재확인)
- 발견을 문서 지적으로 끝내지 말고 **화면 기능**으로 구현(판정기·자금흐름 토글·밴드 슬라이더·신선도 배지).
- 목데이터는 **실제 계산**(견적 합산·가격 편차 히트맵·환불 상태머신) — 하드코딩 금지.
- 브랜드형 마케팅 섹션을 억지로 넣지 않는다 — 이 제품은 **기능형(예약·견적·대시보드) 중심**. 공개 홈만 절제된 히어로+텍스트 리빌.
- 레퍼런스 톤(라이트·세리프·여백)과 나란히 놓아 밀리지 않는지 자기 채점.
