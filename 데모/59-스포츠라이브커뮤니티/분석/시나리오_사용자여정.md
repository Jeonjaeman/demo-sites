# FANPIT — 시나리오 · 사용자 여정

## 1. 등장인물

| # | 인물 | 원하는 것 | 불안한 것 | 겸직 |
|---|---|---|---|---|
| P1 | 라이트 팬 (출퇴근·모바일) | 3초 안에 "지금 몇 대 몇" | 스코어가 TV보다 늦음 | — |
| P2 | 헤비 팬 (집 PC) | 여러 경기 동시 감시 + 분석글 작성 | PC 관심경기가 폰에 안 뜸 | **콘텐츠 생산자 + 신고자 겸직** |
| P3 | 응원방 참여자 | 경기 중 실시간 반응 | 상대팀 조롱·도배 | P1·P2와 동일인 |
| P4 | 선수·구단 관계자/가족 | 비방 게시물 즉시 삭제 | 요청해도 무응답 → 고소 직행 | **비이용자인데 삭제 요청권을 가진 제3자** |
| P5 | 도박 홍보업자/스팸 봇 | 트래픽 탈취 | 계정 정지(→재가입 우회) | **적대적 사용자 — 빼면 설계가 무너짐** |
| P6 | 클라이언트 (1인) | 오픈 후 굴러가는 서비스 | 뭘 모르는지 모름 | **발주자+운영자+모더레이터+API 계약+CS+법적 책임 = 6역** |

> **P6의 6역 겸직이 설계 제1변수** — 관리자 화면은 "관리 기능 모음"이 아니라 **1인 운영자의 하루 처리량을 줄이는 도구**여야 합니다(그래서 관리자 홈이 통계가 아니라 처리 큐).
> **P5를 등장인물로 세운 것이 제2변수** — 국내 라이브스코어 커뮤니티는 불법 토토 1순위 유입 통로. 오픈 첫 주부터 표적이 됩니다.

## 2. 시간순 여정

| 단계 | 상황 | 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 발견 | 퇴근길 "경기 시작했나?" | 스코어보드 첫 화면 | 첫 화면 0.5초 안에 스코어가 안 보이면 삭제되는 앱 |
| 판단 | "볼 만한가" | 상세 — 라인업·프리뷰·H2H | 스코어만 있으면 포털로 감 — 체류 이유 없음 |
| 행동 | 득점 순간 | 응원방 (bump·토스트) | 커뮤니티 없으면 그냥 스코어 앱 — 차별점 소멸 |
| 대기 | 하프타임·이닝 교대 | 자유게시판·분석글 | **실제 체류시간의 대부분이 여기** |
| 실행 | 집 도착 → PC 전환 | 웹 — 관심경기·읽음 위치 연속 | "통합 환경"이 말뿐이 됨 (D-2) |
| 사후 | 종료 직후 5분 | 응원방 — **동접 피크** | 여기서 터지면 다음 경기에 아무도 안 옴 (C-1) |
| 분쟁 | 내 글이 차단됨 / 비방당함 | 임시조치 통지·이의신청 / 권리침해 창구 | 공고에 화면이 없음 — 법정 절차 공백 (B-2·C-3) |

## 3. 역할별 시야 차이 (권한 설계 핵심 — 데모의 「시점 전환」이 이것)

| 데이터 | 팬(제3자) | 작성자 | 운영자(P6) |
|---|---|---|---|
| 임시조치 게시글 | "임시 차단된 게시물" 안내만 | 사유 + D-30 + **이의신청 버튼** | 원문 보존 + 발단 + 만료 처리 |
| 응원방 메시지 | 필터 통과분만 | 내 메시지 | **홀드 큐**(자동 차단 원문) |
| 회원 | 닉네임 | 내 프로필 | 기기 지문·의심 그룹·누적 제재 |
| 라이브 스코어 | 현재 스코어 + "data N초 전" | 동일 | 폴링 상태·쿼터·캐시 히트율·장애 |

## 4. 기능별 존재 이유 전수 매핑

| 기능 | 존재 이유 |
|---|---|
| 필터 칩 라이브(n) 카운트 | 발견 단계 3초 규칙 — 업계 공통 문법 |
| 패자 디밍 .45 | 색 추가 없이 승패 읽힘 (Sofascore 실측) |
| 경기 전 프리뷰·H2H·최근 5경기 | "경기 전입니다" 한 줄로 비우지 않기 (FotMob 문법) |
| 정규화 스팸 필터 | P5 방어 — 1인 운영의 유일한 현실적 수단 (B-1) |
| 신고+차단+연락처 | Apple 1.2 4요소 (B-5) |
| 중계 지연 보정 + data N초 전 | 스포일러 = 최다 이탈 사유 (C-4). 실시간인 척하지 않기 |
| 시점 전환 + 이의신청 | 44조의2 법정 절차의 시연 (B-2) |
| PC↔앱 상태 토글 | "동기화"의 실제 니즈 = 상태 연속성 (D-2) |
| 관리자 홈 = 처리 큐 + SLA | 1인이 24h 조치 의무를 지키는 방법 (C-2) |
| 의심 그룹 일괄 정지 | 계정 정지는 재가입으로 우회됨 (C-5) |
| 부하 시뮬레이션 | 종료 직후 5분의 팬아웃 설계 근거 (C-1) |
| 스토어 체크리스트 | 8주차 등록 일정의 최대 변수 관리 (A-5) |

## 5. 비는 구멍 — 미팅 확인 필요 14건

1. 경기 취소·연기 시 응원방 처리 (동결/이관) — KBO 우천 취소 매주 발생
2. 임시조치 작성자 통지·이의신청·30일 재게시 정책 (법정 절차 — 데모 구현안 승인 필요)
3. 선수·구단 삭제 요청 창구 형식 (데모의 비로그인 폼 vs 이메일)
4. 정지 계정 재가입 정책 (기기 지문 수집 고지 — 개인정보처리방침 반영)
5. 만 14세 미만 가입 허용 여부 자체 (차단 vs 보호자 동의 수집)
6. API 장애 시 화면 정책 (데모: 캐시+N초 전 배지 — 승인 필요)
7. 스코어 오류 신고 경로
8. 응원방 홈/원정 분리 여부 (분리 = 운영 2배, 통합 = 충돌 관리)
9. 게시판 카테고리 초기 구성 (종목별 분리 시 빈 게시판 위험)
10. 광고 수익 모델 유무 (있으면 배너 심사 정책 — B-1 직결)
11. 푸시 알림 범위 (득점·관심팀 — 리텐션 핵심인데 공고에 없음)
12. 오픈 시드 콘텐츠 계획 (빈 게시판 오픈 방지)
13. 회원 탈퇴 시 작성글 처리
14. 새벽 유럽 경기 시간대 운영 공백 (자동화 커버 범위 합의)
