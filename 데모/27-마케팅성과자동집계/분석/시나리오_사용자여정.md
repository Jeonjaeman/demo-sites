# ADSUM 애드섬 — 시나리오·사용자 여정

> 기능 목록을 **시간순 사용 흐름**으로 다시 배치한 문서입니다.
> 이미지 공고와 요구사항 목록만으로는 "이 기능이 왜 있는지"가 보이지 않아, 실제로 쓰는 장면으로 펼쳤습니다.

---

## 1장. 등장인물

| 인물 | 누구인가 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **김선우 · 퍼포먼스 마케터** | 유일한 실사용자. 지금 매일 아침 4개 매체를 돌며 엑셀에 붙여넣고 있습니다. | 아침 30분을 되찾는 것. 어떤 소재를 끄고 어떤 소재에 더 태울지 **오늘 안에** 판단하는 것. | "이 숫자 맞아요?" 라는 질문. 자기가 붙여넣은 엑셀은 자기가 검산할 수 있었는데, 자동화되면 틀려도 모릅니다. |
| **박정민 · 대표(과거 PM)** | 발주자. 주 1회 전체 성과를 봅니다. 광고비 승인 권한이 있습니다. | 이번 달 광고비가 매출을 만들고 있는지. 다음 달 예산을 올릴지 내릴지. | 대시보드의 ROAS와 실제 통장이 안 맞는 상황. 그러면 대시보드 자체를 안 보게 됩니다. |
| **(잠재) 외부 대행사** | 채널 운영을 일부 맡기게 되면 등장합니다. | 자기가 돌린 채널의 성과. | — (의뢰자 입장에선 **실매출 원액을 보여주고 싶지 않은 상대**입니다) |

**한 사람이 두 역할을 겸하는가?**
대표는 발주자이면서 **뷰어**입니다. 마케터는 운영자이면서 **판정 기준을 정하는 사람**입니다.
목표 CPA를 마케터가 바꾸면 대표가 보는 "초과 소재 건수"가 달라집니다.
→ **목표 CPA 변경 이력은 남아야 합니다.** (2차 범위로 제안)

## 2장. 전체 타임라인 — 자동화 이전과 이후

### 지금 (엑셀 수작업)

```
08:40  메타 광고 관리자 로그인 → 어제 데이터 내려받기
08:48  구글 애즈 → 보고서 다운로드
08:55  카카오모먼트 → CSV 내려받기
09:02  네이버 검색광고 → 보고서
09:10  엑셀에 4개 붙여넣기, 열 순서 맞추기 (매체마다 다름)
09:25  ROAS 계산식 걸기 → 어제 대비 색칠
09:35  이상해 보이는 소재 몇 개를 눈으로 찾음
09:45  광고 관리자로 돌아가 소재 이미지 확인
────── 매일 약 1시간. 소재가 늘수록 길어짐. 주말은 밀림.
```

**여기서 이미 발생하고 있는 문제**
- 4개 시트의 "전환수"가 서로 다른 뜻인데 한 줄에 나란히 붙습니다.
- 3일 전에 붙여넣은 숫자는 그 뒤에 매체에서 값이 올라가도 **엑셀에서는 그대로**입니다.
- 소재 이미지는 매번 광고 관리자에서 다시 찾습니다.

### 자동화 이후

```
04:10  배치가 돌아 최근 14일을 다시 조회하고 덮어씀
09:00  마케터가 대시보드를 염 → 어제 잠정치와 확정 구간이 구분돼 있음
09:02  [목표 CPA 초과] 12건 / [무전환 소진] 3건 확인
09:05  무전환 소진 3건의 이미지를 그 자리에서 확인 → 2건 끄기로 결정
09:10  주간 베스트 소재의 공통점(영상 · 고객 후기 톤) 확인
────── 약 10분.
```

## 3장. 역할별 시나리오

### 시나리오 A — 마케터의 아침 10분

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| A-1 | 대시보드를 연다 | 상단 [기간] · [수집 방식] · [매출 기준] | 어제 숫자가 확정인지 아닌지 모른 채 판단합니다. **전환 지연 때문에 어제 값은 최종의 62% 수준입니다.** |
| A-2 | 신선도 배너를 본다 | "최근 6일은 잠정치입니다" | 어제 성과가 나빠 보여서 잘 되던 소재를 끕니다. 3일 뒤에 전환이 채워집니다. |
| A-3 | KPI 6장을 훑는다 | 광고비 / 매출 / ROAS / CTR / 전환 / CPA | — |
| A-4 | **"매출이 왜 이렇게 높지?"** | [매출 기준] 세그먼트 → 채널 합산 ↔ 광고 기여 ↔ 전체 실매출 | 채널 합산값을 진짜 매출로 믿습니다. **데모 기준 45% 부풀려져 있습니다.** |
| A-5 | 중복 진단 카드를 확인 | 3단 게이지 + 중복 신고율 | "왜 다르지?"의 답이 없어 결국 매체 화면을 다시 엽니다. 자동화의 목적이 사라집니다. |
| A-6 | 목표 CPA 초과 소재를 본다 | [목표 CPA 트래킹] 4단계 판정 | 전환 0건 소재가 목록에서 빠져 **가장 돈을 버리는 소재를 못 봅니다.** |
| A-7 | 무전환 소진 3건을 클릭 | 소재 표 → [이미지] 버튼 | 어떤 소재였는지 기억이 안 나 광고 관리자를 다시 엽니다. |
| A-8 | 이미지가 안 열린다 | 3방식 비교 (저장 URL / 해시 재해결 / 자체 사본) | **"URL signature expired"** 만 보고 개발자에게 문의합니다. 이 문의가 매주 반복됩니다. |
| A-9 | 2건을 매체에서 직접 끈다 | (요구대로 자동 제어 없음) | — |

### 시나리오 B — 마케터의 월요일: 다음 주 기획

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| B-1 | 지난주 베스트/워스트를 본다 | [베스트 / 워스트] 주간 | ROAS만으로 정렬하면 **3만원 쓰고 1건 팔린 소재가 1위**가 됩니다. |
| B-2 | 기준 게이트를 확인 | "소진 30만원 이상 · 전환 3건 이상 → 후보 N개 / 표본 부족 M개 제외" | 왜 어떤 소재가 목록에 없는지 모릅니다. 시스템을 안 믿게 됩니다. |
| B-3 | **왜 잘 됐는지**를 본다 | [자동 생성 인사이트] — 형식·톤·인물·가격표기·주조색 5축 스코어카드 | "영상이 좋더라"는 감으로 남습니다. 다음 소재 발주 때 근거가 없습니다. |
| B-4 | 문장으로 읽는다 | 계산된 격차를 문장으로 (데모 기준: "카피 톤 — 고객 후기(368%, 8개)가 성분·스펙(202%, 6개)보다 166%p 높습니다") | 표를 해석할 시간이 또 듭니다. |
| B-5 | 이 데이터가 어디로 나가는지 확인 | [LLM 전송 페이로드 미리보기] | 사내 광고비·매출이 외부 모델로 그대로 나갑니다. |

### 시나리오 C — 대표의 주간 확인

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| C-1 | 이번 달 광고가 돈을 벌고 있나 | KPI [매출 기준: 전체 실매출] → **MER** | 채널 합산 ROAS 360%를 보고 예산을 늘립니다. 실제 MER은 303%입니다. |
| C-2 | 채널별로 어디에 더 태울까 | [채널별 성과] 표 | — |
| C-3 | 합계 행을 본다 | "기간이 달라 합산 불가" 명시 + MER 행 별도 | 세로 합계를 그대로 읽습니다. **틀린 수를 경영 판단에 씁니다.** |
| C-4 | 숫자가 통장과 안 맞는다고 느낀다 | [중복 진단] 카드에 이미 설명이 있음 | 대시보드를 안 보게 됩니다. 프로젝트가 실패하는 가장 흔한 경로입니다. |

### 시나리오 D — 운영자(대표 계정)의 관리자 화면

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| D-1 | 오늘 배치가 잘 돌았나 | 관리자 [배치] 로그 | 데이터가 비어도 며칠 뒤에 압니다. |
| D-2 | 카카오는 왜 자동이 아닌가 | [연동 상태] — 심사 D+10 · CSV 대체 동선 | "연동한다더니 왜 수동이냐"는 오해가 생깁니다. **상태를 화면에 드러내는 것이 신뢰입니다.** |
| D-3 | 재수집 창을 조정 | [배치] 3/7/14/30일 + 회수량·호출량 그래프 | 무작정 30일로 잡아 API 호출만 5배 늘립니다. |
| D-4 | 토큰 만료가 다가온다 | [연동 상태] 토큰 만료 D-41 | **메타 시스템 사용자 토큰이 만료되어 어느 날 수집이 멈춥니다.** |
| D-5 | 목표 CPA를 조정 | [목표 CPA] 개별·일괄 | 소재가 늘 때마다 개발자에게 요청합니다. |
| D-6 | 대행사에 화면을 열어 준다 | [권한] 뷰어 = 실매출 금액 숨김, 지수만 | 실매출 원액이 외부로 나갑니다. |
| D-7 | 착수 전 리스크를 확인 | [검토 항목] 8건 · 등급 필터 | 같은 논의를 미팅마다 반복합니다. |

## 4장. 역할별 시야 차이 — 권한 설계의 핵심

같은 데이터를 역할에 따라 다르게 봅니다. 이 표가 권한 설계의 근거입니다.

| 데이터 | 대표 | 마케터 | 뷰어(대행사) | 근거 |
|---|---|---|---|---|
| 전체 실매출 | 금액 | 금액 | **지수만** | 대행사에 실매출 원액을 줄 이유가 없습니다. ROAS 지수만으로 운영 가능합니다. |
| 목표 CPA 수정 | 가능 | 가능 | 불가 | 판정 기준이 바뀌면 모든 리포트가 달라집니다. |
| API 키·토큰 | 마스킹 표시 | 불가 | 불가 | 광고 계정 토큰 유출 = 예산 집행 권한 유출입니다. |
| 채널 연동 설정 | 가능 | 불가 | 불가 | 설정 변경은 과거 데이터 정합성에 영향을 줍니다. |
| CSV 내보내기 | 가능 | 가능 | 금액 제외 열만 | 반출은 가장 흔한 유출 경로입니다. |
| LLM 인사이트 요청 | 가능 | 가능 | 불가 | 외부 모델 호출은 사내 데이터의 외부 전송입니다. |
| 배치 수동 실행 | 가능 | 가능(일 3회) | 불가 | rate limit을 넘기면 그날 수집 전체가 실패합니다. |

## 6장. 예외 상황 — 시나리오를 그리면 드러나는 구멍

| 상황 | 지금 정의가 없는 것 | 데모에서의 처리 |
|---|---|---|
| **주문이 취소·반품되면?** | 실매출에서 언제 빼나. 매체 신고 전환매출은 취소를 반영하지 않습니다 | 미구현 — **미팅 확인 항목** |
| **토큰이 만료되면?** | 수집이 멈춘 걸 누가 어떻게 아나 | [연동 상태]에 토큰 만료일 D-표시 |
| **배치가 실패하면?** | 재시도 횟수, 실패 알림 채널, 부분 성공 처리 | 배치 로그에 rate limit 대기·SKIP 표기 |
| **매체가 어트리뷰션 정책을 또 바꾸면?** | 과거 데이터와의 비교 기준을 어떻게 끊나 | **미팅 확인 항목** — 정책 변경일에 baseline 마커를 두는 방식 제안 |
| **소재가 매체에서 삭제되면?** | 과거 리포트의 이미지가 사라집니다 | 자체 스토리지 사본 방식 제시 |
| **네이버에 소재 단위가 없으면?** | "소재별 목표 CPA"를 무엇에 걸 것인가 | [지표 매핑]에 명시 — **미팅 확인 항목** |
