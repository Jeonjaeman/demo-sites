아래 4건은 모두 제가 직접 기획·디자인·개발·배포까지 진행해 실제로

전 기능을 확인하실 수 있습니다. 이번 프로젝트의 구성 요소 —
모니터링 대시보드, 접근성 설계, 다국어, 모바일 앱 UI, 관리 시스템 —
를 각각 실전 수준으로 다뤄본 경험입니다.

[1] 스마트 HACCP 모니터링 웹+앱 (본 공고 대응 데모)
https://jeonjaeman.github.io/demo-sites/ondo/
https://jeonjaeman.github.io/demo-sites/ondo/mobile.html

- 진행 과정
  공고 분석 → 제도 리서치(식약처 스마트 HACCP 고시·인증 4대 요건,
  색각 접근성 지침, 식품 현장 외국인 인력 언어 구성) → 디자인 실측
  (Linear의 다크·보라 토큰, SafetyCulture의 신호등 점검 문법) →
  웹 3화면+앱 4화면 구현 → 브라우저 실측 검증(콘솔 에러 0건·상태
  판정 실계산·모바일 375px)까지 이틀 내 완료했습니다. 이 속도가
  "수정 요청 당일~익일 반영"의 근거입니다.

- 특징
  공고의 디자인 요구(다크+보라·큰 글씨·신호등·최소 조작)를 문구
  그대로 구현하되, 요구사항끼리 충돌하는 지점을 찾아 해결했습니다.
  신호등 컬러만으로는 적록색각이상 근로자가 상태를 구분할 수 없어
  접근성 요구와 충돌합니다. 모든 상태를 색+아이콘+텍스트 3중으로
  표시하고 색각 보조 모드(청/주황 팔레트 전환)를 추가했습니다.

- 핵심 요소
  이탈 시뮬레이션 버튼 하나로 푸시 알림 → 해당 설비 화면 자동 이동
  → 개선조치 입력 → 복귀 기록까지 이어지는 최소 조작 동선, 전자기록
  해시 체인 화면(위변조 방지 요건의 가시화), 큰 글씨 3단계 토글,
  한국어/영어/베트남어 즉시 전환, canvas 자체 구현 24시간 차트(한계선
  CL·이탈 포인트 표시), 식약처 제출용 기록부(PDF 저장·CSV).

[2] 학원 통합 관리 시스템 (출결·수납·성적·알림)
https://jeonjaeman.github.io/demo-sites/dojang/

- 진행 과정
  의뢰 요구는 "노션·Zapier 조합을 자체 시스템으로"였습니다. 기존
  구성의 문제(학생별 공개 링크의 유출·검색 노출 위험, 자동화 도구
  월 구독비)를 먼저 정리하고, 권한 구조를 설계한 뒤 화면을 만들었
  습니다. 원장·강사·학부모 3단계 권한이 실제로 다른 화면을 보도록
  역할 전환 데모까지 구현했습니다.

- 특징
  관리 시스템의 핵심인 "권한별 시야 분리"를 문서가 아니라 동작으로
  증명했습니다. 강사는 담당 반만, 학부모는 자기 자녀만 — 내부 메모는
  비노출. 이번 프로젝트의 관리자·현장·품질 3롤 구조와 같은 문제입니다.

- 핵심 요소
  출결 키오스크(번호/QR 입력·지각 자동판정), 결제 내역 매칭 시
  동명이인은 자동 처리하지 않고 수동확인 대기로 두는 오매칭 방지
  설계, 기준 미달 시 보충 콘텐츠 자동 배정과 알림 발송 이력, 통계
  실계산과 CSV 산출, 학부모용 무로그인 24시간 만료 토큰 링크.

[3] 외국인 고객용 차량 이용가이드 모바일 앱
https://jeonjaeman.github.io/demo-sites/keyring/

- 진행 과정
  렌터카 외국인 고객이 QR을 찍으면 차종별 가이드가 열리는 구조를
  기획부터 만들었습니다. 언어 설계 → 화면 구현 → 관리자(원고 등록
  →QR 즉시 발급) 순으로 진행했고, 현위치 지도 기능이 위치기반서비스
  사업 신고 대상이라는 법적 리스크를 착수 전에 확인해 동의 게이트
  방식으로 풀었습니다.

- 특징
  주 사용자가 외국인이라는 점이 모든 설계를 좌우한 프로젝트입니다.
  한국어/영어/중국어/일본어 4개 언어를 사전 구조로 만들어 언어 추가가
  파일 추가로 끝나게 했고, 기계번역 화면에도 안전 주의사항만은
  한국어 원문을 병기해 오역 배상 리스크를 차단했습니다. 이번
  프로젝트의 외국인 근로자 접근성 설계와 같은 축입니다.

- 핵심 요소
  QR 스캔 → 딥링크로 해당 차종 가이드 자동 오픈, 다국어 사전 구조,
  탭투콜 비상연락, 위치 동의 시에만 거리순 정렬(거부 시 목록만),
  관리자에서 원고를 수정해도 QR이 불변이라 재인쇄가 필요 없는 구조.

[4] 마케팅 성과 모니터링 대시보드
https://jeonjaeman.github.io/demo-sites/adsum/

- 진행 과정
  광고 채널별 성과를 한 화면에 모으는 대시보드로, 착수 전 각 광고
  API 명세를 실제로 확인해 "매출 필드가 API에 없다", "채널별 기여
  기간 차이로 합산 시 중복이 생긴다"는 데이터 정합성 문제를 먼저
  찾아냈고, 이를 화면 기능(중복 제거 토글·수집 시점 보정)으로
  구현했습니다.

- 특징
  모니터링 대시보드에서 중요한 것은 차트가 아니라 "숫자를 믿을 수
  있는가"라는 관점으로 만들었습니다. 이번 프로젝트의 온도 데이터도
  같은 문제입니다 — 센서값·판정·기록이 흐트러지지 않는 구조가 핵심
  이고, 그 경험을 그대로 가져갑니다.

- 핵심 요소
  외부 라이브러리 없는 canvas 차트(스파크라인·추이·비교), KPI 실계산,
  필터·기간 변경 시 전체 지표 동기 갱신, 다크 테마 대시보드 디자인
  실측(어워드 수상작 기준선), CSV 내보내기.

[공통 진행 방식]

네 프로젝트 모두 같은 과정으로 진행했습니다 — ① 요구사항을 사용
흐름으로 재구성 ② 제도·기술 리서치로 요구사항의 함정을 착수 전에
발견 ③ 레퍼런스를 브라우저로 실측해 디자인 기준선 확보 ④ 발견한
문제를 문서가 아니라 동작하는 기능으로 구현 ⑤ 브라우저 실측 검증
(콘솔 에러 0건·실계산 확인·모바일 뷰포트) 후 공개. 이번 프로젝트도
기존 MVP 코드 분석 → 리뉴얼 설계 → 웹/앱 병행 구현 → 접근성 검증의
같은 과정으로 진행합니다.
