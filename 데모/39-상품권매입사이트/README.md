# PINGUARD 핀가드 — 상품권 매입 준법 데모

상품권 매입(현금화) 서비스 **제안용 데모**. 공고를 그대로 만들면(회원가입 없이 3초 자동송금·
소액결제 상품권 현금화·핀 자동 스크래핑) 정보통신망법·특금법·전자금융거래법·대부업법에
걸립니다. 이 데모는 **속도가 아니라 준법(KYC·AML·FDS)** 을 전면에 세운 버전으로 재구성하고,
위법 지점을 **‘준법 진단’ 화면**으로 노출합니다.

> ⚠️ 제안 검토용 **비공식 데모**이며 실제 서비스가 아닙니다. 매입률·거래·계좌·사업자정보는
> 전부 가상입니다. 실제 불법 자동화(소액결제 현금화·발행사 스크래핑)는 구현하지 않았습니다.

## 화면
| 파일 | 화면 | 핵심 |
|---|---|---|
| `index.html` | 공개 매입 사이트 | 시세 그리드 · 4단계 신청(종류→핀·**구매경로 차단**→**KYC 게이트**→계좌) · 실시간 견적 · 처리 현황 |
| `compliance.html` | **준법 진단** | 공고 요구 기능별 위법 신호등(위법 3·조건부 2·준법 3) + 근거 법령 + 준법 대안 |
| `admin.html` | 관리자 | 주문관리 · 송금관리(전 조건 통과분만) · 매입률 설정(실시간 재계산) · 이상거래(FDS) 룰 |

## 체험 시나리오
1. 시세 그리드에서 상품권 클릭 → 신청으로 이동.
2. 2단계에서 구매경로 **“소액결제·카드로 방금 구매”** 선택 → 위법 경고 + 다음 버튼 잠김.
3. **“본인 보유”** 선택 → 진행. 핀 다건 입력 시 우측 견적 실시간 계산.
4. 3단계 **본인확인(KYC)** 입력 전에는 다음 잠김, 입력하면 “송금 가능 상태”로 전환.
5. `compliance.html`에서 위법/조건부/준법 필터로 요구 기능 진단 확인.
6. `admin.html` → 주문관리에서 **10건 대량 주문은 FDS ‘보류’로 송금 잠김** 확인.
7. 매입률 설정에서 매입률 변경 → 주문 지급예정액 즉시 재계산.
8. 송금관리에서 전 조건 통과 주문만 **송금 실행** 가능.

## ⚠️ 착수 전 확인 (미팅)
- 상품권매매업 사업자등록·통신판매업 신고 여부(전제)
- 본인확인(KYC) 수단, PG·펌뱅킹 계약, 발행사(컬쳐랜드·롯데) 공식 정산 제휴 가능 여부
- 이상거래 임계값·의심거래보고(STR) 절차
- **소액결제 상품권 현금화 취급 여부** — 본 제안은 취급 불가 전제

## 리서치 핵심 (근거)
- 소액결제·카드 상품권 현금화 알선 = 정보통신망법 제72조(3년/3천만원)
- 상품권 매매업 가장 계좌의 자금세탁 악용 처벌(대법원 판례)
- 자금세탁방지 고객확인의무(KYC/CDD) — 무인 송금과 충돌
- 컬쳐랜드 자동등록은 발행사 보안(다중IP·VPN·매크로 감지)에 차단 → 기술적 실패
- 상품권 예약판매·선지급 = 불법 대부(전국 첫 처벌)
- 상품권매매업 = 부가세 면세·통신판매업 신고 필수

## 기술 구성
- 순수 HTML/CSS/바닐라 JS, 빌드 없음, 정적 서버 즉시 실행.
- 실제 계산: 매입률×액면×건수 견적, **FDS 룰 실판정**(건수·금액), 매입률 편집 시 지급액 재계산.
- 스크롤 리빌은 `getBoundingClientRect` 기반(백그라운드 탭에서도 표시). `localStorage` 매입률 저장.
- 375px 무-가로스크롤, `prefers-reduced-motion` 존중.
- 파일: `assets/css/pinguard.css` · `assets/js/{data,app,compliance,admin}.js`
