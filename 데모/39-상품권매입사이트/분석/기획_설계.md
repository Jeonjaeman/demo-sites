# 상품권 매입 홈페이지 — 기획·설계 (PINGUARD 핀가드)

> 크몽 공고: **상품권 매입 홈페이지 구축** · 예산 500~1,000만원(표시 500만) · 착수 후 2개월 이내 ·
> 컬쳐랜드/롯데 자동판별·자동송금, 그 외 상품권 채널톡 상담, 관리자(주문·등록상태·송금·매입률).
> 참고 사이트: livecon.co.kr · 24pin.co.kr · 24pinfarm.co.kr
> ⚠️ 데모 내 매입률·거래·계좌·사업자정보는 전부 제안용 가상 데이터.

## 0. 이 건의 핵심 — "만들 수 있다"가 아니라 "그대로 만들면 처벌받는다"

이 공고는 화면 난이도보다 **법적 리스크**가 본질입니다. 요구사항을 그대로 구현하면
정보통신망법·특정금융정보법·전자금융거래법·대부업법에 걸립니다. 그래서 이 제안은
**속도(3초 자동송금)가 아니라 준법(KYC·AML·FDS)** 을 전면에 세운 버전으로 재구성하고,
위법 지점을 **‘준법 진단’ 화면(compliance.html)** 으로 노출했습니다.

## 1. 명시된 니즈 / 숨은 니즈

### 명시된 니즈
- 상품권 종류 선택 · 핀번호 다건 입력 · 고객 계좌 입력 · 주문 접수/조회
- 컬쳐랜드/롯데 자동 판별 → 성공 시 자동 송금 / 실패 시 오류·관리자 확인
- 그 외 상품권(문화·신세계·스타벅스)은 채널톡 상담 연결
- 관리자: 주문관리 · 등록상태 확인 · 송금관리 · 매입률 설정

### 숨은 니즈
| 단서 | 숨은 니즈 |
|---|---|
| "현재 홈페이지·채널톡 연동 운영 중, 고도화" | 이미 영업 중 → 지금 구조의 **법적·운영 리스크를 줄이는 것**이 진짜 목적일 수 있음 |
| "회원가입 없이 자동 송금(참고 사이트 3초)" | 편의를 원하나, 본인확인 없는 송금은 **자금세탁·대포통장 방조** 위험 |
| "스크래핑/RPA 우대" | 컬쳐랜드 자동등록을 원하나, 발행사 보안에 **막혀 실패**하는 구조 |
| "PG·펌뱅킹 우대" | 무인 송금 자동화를 원하나, **이상거래 필터** 없이는 위법 방조 |

## 2. 웹 리서치 — 그대로 만들면 실패하는 지점 (근거)

1. **소액결제·카드로 산 상품권 현금화 알선 = 형사처벌** — 통신과금(소액결제) 현금화를
   업체가 수수료를 받고 알선·대행하면 정보통신망법 제72조 위반(3년 이하 징역/3천만원).
   근거: [아하 법률QA](https://www.a-ha.io/questions/4f89a7a7e52351acb0b1993a6e555d8f)
2. **상품권 매매업 가장 계좌의 자금세탁 악용 처벌(대법원 판례)** — 상품권 매매업체로 가장한
   법인계좌를 도박조직에 제공한 사건을 대법원이 처벌. 본인확인 없는 자동송금은 그 통로가 됨.
   근거: [대법원 판례속보](https://sc.scourt.go.kr/portal/news/NewsViewAction.work?seqnum=10463&gubun=4)
3. **자금세탁방지 고객확인의무(KYC/CDD)** — 금융 관련 서비스는 자금세탁 악용 방지를 위해
   고객확인·거래목적확인 의무. 무인 송금은 이 의무와 정면충돌.
   근거: [고객확인제도(나무위키)](https://namu.wiki/w/%EA%B3%A0%EA%B0%9D%ED%99%95%EC%9D%B8%EC%A0%9C%EB%8F%84)
4. **컬쳐랜드 자동등록은 발행사 보안에 차단** — 다중 IP·VPN·반복·매크로 접속을 감지해 계정
   자동 차단·본인인증 요구. 스크래핑 자동화는 곧 막혀 서비스가 중단됨(+약관 위반).
   근거: [상품권닷컴 로그인 제한 안내](https://xn--zf0b677a8no.com/info/%EC%BB%AC%EC%B3%90%EB%9E%9C%EB%93%9C-%EB%A1%9C%EA%B7%B8%EC%9D%B8-%EC%A0%9C%ED%95%9C%EC%82%AC%EC%9C%A0%EC%99%80-%ED%95%B4%EA%B2%B0%EB%B0%A9%EB%B2%95-315)
5. **상품권 예약판매·선지급 = 불법 대부(사금융)** — 먼저 현금을 주고 상품권으로 이자를 붙여
   받는 구조는 불법 대부로, 전국 첫 처벌 사례.
   근거: [국민일보 보도](https://www.kmib.co.kr/article/view.asp?arcid=0030138616)
6. **상품권매매업 = 부가세 면세·통신판매업 신고 필수** — 상품권은 재화가 아니므로 매매업은
   부가세 면세(그 외 기타 금융업), 세금계산서 발급 불가. 온라인 판매는 통신판매업 신고 필수.
   근거: [홈택스 질의회신](https://txsi.hometax.go.kr/docs/customer/case/qna_view.jsp?docu_no=55406)

**우선순위:** 그대로 만들면 위법(소액결제 현금화·무인송금·예약판매) > 기술적으로 실패(스크래핑) > 사업 요건(사업자·통신판매업).

## 4. 발견을 화면(기능)으로 — 문서에만 적지 않았습니다

| 발견한 위험 | 화면으로 구현한 대안 |
|---|---|
| 소액결제·카드 현금화 알선 위법 | 신청 2단계에 **구매경로 확인** — 소액결제·카드 선택 시 **실제로 차단**(다음 비활성 + 근거 경고) |
| 본인확인 없는 자동송금 위법 | 3단계 **KYC 게이트** — 실명·계좌주 확인 통과해야만 다음/송금 가능 |
| 무인 자동송금 자금세탁 방조 | 관리자 **FDS 실판정**(건수·금액 기준) — 10건 이상/고액은 자동 보류, 통과분만 송금 버튼 활성 |
| 컬쳐랜드 스크래핑 실패·약관위반 | 자동등록 대신 **검수 큐 + 상담매입** 표기, 준법 진단에서 대안 명시 |
| 예약판매·선지급 불법사금융 | 준법 진단에서 차단 판정 + "즉시 매입만" 대안 |

## 6. 제안 스택 & 견적
### 스택
- 정적 데모: HTML/CSS/바닐라 JS(빌드 없음), Pretendard.
- 실제 구축: 프론트(퍼블리싱·신청 플로우) → Node 기반 관리자·주문 API → 본인확인(KYC) 연동 →
  PG/펌뱅킹 송금 연동(이상거래 필터 경유) → 채널톡 API.
