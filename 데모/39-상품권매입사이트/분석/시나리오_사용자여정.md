# 시나리오 · 사용자 여정 — PINGUARD 핀가드

상품권 매입 서비스를 누가·왜 쓰는지 시간순으로 재구성한다. 이 서비스의 핵심 갈등은
"빠르게 현금을 받고 싶은 판매자"와 "자금세탁·불법을 막아야 하는 운영자·법" 사이에 있다.

## 1. 등장인물
| 역할 | 누가 | 무엇을 원하나 | 무엇을(누가) 불안해하나 |
|---|---|---|---|
| **일반 판매자** | 선물받은 상품권을 현금화 | 빠르고 안전하게 제값 받기 | 사기·미지급, 개인정보 유출 |
| **악용 시도자** | 소액결제·카드깡, 대포통장 환전 | 신원 노출 없이 현금 세탁 | (막아야 할 대상) |
| **운영자(관리자)** | 매입·송금 처리 | 정상 거래만 자동화, 이상은 걸러내기 | 자금세탁 방조로 **형사책임** |
| **대표/사업자** | 서비스 운영 | 합법 테두리 안의 지속 운영 | 단속·계좌지급정지·처벌 |
| **발행사(컬쳐랜드 등)** | (외부) | 약관대로 정상 사용 | 자동 등록·대량 소진 |

★ 같은 "자동 송금" 기능이 일반 판매자에겐 편의지만, 악용 시도자에겐 세탁 통로가 된다.
그래서 **속도보다 본인확인·이상거래 판정이 먼저**여야 한다.

## 2. 시간순 여정
| 단계 | 상황 | 쓰는 화면 | 준법 장치가 없으면 |
|---|---|---|---|
| 발견 | "상품권 현금화하려는데" | 히어로·시세 그리드 | 매입률만 보고 아무 데나 감(사기 노출) |
| 확인 | 얼마 받나 | 시세 카드 → 신청 견적 | 실지급액 모르고 신청 후 분쟁 |
| 신청1 | 상품권 종류·핀 입력 | 신청 1~2단계 | - |
| **분기** | 이 상품권 어디서 났나 | **구매경로 확인** | 소액결제·카드깡 상품권이 섞여 위법 방조 |
| **본인확인** | 실명·계좌주 확인 | **KYC 게이트** | 대포통장·타인계좌로 자금세탁 |
| 지급 | 검증→송금 | 처리 현황 | 이상거래도 무인 자동송금 → 방조 |
| 운영 | 주문·송금 처리 | 관리자 | 개발자 의존·이상거래 못 거름 |
| 사후 | 매입률 조정 | 관리자 매입률 | 시세 변동 대응 불가 |

## 3. 역할별 시야 차이 (권한 설계의 핵심)
| 데이터 | 판매자(공개) | 운영자(관리자) |
|---|---|---|
| 매입률 | 조회만 | 설정·변경(주문 지급액 즉시 재계산) |
| 핀 검증 | 결과 안내(성공/오류) | 검증 큐·수동 확인 |
| 이상거래(FDS) | 보이지 않음 | 판정 결과·보류·해제 |
| 송금 | 상태 조회 | **전 조건 통과분만** 실행 |

→ 관리자의 송금 버튼은 KYC·핀검증·FDS를 **모두 통과해야만** 활성화된다(데모에서 실제로 잠김).

## 4. 기능별 존재 이유
- **구매경로 확인**: 소액결제·카드깡 상품권을 입구에서 차단(정보통신망법 방지).
- **KYC 게이트**: 실명·계좌주 일치 없이는 송금 불가(자금세탁방지·대포통장 차단).
- **FDS 실판정**: 대량·고액·분할·심야 거래를 자동 보류(의심거래 통제).
- **매입률 설정**: 시세 변동 대응 + 지급액 즉시 재계산.
- **핀검증 큐**: 자동판별 실패분을 관리자가 수동 확인(스크래핑 의존 제거).
- **상담매입(채널톡)**: 자동판별 불가 상품권을 사람이 확인 후 매입.
- **준법 진단 화면**: 요구 기능별 위법 위험과 대안을 투명하게 고지(의뢰자 설득 + 리스크 공유).

## 5. 비는 구멍 (착수 전 미팅 확인)
1. **현재 운영 중인 사업자 형태·등록** — 상품권매매업 사업자등록·통신판매업 신고 여부(전제).
2. **본인확인(KYC) 수단** — 통신사 본인인증/계좌 1원 인증 등 어느 것을 쓸지(비용·연동).
3. **발행사 정산 채널** — 컬쳐랜드·롯데의 공식 정산/검증 제휴 가능 여부. 없으면 자동판별 불가.
4. **PG·펌뱅킹 계약** — 송금 자동화 주체·수수료·한도.
5. **이상거래 임계값·의심거래보고(STR) 절차** — 보류 기준과 보고 책임자.
6. **소액결제 현금화 취급 여부** — 본 제안은 **취급 불가**를 전제. 취급을 원하면 계약 불가 사유.
7. **개인정보·계좌정보 보관 정책** — 파기 시점, 암호화, 접근 권한.

## 6. 데이터·사실성
데모의 매입률·거래·계좌·연락처·사업자정보는 전부 가상입니다. 실제 서비스 운영은
사업자등록·통신판매업 신고·본인확인·이상거래탐지를 갖춘 상태에서, 정상 보유 상품권만
취급할 때 합법적으로 가능합니다.
