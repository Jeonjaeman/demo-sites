# 시나리오·사용자 여정 (B안 · Confluence)

합병 직후의 통합 홈페이지를 **누가·왜** 방문하는지 시간순으로 재구성한다.
B안은 이 여정을 "설명"이 아니라 "브랜드 필름 챕터"로 전달한다.

## 1. 등장인물

| 인물 | 방문 목적 | 불안·궁금증 |
|---|---|---|
| 기존 고객 (오브젠·잘레시아 각각) | 내가 쓰던 서비스/담당이 어떻게 되나 | 합병으로 계약·지원이 바뀌나 |
| 잠재 고객 (기업 실무자) | 데이터·AI 파트너를 찾는 중 | 이 회사가 우리 문제를 풀 수 있나 |
| 투자자·애널리스트 | 통합 법인의 가치·방향 판단 | 합병 시너지가 실제로 있나, IR 자료는 어디에 |
| 언론·PR | 합병 사실·보도자료 확인 | 공식 입장·타임라인이 명확한가 |
| 파트너 | 협업 접점 탐색 | 통합 후 어느 조직과 이야기하나 |
| **운영자(관리자)** | 공지·IR·보도자료 게시·수정 | 개발자 없이 콘텐츠를 바로 올릴 수 있나 |

★ 한 사람이 두 역할을 겸한다: **기존 고객이자 투자자**, **언론이자 잠재 파트너**.
그래서 첫 화면은 "제품 소개"가 아니라 "무슨 일이 있었는가(합병)"에서 시작해야 모두를 포섭한다.

## 2. 시간순 여정

| 단계 | 상황 | 쓰는 화면(챕터) | 없으면 벌어지는 일 |
|---|---|---|---|
| 발견 | 합병 뉴스를 듣고 접속 | Ch.00 히어로 "두 흐름, 하나의 오브젠" | 무엇이 달라졌는지 못 읽고 이탈 |
| 이해 | 두 회사가 뭘 하던 곳인지 | Ch.01 두 회사 | 합병의 맥락 없이 제품만 보고 혼란 |
| 납득 | 합병이 왜 의미 있나 | Ch.02 합병의 순간(convergence) | "그래서 뭐가 좋아졌나"에 답 못 함 |
| 신뢰 | 통합 후 무엇을 더 잘하나 | Ch.03 하나의 오브젠 + 시너지 | 근거 없는 선언으로 읽힘 |
| 검증 | 실제로 오래된 회사인가 | Ch.04 연혁 타임라인 | 신생 법인처럼 보여 투자 신뢰 하락 |
| 탐색 | 우리 문제에 맞는 서비스인가 | Ch.05 통합 서비스 | 제품 나열만 보고 판단 불가 |
| 확인 | 공식 자료·IR을 찾음 | Ch.06 뉴스룸·IR(검색·필터·다운로드) | 자료가 흩어져 IR 신뢰 하락 |
| 행동 | 문의·연락 | Ch.07 문의 | 전환 지점 없이 이탈 |
| 사후 | 운영자가 콘텐츠 갱신 | admin.html | 개발자 의존 → 갱신 지연 |

## 3. 역할별 시야 차이 (권한 설계의 핵심)

같은 "뉴스룸·IR" 데이터를 역할에 따라 다르게 본다.

- 방문자: 게시(공개) 상태 자료만, 필터·다운로드
- 운영자: 게시+임시(draft) 전부, 등록·수정·상태 전환
- → 데모의 관리자에서 "게시/임시" 상태로 이 분기를 시연한다. 실구축 시 게시된 것만 공개 노출.

## 4. 기능별 존재 이유 (전수 매핑)

| 기능 | 왜 있나 (어떤 불안을 없애나) |
|---|---|
| 두 흐름 합류 히어로 | 첫 3초에 "합병으로 무엇이 하나가 됐는가"를 전달 |
| Ch.01 두 회사 분리 제시 | 기존 고객이 "내 서비스"의 출처를 확인 |
| Ch.02 convergence 모션 | 합병의 "의미"를 텍스트가 아닌 시각으로 납득 |
| 시너지 카운트업 | 통합 규모를 즉시 체감(제안용 가상 지표 명시) |
| 연혁 타임라인 | 신생이 아닌 축적된 조직임을 증명(투자자) |
| 통합 서비스 아코디언(합병 전/후) | 어느 역량이 새로 생겼는지 구분해 신뢰 형성 |
| 뉴스룸·IR 필터·다운로드 | 투자자·언론이 필요한 자료에 빠르게 도달 |
| 통합검색 | 25페이지 규모에서 원하는 정보로 직행 |
| 문의 폼 검증 | 잘못된 문의로 인한 응대 낭비 방지 |
| 관리자 CMS | 개발자 없이 콘텐츠 갱신 → 오픈 후 유지보수 |
| 다국어(옵션) | 해외 투자자 대상 IR 확장 대비 |

## 5. 비는 구멍 (미팅에서 반드시 확인)

시나리오를 그리면 정의가 없는 지점이 드러난다.

1. **기존 고객 이관 안내** — 합병 후 계약·담당·지원이 어떻게 바뀌는지 별도 안내 페이지가 필요한가?
   (본 데모는 브랜드 서사 중심이라 이 실무 안내는 미포함 — 실구축 시 회사소개 하위에 추가)
2. **IR 공시 법적 요건** — 상장 여부·전자공시 연계 범위. 공시는 법정 양식·기한이 있어 별도 검토 필요.
3. **개인정보 이전 고지** — 합병에 따른 개인정보 이전은 법정 고지 대상. 문구는 법무 검수 필수.
4. **다국어 범위** — 핵심 메시지만인지 전체 25페이지인지. 번역 분량이 견적을 좌우.
5. **CMS 권한 체계** — 운영자 등급(작성/승인/게시)이 필요한가. 데모는 단일 운영자 기준.
6. **연혁·수치의 사실 확정** — 데모의 연도·시너지 수치는 전부 가상. 실제 값은 회사 제공 필요.

## 6. A안과의 관계

A안(Signal Loom)은 같은 여정을 "시스템 신뢰"로 푼다(플랫폼·거버넌스 강조). B안은 "브랜드 서사"로
푼다(합병 스토리·연혁·시너지 강조). 두 안은 동일 여정을 커버하며, 미팅에서 의뢰자의 우선순위
(제품 신뢰 vs 통합 정체성)에 따라 선택하거나 절충한다.
