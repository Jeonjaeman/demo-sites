## 4. 기술 스택 제안 근거

### 4-1. 접속 방식 — 반응형 모바일 웹 + PWA (앱 대체)
- **보호자는 앱을 설치하지 않는다.** 동의서 서명은 1년에 몇 번 하는 일이라 "링크 한 번 → 인증 → 서명 → 끝"이 전부여야 한다. 알림톡 링크는 설치 없이 바로 열린다.
- **학생은 홈 화면에 추가(PWA)** 하면 앱처럼 쓴다. iOS 16.4+는 홈 화면 PWA에서 웹푸시 가능(제약 있음) → 푸시는 보조, 알림톡이 주 채널. <https://documentation.onesignal.com/docs/en/web-push-for-ios>
- 네이티브 앱은 스토어 심사·개발자 계정(Apple $99/년·Google $25)·OS별 유지보수가 붙어 1,500만원 안에서 화면 퀄리티를 깎아 먹는다 → 2차에서 판단.

### 4-2. 서버·DB
- **프론트**: Next.js(React, TypeScript) — 학생/보호자 모바일 화면과 교사 PC 관리 화면을 한 코드베이스로, PWA 매니페스트·서비스워커.
- **백엔드/DB**: Node.js API + **PostgreSQL**(권한 스코프를 행 수준으로 강제하기 쉬움 — 담임은 본인 학급 행만). 파일(증빙·포트폴리오)은 객체 스토리지, 서명 원본은 변경 불가 보관.
- **클라우드**: 학생 개인정보를 다루므로 **국내 CSP(네이버클라우드 공공/NHN Cloud/KT Cloud)** 우선 제안. AWS 서울 리전은 CSAP '하'만 보유(F13). 교육청 확인 결과에 따라 확정.
- **PDF**: 서버 헤드리스 크롬(Puppeteer)으로 HTML 서식 → PDF, Noto Sans CJK KR 임베딩, 마지막 장에 감사추적(F3).
- **엑셀**: ExcelJS — 교육청 XLSX 원본 양식을 열어 고정 셀만 채워 서식 유지(양식 입수 후). 업로드 파싱은 모든 열을 문자열로 읽기(F11).
- **서명 패드**: canvas 기반 + 벡터 좌표 보존, 서버에서 SHA-256 해시·타임스탬프.

## 5. 의뢰자 기획에서 잘된 부분 (신뢰 형성용)

1. **증빙 파일 + 교사 확인 상태** — 학생이 올린 자격증을 교사가 확인해야 "이력"이 된다는 설계. 자기 신고 이력의 신뢰 문제를 이미 짚었다. 그대로 살리고 확인자·확인일 로그만 더한다.
2. **알림톡 실패 → SMS 대체 + 미확인자 재발송** — 실제 발송 운영을 해 본 사람의 요구다. 실패 사유 분류·비용 계산만 붙이면 된다(F5).
3. **교사 3단계 권한(담임 = 본인 학급)** — 같은 학생 데이터를 역할마다 다르게 봐야 한다는 핵심을 정확히 짚었다. 보호자·기업 시야까지 넓히면 완성(시나리오 문서 3장).
4. **자소서·포트폴리오 버전(v1, v2) 누적** — 상담 이력을 남기는 데 결정적이다. 버전 간 교사 코멘트 비교로 확장할 수 있다.
5. **데모 시연 요구 + 저작권 학교 귀속** — 주문 제작의 리스크를 정확히 관리하고 있다.
