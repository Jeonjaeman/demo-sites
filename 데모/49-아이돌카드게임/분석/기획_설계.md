# ENCORE 앙코르 — 기획·설계

> [모바일 웹 UI 디자인] 아이돌 카드 맞추기 미니게임 (크몽 공고) · 제안용 데모
> 그룹 LUMIN·멤버·닉네임·기록 등 모든 데이터는 가상. 실존 인물·단체와 무관

## 0. 공고 요약

- 아이돌 IP 활용 **모바일 웹 카드 맞추기(같은 그림 한 쌍 매칭) 미니게임**의 **UI 디자인만** 의뢰 (개발 X)
- 예산 카드 550만 / 본문 명시 **250~300만** · 일정 8/5~8/19 **약 2주** · 중간 산출물 8/12 · 최종+디자인 소스 8/19
- 주요업무: **모바일 페이지 UI 15~20장 내외 (7파트)** · figma 혹은 포토샵
- 자격: 웹·모바일 UI/UX 3년+ · **게임의 상태 변화와 사용자 흐름을 이해하고 화면에 반영**
- **"게임적인 기능보다는 모던하고 매거진스러운 디자인이 중요"** ← 핵심 요구
- 우대: 아이돌·엔터 콘텐츠 경험 · 짧은 일정 고완성도 · **개발 전달용 UI·에셋 정리**
- 관련자료: im-fine.co.kr — 의뢰자는 삼성·현대·기아·젠틀몬스터 인터랙티브 전시를 만든 **크리에이티브 에이전시** (엔터사 아님 → 아이돌 IP 프로젝트를 수주한 구조로 추정)
- 정책: 지원서에 외부 연락처 기입 금지

## 1. 명시된 니즈 vs 숨은 니즈

| 구분 | 내용 |
|---|---|
| 명시 | 모바일 UI 15~20장(7파트) · 매거진 톤 · 상태 변화 반영 · 2주 · 에셋 정리 |
| 숨은 ① | "상태 변화 이해" = **정적 시안 20장이 아니라 상태(대기/뒤집힘/매칭/오답/타임오버)별 화면 정의**가 필요 — 개발사에 넘길 때 분쟁이 나는 지점 |
| 숨은 ② | 의뢰자가 에이전시 → **최종 클라이언트(아이돌 IP사) 컨펌**을 통과해야 함 → 시안을 "말로 설명"하는 것보다 **눌러볼 수 있는 형태**가 컨펌 속도를 결정 |
| 숨은 ③ | 아이돌 실사진을 쓰는 순간 **퍼블리시티권 계약 범위** 확인 필요 — 시안 단계에서 무단 사진을 쓰면 그 자체가 리스크 |
| 숨은 ④ | 모바일 웹(앱 아님) = 세로 스크롤·safe-area·주소창 변수 대응이 시안에 반영돼야 개발 단계 재작업이 없음 |

|---|---|---|

| P2 게임 준비 | 03 덱 선택 · 04 난이도 | 스냅 캐러셀·선택 상태·난이도별 그리드 프리뷰 |

데스크톱은 좌측 화면 인덱스(7파트 20장) + 폰 프레임, 모바일 실기기는 풀스크린.

## 6. 레드팀 3종 검수 기록

- **① 디자인**: 생성 이미지 8장 전수 육안 검수 → 전량 "잡지 인쇄물을 찍은 사진"(VOGUE 로고·종이 테두리·바코드·읽히는 텍스트) 판정 → 프롬프트를 풀블리드·무텍스트로 고쳐 **전량 재생성**. 이모지 남발 없음·블랙+라임 단일 액센트 유지
- **② 인터랙션**: 정적 지점 4곳 지적 → 리스트/히어로 stagger 진입, 성공·신기록 콘페티 버스트(canvas), 덱 카드 호버 리프트+이미지 줌, 매치 펄스/오답 셰이크/타이머 경고/홀로 스윕은 초기 구현에 포함
- **③ 완료(실측)**: 20화면 × (오버플로·터치타겟 26px 미만·텍스트 잘림) 자바스크립트 실측 — 검출 1건(카드 상세 홀로 레이어)은 overflow:hidden 내부로 시각 문제 없음 확인. 진입 애니메이션 중간 측정으로 인한 오탐 87건은 애니메이션 정지 후 재실측으로 배제
