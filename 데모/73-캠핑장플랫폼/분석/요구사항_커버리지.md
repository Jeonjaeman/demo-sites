## 3. P0/P1/P2/제외 범위

### P0: 정적 데모에서 반드시 보여야 하는 것

1. 공개 사용자 홈/탐색: 매거진형 피드 + 날짜 칩 + 조건 필터.
2. 상세: 시설, 규정, 취소/환불, 업체 확인 상태.
3. 예약: 사이트/날짜/인원/옵션 선택과 총액 계산.
4. 목 결제: 실결제 아님을 명시하고 결제 접수 상태만 생성.
5. 완료: “예약 확정”이 아니라 “업체 확인 대기/확정/대체/취소” 상태를 분리.
6. 운영 패널 1개: 예약 요청 큐와 확정/대체/취소 상태 전환.
7. PG/사업자/환불정책 체크리스트.

### P1: 있으면 제안 신뢰가 올라가는 것

1. 예약 상태 로그: 접수 → 업체 연락 → 확정/대체/취소.
2. SLA 표시: “담당자 확인 예정 2시간 이내” 같은 운영 약속 표현.
3. 옵션상품의 환불 분리 계산.
4. 모바일 바텀시트 예약 요약.
5. 빈 상태: 선택 날짜에 예약 가능한 캠핑장이 없을 때 대체 날짜 제안.

### P2: 이번 데모에서는 축소 가능

1. 리뷰/커뮤니티.
2. AI 추천/개인화.
3. 지도 고급 기능.
4. 쿠폰/프로모션.
5. 업체별 통계/정산 리포트.

### 제외 범위: 과개발 금지

1. 실제 서버/DB/API.
2. 실제 PG 카드결제, 운영키, 웹훅, 결제 취소 API.
3. 로그인/회원가입.
4. 업체 직접 등록/관리자 CRUD 멀티페이지.
5. 실존 캠핑장/업체/사용자 데이터.
6. 배포/프로덕션 운영/외부 발송.
7. 관리자 권한관리, 정산, 세금계산서 발행 시스템.

## 4. 화면 범위 제안

| 화면 | 목적 | 포함 요소 | 상태연산 |
|---|---|---|---|
| 탐색(index) | 발견→판단 진입 | 매거진 카드, 날짜 칩, 지역/시설 필터, 가능/마감 뱃지 | 필터와 날짜에 따른 카드 목록 재계산 |
| 상세(detail) | 예약 전 신뢰 확보 | 사진, 시설, 규정, 사이트별 재고, 환불정책, 업체확인 | 사이트 선택 가능 여부, D-day 환불률 |
| 예약(booking) | 예약·옵션·목결제 | 예약자 정보 목값, 옵션 체크, 총액, 정책 확인 | 총액/옵션액/환불예상액 계산 |
| 완료(complete) | 결제 접수와 수동 확정 분리 | 접수번호, 상태 타임라인, 연락 예정, 체크리스트 | 운영 패널 변경에 따라 상태 반영 |
| 운영 패널(modal/panel) | 관리자·업체 최소 표현 | 캠핑장 목등록, 예약 큐, 확정/대체/취소 버튼 | 예약 상태 변경, SLA 초과 표시 |

멀티페이지는 탐색/상세/예약/완료만 필요하다. 관리자·업체는 별도 페이지가 아니라 1개 모달/패널 수준으로 제한한다.

## 5. 수용 기준

| 기준 | 통과 조건 |
|---|---|
| 원본 보존 | PNG 원본이 원본기획/으로 이동되어 있고 삭제/수정되지 않았다. |
| 전사 | 기능명세(의뢰자 원본).txt가 공고의 명시 요구·예산·기간·산출물·제외 범위·기획 상태·지원사업 일정·연락두절 우려를 포함한다. |
| 리서치 | 최소 4축: 전자상거래/환불, 개인정보/결제, 캠핑장 운영, PG/옵션. 각 축에 URL과 적용 조건/확인 필요 사항이 있다. |
| 레퍼런스 | 국내 1곳 이상, 해외 2곳 이상 비교. 라이브 URL이 있다. |
| MVP 매핑 | 치명적 리스크가 문서 지적이 아니라 데모 기능으로 매핑되어 있다. |
| 과개발 방지 | 실제 서버/DB/PG/API/로그인/관리자 CRUD 제외가 명시되어 있다. |
| 구현 금지 준수 | 분석 문서만 작성하고 실제 데모 구현 파일을 만들지 않았다. |

## 6. 남은 질문

1. 실제 오픈 MVP에서 결제는 확정 전/후 어느 시점에 이루어집니까?
2. 결제 실패, 확정 실패, 부분취소, 옵션만 취소의 책임자와 처리 SLA는 무엇입니까?
3. 캠핑장별 재고·환불정책·시설정보의 원천 데이터는 누가 제공합니까?
4. 업체 연락은 전화/카카오/문자/이메일 중 무엇이며, 발송 비용과 발송 주체는 누구입니까?
5. 정부지원사업 검수에서 “실제 PG 실결제”가 필수입니까, 테스트 결제/시연으로 충분합니까?
6. 오픈 후 무상 A/S 범위와 기간을 계약서에 어떻게 적을지 확인이 필요합니다.
