## 2. 판단 기준

### 2.1 CC BY 2.0

CC BY 2.0은 공유·변경·상업적 이용을 허용하지만, 적절한 credit, 라이선스 링크, 변경 표시를 요구한다.[1] 이번 파일들은 제목이 제공돼 있고 2.0 라이선스이므로 제목도 포함하는 보수적 TASL(Title, Author, Source, License) 방식으로 처리한다.[5]

**필수 게이트:** 파일별 작품명 / 저작자 / 원본 링크 / `CC BY 2.0` 링크 / 변경 설명.

### 2.2 CC BY-SA 2.0

CC BY-SA 2.0은 CC BY의 attribution 조건에 더해, remix·transform·build upon한 경우 기여분을 같은 라이선스로 배포하도록 요구한다.[2]

- `fetch_images.py`와 `refetch_images.py`는 중앙 크롭, 리사이즈, WebP 변환 및 손실 압축을 수행한다.
- `fetch_images.py`의 `is_cool()`은 쿨톤 후보를 **선별**할 뿐 픽셀 색을 보정하지 않는다. README의 “쿨톤 필터” 표현과 구현은 일치하지 않는다.
- 단순 포맷 변환·기계적 크롭이 항상 저작권법상 2차적저작물인지에는 관할·창작성 판단이 남지만, 내부 준수 게이트에서는 변경본으로 취급해 변경을 명시한다. CC 권장 예시도 단순 crop을 “Cropped from original”로 표시한다.[5]
- 안전한 운영안은 각 BY-SA WebP 변경본 자체를 `CC BY-SA 2.0`으로 표시·배포하는 것이다. 이 판단은 **해당 변경 이미지 파일**에 관한 것이며, 주변 HTML/CSS/사이트 전체를 자동으로 BY-SA로 전환해야 한다는 뜻은 아니다. 다만 이미지와 사이트 결합이 단순 collection인지 adaptation인지 특정 관할에서 다투어질 여지는 확인 필요다.

### 2.3 CC0 / PDM / Public Domain

- CC0는 권리자가 가능한 범위에서 저작권·인접권을 포기한 도구이며 상업적 복제·변경을 허용하지만, 상표·특허·초상/프라이버시 권리는 별개다.[3]
- PDM은 알려진 저작권 제한이 없음을 식별하는 표지이고 모든 관할에서 동일한 결과를 보장하지 않는다.[4]
- CC는 CC0·PDM에 attribution 법적 의무는 없더라도 호스팅 기관과 원 출처를 표기할 것을 권장한다.[5]
- `hero-main.webp`의 Commons 원본은 미국 연방정부(BLM) 업무상 저작물로 미국 내 Public Domain 설명과 CC BY 2.0 이력을 함께 보여준다.[7] 그러나 현지 `SOURCES.json`은 `license_url`이 비어 있고 creator에 HTML 문자열이 들어 있어 그대로는 공개 credits 데이터로 부적합하다.

## 5. issue / impact

### 빨강 1 — 공개 attribution 부재

- **issue:** JSON은 개발자용 내부 파일이고 공개 페이지 어디에서도 연결되지 않는다.
- **impact:** CC BY/BY-SA 조건을 충족했다고 보기 어려우며, 공개 제출 신뢰와 재사용자 provenance를 훼손한다.
- **priority:** P1, 공개 전 필수.

### 빨강 2 — BY-SA 변경물 표시·배포 조건 미처리

- **issue:** 크롭·리사이즈·WebP 변경본임을 알리지 않고 동일 라이선스도 표시하지 않는다.
- **impact:** ShareAlike 조건 누락 위험. 특히 변경 WebP 파일을 별도 다운로드·캐시·재배포하는 사용자에게 조건이 전달되지 않는다.
- **priority:** P1, 공개 전 필수.

### 빨강 3 — 출처/라이선스 provenance 실패

- **issue:** `mag-01`은 현재 원본과 manifest가 충돌하고, `theme-wide`는 원본에 접근할 수 없으며, `hero-main`은 필수 메타가 정규화되지 않았다.
- **impact:** 상업적 이용 허용 여부 또는 올바른 attribution을 입증하기 어렵다.
- **priority:** P1, 교체 우선.

## 6. proposed_text / 공개 UI 구성안

CC 권장안은 매체에 맞는 별도 attribution 웹페이지를 둘 수 있고, 가능한 경우 Author·Source·License를 따라갈 수 있는 링크로 제공하라고 설명한다.[5] 따라서 아래 구성이 합리적이다.

### 6.1 모든 페이지 footer

전 HTML footer의 기존 링크들과 같은 수준·가시성으로 다음 링크를 둔다.

> 이미지 출처·라이선스

- 링크 대상 예시: `credits.html`.
- 5개 페이지 모두에서 1회 클릭으로 접근 가능해야 한다.
- 로그인·drawer·hover·JS 실행을 요구하지 않는 일반 `<a>` 링크가 적합하다.
- alt text에 라이선스 정보를 몰아넣지 않는다. CC도 alt text·메타데이터만의 attribution을 피하라고 권고한다.[5]

### 6.2 credits 페이지 상단 공통 문구

> 이 데모의 사진은 각 항목에 표시된 원 저작자의 라이선스에 따라 사용했습니다. 사진은 레이아웃에 맞게 중앙 크롭·리사이즈하고 WebP로 변환·압축했습니다. 별도 기재가 없는 한 색상 픽셀 보정은 하지 않았으며, 수집 단계에서 쿨톤 이미지를 우선 선별했습니다. 각 라이선스는 해당 이미지에 적용되며, 데모 운영자나 원 저작자의 상호 보증·제휴를 의미하지 않습니다.

실제 색보정을 했다면 “색온도·명암을 조정했습니다”를 추가하고, 하지 않았다면 README의 “쿨톤 필터”를 “쿨톤 후보 선별”로 바로잡아야 한다.

### 6.3 CC BY 항목 템플릿

다음이 모두 확인되기 전에는 P1-07을 닫거나 공개 가능으로 판정하지 않는다.

1. `mag-01`, `theme-wide`, `hero-main`, `camp-caravan-01` 교체 또는 대표의 명시적 예외 승인과 보강 근거 확보.
2. 18개 최종 이미지와 credits 항목이 파일명 기준 1:1로 대응하고 누락·중복이 없음.
3. 모든 CC BY/BY-SA 항목에 title / author / source link / 정확한 license name+link / 변경 표시가 있음.
4. 모든 BY-SA 변경 이미지에 동일 라이선스 배포 문구가 있음.
5. 모든 HTML footer에서 credits 링크가 보이고 키보드로 접근되며 200 응답함.
6. 원본 링크 18개와 라이선스 링크를 GET으로 재확인하고, 접근 불가 또는 현재 라이선스 불일치는 교체함.
7. README의 이미지 출처 섹션이 공개 credits 페이지를 직접 링크하고 “쿨톤 필터” 표현을 실제 처리와 일치시킴.
8. 사람·브랜드·게임 화면이 남는 파일은 저작권 외 권리 검토 결과 또는 교체 결정을 기록함.
9. Argos가 P1-07 재현 절차로 5페이지 footer와 credits 페이지, 링크 접근성, 파일 수를 독립 재검증함.

## 8. questions / needs_confirmation

1. 실제 공개 전 파일에 스크립트 외 수동 색온도·명암·쿨톤 보정을 적용했는가? 적용했다면 변경 설명을 파일별 또는 공통으로 보강해야 한다.
2. `mag-01.webp`를 CC BY 2.0으로 취득한 시점의 Openverse API 원응답·다운로드 로그·스크린샷이 보존돼 있는가? 없으면 교체한다.
3. `hero-main.webp`는 미국 Public Domain 근거로 유지할지, Commons의 CC BY 2.0 경로로 attribution할지, 또는 메타 게이트 원칙대로 교체할지 결정이 필요하다.
4. `camp-glamp-02.webp`, `detail-02.webp`의 식별 가능한 사람에 대한 모델 릴리스/초상권 근거가 있는가? 없으면 무인 이미지 교체가 안전하다.
5. 공개 배포물이 대한민국 이용자만을 대상으로 하는지, 해외에서도 접근 가능한지 확인이 필요하다. PDM/미국 연방정부 PD의 관할 차이를 고려한다.
