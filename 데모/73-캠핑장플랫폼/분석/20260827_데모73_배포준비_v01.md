# 데모73 로컬 배포 준비 v01

## 변경 대상

- 루트 `index.html`: `DEMOS` 배열 선두에 CAMP FLOW 카드 1건 등록
- 루트 `campflow/index.html`: 홈 제출용 ASCII 별칭 등록
- 루트 `.claude/launch.json`: `campflow`, 포트 `8048`, 데모73 디렉터리 등록
- 데모73 `README.md`: 로컬·예상 공개 URL과 배포 전 상태 명시
- 본 문서: 배포 승인 범위·검증·롤백 절차 기록

## 포함 / 제외

포함 범위는 포털 카드, 홈 별칭, launch 설정, README와 본 준비 문서다. 데모73의 기존 정적 산출물은 배포 후보에 포함하되 이번 준비 작업에서는 기능 코드를 수정하지 않는다.

제외 범위는 기존 UNFRAME 소유 `assets/thumbs/73.webp`의 수정, Aphrodite 산출물인 `assets/thumbs/76.webp`의 내용 수정, 프린트라인 포트폴리오, 다른 데모·포털 항목, `404.html`, 지원서 placeholder 교체, 하위 페이지 별칭이다. commit·stage·push·Pages 배포도 이번 작업에서 실행하지 않는다.

## 예상 URL

- 로컬 포털: `http://localhost:8080/`
- 로컬 원본: `http://localhost:8080/데모/73-캠핑장플랫폼/index.html`
- 로컬 별칭: `http://localhost:8080/campflow/`
- launch 전용: `http://localhost:8048/`
- 예상 공개 원본: `https://jeonjaeman.github.io/demo-sites/데모/73-캠핑장플랫폼/index.html`
- 예상 공개 별칭(지원서 제출 후보): `https://jeonjaeman.github.io/demo-sites/campflow/`

공개 URL은 Pages 배포 후 HTTP 200과 브라우저 리다이렉트를 확인하기 전까지 예정값이다. 지원서의 `[배포 후 URL 입력]` placeholder는 그 확인 뒤에만 교체한다.

## 로컬 검증 기준

1. 루트 서버에서 `/campflow/`와 데모73의 `index.html`, `search.html`, `camp.html`, `booking.html`, `complete.html`, `credits.html`가 모두 HTTP 200.
2. `/campflow/?source=deploy-check#availability` 접근 시 원본 `index.html?source=deploy-check#availability`로 이동해 query와 hash가 모두 보존됨.
3. 포털에 `캠핑장 예약 플랫폼` 카드가 렌더되고 링크·카테고리·썸네일 경로가 정확함.
4. 루트 `index.html` 인라인 JavaScript 구문 오류 없음, 포털과 별칭 브라우저 콘솔 오류 0.
5. `.claude/launch.json` JSON 파싱 성공, `campflow:8048`의 `--directory`가 데모73을 가리킴.
6. 포털 썸네일 소유 규칙은 UNFRAME=`assets/thumbs/73.webp` clean 유지, CAMP FLOW=`assets/thumbs/76.webp` 신규다. 두 파일은 Aphrodite 담당 산출물이므로 내용을 수정하지 않고, 포털의 `img src`·decoded 크기·SHA-256·시각 차이만 통합 검증한다.

## commit 후보 파일

- `index.html`
- `campflow/index.html`
- `데모/73-캠핑장플랫폼/`의 배포 대상 파일(단, `node_modules/`, `qa/` 제외)
- `assets/thumbs/76.webp`는 CAMP FLOW용 Aphrodite 신규 산출물로, 내용 수정 없이 별도 소유권을 유지한 채 통합 후보에 포함

기존 UNFRAME용 `assets/thumbs/73.webp`는 clean 유지하며 이번 commit 후보에 포함하지 않는다.

`.claude/launch.json`은 저장소 `.gitignore`의 `.claude/` 규칙에 해당하는 로컬 전용 설정이므로 commit 후보에서 제외한다. 기존 dirty 파일도 staging 대상에서 제외한다. 실제 commit 전에는 위 경로를 명시적으로 지정하고 `git diff --cached --name-only`로 혼입 0건을 확인한다.

## push 영향

`main` push 시 GitHub Pages가 갱신되어 포털 카드와 `/campflow/` 공개 별칭이 새로 노출된다. 데모73 전체를 처음 추적하는 경우 저장소 용량과 Pages 빌드 시간이 증가할 수 있다. 다른 데모의 코드·URL은 변경하지 않고, 기존 `UNFRAME` 카드는 73.webp를 계속 사용하며 CAMP FLOW만 신규 76.webp를 사용한다. 외부 push는 되돌릴 수 있는 Git 변경이지만 공개 캐시와 이미 공유된 링크에는 반영 지연이 생길 수 있어 C등급 승인 대상으로 취급한다.

### 통합 위험

- 썸네일 충돌은 해소됐다. 기존 `UNFRAME`은 `./assets/thumbs/73.webp`를 clean 유지하고 CAMP FLOW는 `./assets/thumbs/76.webp`를 참조한다. 로컬 루트 서버에서 두 카드의 실제 `img src`, decoded 크기, SHA-256과 시각 차이를 재검증했다.
- `.claude/launch.json`은 로컬 ignore 파일이라 다른 환경에는 push로 전달되지 않는다. 팀 공유가 필요하면 별도 정책 변경 승인이 필요하다.

## 후속 통합 검증 결과

- 포털 카드: CAMP FLOW `./assets/thumbs/76.webp`, UNFRAME `./assets/thumbs/73.webp`; 두 이미지 모두 브라우저 decoded `900×900`, 로드 완료.
- SHA-256: 76.webp=`04b64829ab96a144e91cb36e34117a679ce5d34436c232f237616875edc96fd8`, 73.webp=`6820ad08e85d3983409c9cfbea1ed00898d4a7dc343e60965997e65f1036342a`. 축소 비교 RGB RMS=`104.39/97.39/90.96`으로 시각 데이터가 서로 다르고 카드별 소유 경로도 분리됐다.
- 충돌 해소: UNFRAME 73 clean 유지, CAMP FLOW 76 신규 규칙과 루트 `index.html` 매핑이 일치한다.
- 포털 브라우저: pageerror 0, non-favicon console error 0, non-favicon network 404 0. 기본 `/favicon.ico` 404 1건만 제외했다.
- `/campflow/?source=deploy-check#availability`는 `/데모/73-캠핑장플랫폼/index.html?source=deploy-check#availability`로 이동해 query/hash를 보존했다.
- 로컬 루트 서버: `/campflow/`와 데모 6페이지(`index`, `search`, `camp`, `booking`, `complete`, `credits`) 모두 HTTP 200.
- 회귀: `node --test tests/mvp.test.mjs` 29/29 PASS, `node scripts/qa.mjs` 81/81 PASS. QA는 저장소 파일을 건드리지 않도록 동일 소스의 임시 복사본에서 실행했다.

## 배포 후 Pages healthcheck

1. Pages workflow 성공과 배포 SHA가 승인된 commit SHA와 같은지 확인한다.
2. 예상 공개 별칭과 원본 6페이지에 `curl --fail --location --silent --show-error`를 실행해 최종 HTTP 200을 확인한다.
3. 브라우저에서 `/campflow/?source=pages-check#availability`의 최종 URL이 query/hash를 보존하는지 확인한다.
4. 공개 포털에서 카드 이미지·제목·링크를 확인하고 콘솔 오류가 0인지 확인한다.
5. 모든 healthcheck가 끝난 뒤에만 지원서 placeholder를 실제 별칭 URL로 교체한다.

## rollback

- 우선안: 배포 commit 전체를 `git revert <배포-commit>`로 되돌리고 Pages 재배포 후 기존 URL healthcheck를 반복한다.
- 부분 복구안: 이전 루트 `index.html`, `campflow/index.html`을 승인 직전 버전으로 복원하고 신규 `assets/thumbs/76.webp`를 배포 후보에서 제외한다. 기존 UNFRAME용 `assets/thumbs/73.webp`는 변경하지 않는다. 새 별칭만 철회할 경우 `/campflow/`가 404가 될 수 있으므로 이미 외부 공유했다면 삭제 대신 이전 대상 또는 안전한 안내 페이지로 되돌린다.
- launch 설정 문제는 `.claude/launch.json`의 `campflow` 항목만 이전 상태로 복원하고 JSON 파싱을 재검증한다.
- 롤백 후 포털, 기존 데모, `/campflow/`, Pages workflow 상태를 다시 확인한다.

## 승인 유효기간 제안

승인은 승인 시각부터 24시간 동안, 그리고 본 문서의 commit 후보 파일 내용이 바뀌지 않는 동안만 유효한 것으로 제안한다. 대상 파일, 배포 SHA, Pages 설정 또는 썸네일 산출물이 바뀌면 기존 승인을 무효화하고 변경 diff·영향·롤백을 다시 제시해 새 C등급 승인을 받는다.
