### P1-01. URL 파라미터가 예약 폼의 `innerHTML`에 삽입되어 DOM XSS가 실행된다

- category: security / URL validation
- files/selectors: `booking.html:74-87`, `booking.html:183-193`, `#step-body`
- reproduction:
  1. 설치된 Chrome으로 `booking.html?id=camp-areum&checkIn=%22%3E%3Cimg%20src=x%20onerror=window.__ARGOS_URL_XSS=1%3E&checkOut=2026-09-13` 접속.
  2. `window.__ARGOS_URL_XSS` 값을 확인.
- expected: 날짜 파라미터는 ISO 날짜로 검증되고, 유효하지 않으면 안전한 오류 상태 또는 기본 날짜로 복구되어야 한다. URL 문자열이 HTML로 해석되면 안 된다.
- actual: `URL_XSS_EXECUTED=true`. URL의 `checkIn`이 `<input value="${state.checkIn}">` 문자열에 직접 들어가 이벤트 핸들러가 실행됐다.
- evidence: `qa/argos-v01/url-xss-proof.png`; 독립 실행 출력 `URL_XSS_EXECUTED=true`.
- acceptance: 모든 URL 파라미터를 allowlist/형식/범위 검증하고, DOM 생성은 `textContent`, `value`, `setAttribute` 또는 안전한 노드 조립으로 전환한다. 동일 페이로드로 전역 마커가 생성되지 않는 자동 회귀 테스트를 추가한다.
- owner: hephaestus

### P1-02. localStorage 예약 레코드를 신뢰해 완료 화면과 운영 패널에서 저장형 DOM XSS가 실행된다

- category: security / stored XSS
- files/selectors: `assets/js/app.js:148-173`, `assets/js/app.js:235-284`, `complete.html:131-172`, `complete.html:195`, `#complete-root`, `.admin-drawer .panel-body`
- reproduction:
  1. `campflow73.reservations`에 `campName: '<img src=x onerror="window.__ARGOS_XSS=1">'`가 든 예약 레코드를 저장.
  2. `complete.html?code=CF-XSS-0001` 접속 또는 운영 패널 열기.
- expected: 저장 데이터가 변조되어도 문자열로만 렌더되어야 한다.
- actual: `window.__ARGOS_XSS === 1`; 저장된 HTML 이벤트가 실행됐다.
- evidence: `qa/argos-v01/stored-xss-proof.png`, `qa/argos-v01/browser-results.json:956-960`.
- acceptance: 스토리지 스키마를 검증하고 모든 예약 필드를 노드 API/이스케이프된 텍스트로 렌더한다. 완료·조회·운영 패널 세 경로에 저장형 XSS 회귀 테스트를 둔다.
- owner: hephaestus

### P1-03. 날짜·사이트·재고 무결성 검증을 우회해 잘못된 예약 금액과 요청을 만들 수 있다

- category: functional / reservation integrity
- files/selectors: `assets/js/core.js:18-21`, `assets/js/core.js:47-59`, `assets/js/core.js:76-95`, `booking.html:82-101`, `booking.html:196-203`, `booking.html:377-399`
- reproduction A — 역전 날짜:
  1. `booking.html?id=camp-areum&checkIn=2026-09-14&checkOut=2026-09-12` 접속.
  2. 주문 요약과 「옵션 선택」 클릭 결과 확인.
- actual A: `2026-09-14 ~ 2026-09-12 (1박)`, `₩68,000`으로 표시하고 2단계로 진행했다. `Math.max(1, calcNights(...))` 때문에 `nights() < 1` 검증은 도달 불가능하다.
- reproduction B — 잘못된 사이트:
  1. `booking.html?id=camp-areum&siteId=BAD&checkIn=2026-09-12&checkOut=2026-09-13` 접속.
- actual B: `TypeError: Cannot read properties of undefined (reading 'price')`가 발생한다.
- reproduction C — 재고/중복:
  1. `siteStatus`가 `sold_out`인 날짜의 사이트로 `requestSite`를 호출하거나, 기존 요청과 날짜 범위가 겹치되 체크인 날짜만 다르게 호출한다.
- actual C: `requestSite`는 재고 상태를 확인하지 않고, 중복도 `checkIn` 완전일치만 비교해 `accepted`를 반환한다.
- expected: 유효한 날짜 순서·캠프/사이트 존재·정원·전 숙박일 재고·겹치는 예약을 결제 직전 다시 검증하고 실패 시 입력 보존 오류 상태로 돌아가야 한다.
- evidence: `qa/argos-v01/browser-results.json:916-938`; 독립 순수함수 재현에서 sold-out/overlap 요청 `accepted`.
- acceptance: 공통 예약 검증 함수를 만들고 UI·결제 직전·테스트가 동일 계약을 사용한다. 역전/동일 날짜, 잘못된 ID, 정원 초과, sold-out, 부분 겹침을 모두 차단하는 테스트를 추가한다.
- owner: hephaestus

### P1-05. “실제 개인정보를 저장하지 않는다”는 카피와 실제 localStorage 저장이 모순된다

- actual evidence: CAMP FLOW는 색·Pretendard/Bai Jamjuree·border/radius·arrow-wrap·기본 reveal/countUp은 적용했다. 그러나 contact sheet에서 홈은 흰 컨테이너에 작은 3컷과 긴 빈 면이 중심이고, 검색·예약·완료는 동일한 흰 카드 문법이 반복된다. clip-path hero와 wordFlash가 없고 다크/풀블리드 리듬은 사실상 없다. 예약/완료 증거 이미지는 동일 캡처다.
- judgment: 기능형 플랫폼에서 POSCO의 wheel hijack/100vh를 버린 결정은 타당하지만, ‘재현하고 능가’ 기준으로는 시각적 위계와 장면 전환이 충분하지 않다. 현재는 POSCO FLOW ‘토큰 적용’이지 동급 재현이 아니다.
- acceptance: aphrodite가 실제 5페이지의 정확한 캡처를 POSCO 옆에 다시 놓고 표면별 기준을 재정의한다. 홈은 이미지 스케일/명암 리듬/비대칭을 강화하고, 기능 페이지는 상태별 시각 구분과 여백 밀도를 정교화한다.
