# 데모73 — POSCO FLOW 중심 디자인 적용안

## 1. design_goal

매거진을 넘기듯 캠핑장을 발견하는 감성과, 날짜·옵션·금액을 오해 없이 확인하고 결제 시뮬레이션까지 완료하는 예약 신뢰를 한 시스템에 묶는다. POSCO FLOW에서 가져오는 것은 물류 브랜드가 아니라 **정밀한 위계, 좁은 팔레트, 큰 여백, 경계선 중심 컴포넌트, 절제된 모션**이다.

핵심 판단 기준은 다음 세 가지다.

1. 첫 화면에서 사용자는 5초 안에 `어디로 / 언제 / 몇 명`을 입력할 수 있다.
2. 큐레이션을 보던 사용자는 카드마다 날짜 가능 여부·가격·지역을 비교하고 상세로 이동할 수 있다.
3. 예약 과정의 모든 카피는 실제 데모 기능과 일치한다. 실제 승인·청구가 없는 단계는 반드시 `시뮬레이션`으로 표시한다.

## 3. 디자인 시스템 토큰

### 3.1 색상

| 토큰 | 값 | 용도 | 접근성 규칙 |
|---|---:|---|---|
| `--color-primary-700` | `#025997` | 기본 CTA, 선택 상태, 링크, 포커스 링 | 흰 글자 대비 `7.30:1` — 일반 텍스트 AA 통과 |
| `--color-accent-500` | `#00A3F1` | 날짜 선택 보조, 그래프·진행 강조, 장식선 | 흰 글자 대비 `2.80:1` — **흰 텍스트 금지**. `#161D27` 사용 시 `6.06:1` |
| `--color-ink-900` | `#161D27` | 제목·본문 | 흰색 대비 `16.95:1` |
| `--color-surface-blue` | `#E8F3FE` | 검색 요약, 정보·로딩 배경 | 잉크 대비 `15.08:1`, primary 대비 `6.49:1` |
| `--color-border-300` | `#D1D2D4` | 카드·입력·구분선 | 텍스트로 사용하지 않음 |
| `--color-text-600` | `#6D6E72` | 보조 설명·메타 | 흰색 대비 `5.09:1` — 일반 텍스트 AA 통과 |
| `--color-text-400` | `#818286` | placeholder·비활성 힌트 | 흰색 대비 `3.84:1` — 18px+ 굵은 텍스트 외 본문 금지 |
| `--color-surface-100` | `#F3F3F3` | disabled·페이지 보조면 | 잉크 텍스트 사용 |
| `--color-white` | `#FFFFFF` | 기본 면 | — |
| `--color-error-700` | `#B42318` | 오류·취소·위험 동작 | 흰색 대비 `6.57:1` |
| `--color-success-700` | `#08783E` | 결제 시뮬레이션 성공·등록 완료 | 흰색 대비 `5.58:1` |
| `--color-warning-700` | `#8A5A00` | 운영자 확인 대기·마감 임박 | 흰색 대비 `5.93:1` |

`error/success/warning`은 POSCO FLOW 기본 팔레트에 없는 신규 값이다. 예약·결제·취소 상태를 색 하나에 의존하지 않고 아이콘·제목과 함께 구분하기 위해 추가하며, 장식에는 사용하지 않는다.

### 3.2 타이포그래피

폰트 로딩은 `font-display: swap`; Pretendard는 400/500/600/700 서브셋, Bai Jamjuree는 500/600/700 숫자 글리프 중심으로 제한한다.

| 역할 | Desktop | 375 mobile | weight / line-height / letter-spacing | 폰트 |
|---|---:|---:|---|---|
| Display | `clamp(56px, 5vw, 80px)` | 44px | 700 / 1.05 / `-0.03em` | Pretendard |
| Page title | 56px | 36px | 700 / 1.15 / `-0.03em` | Pretendard |
| Section title | 48px | 32px | 700 / 1.25 / `-0.02em` | Pretendard |
| Card title | 24px | 20px | 600 / 1.35 / `-0.02em` | Pretendard |
| Lead | 20px | 18px | 500 / 1.55 / `-0.02em` | Pretendard |
| Body | 16px | 16px | 400 / 1.60 / `-0.02em` | Pretendard |
| Small/meta | 14px | 14px | 400~600 / 1.50 / `-0.01em` | Pretendard |
| Price/stat large | 56px | 40px | 600 / 1.0 / `-0.03em`; `font-variant-numeric: tabular-nums` | Bai Jamjuree |
| Price/date inline | 18px | 17px | 600 / 1.3 / `-0.02em`; tabular nums | Bai Jamjuree |

국문 제목은 `word-break: keep-all; overflow-wrap: break-word`를 적용한다. 강제 줄바꿈은 홈 히어로와 에디토리얼 선언문에만 허용하며 375px에서는 콘텐츠 폭에 따라 해제한다.

### 3.3 간격·형태·선

- 기본 스페이싱: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 120, 160px`
- 콘텐츠 내부는 4/8pt 기반, 홈 섹션 사이는 120~160px로 대형 리듬을 만든다.
- 카드 radius `12px`, 큰 정보 패널 `16px`, pill `999px`, 태그 `4px`, 풀블리드 이미지 `0`.
- 카드 그림자 `none`. 팝오버·모달에만 `0 8px 22px rgba(0,0,0,.16)` 허용.
- 기본 border `1px solid #D1D2D4`; 표 시작선 `2px solid #161D27`.
- 포커스는 레이아웃을 밀지 않도록 `outline: 2px solid #025997; outline-offset: 2px`.

### 3.4 레이아웃 토큰

| 항목 | Desktop ≥1025 | Tablet 768~1024 | 375 mobile |
|---|---|---|---|
| 본문 max-width | 1280px | 100% | 100% |
| 본문 gutter | 64px | 32px | 20px |
| 헤더 높이 | 80px | 72px | 68px |
| 표준 섹션 padding-block | 120~160px | 96px | 72px |
| 기능 페이지 padding-top | 64px | 48px | 32px |
| 검색 결과 grid | 3열, gap 24px | 2열, gap 20px | 1열, gap 20px |
| 상세 메인 | 콘텐츠 `minmax(0,1fr)` + 예약 패널 380px | 단일 열 | 단일 열 + 하단 sticky CTA |
| 예약 폼 | 폼 `minmax(0,1fr)` + 요약 360px | 단일 열 | 단일 열 |
| 관리자 | 240px 좌측 내비 + 콘텐츠 | 72px 축약 내비 | 상단 탭 + 단일 열 |

데스크톱의 유동 값은 단순 `clamp()`로 제한한다. POSCO FLOW의 1920 기준 `100cqw` 전면 스케일은 구현 비용과 작은 데스크톱 가독성 편차가 커서 사용하지 않는다.

## 4. 공통 레이아웃

### 4.1 헤더

- 좌: 서비스 워드마크(가칭 `CAMP FLOW`, POSCO 로고 형태 복제 금지).
- 중앙: `캠핑장 찾기 / 큐레이션 / 예약조회 / 이용안내`.
- 우: primary pill `날짜로 찾기`.
- 현재 페이지는 `aria-current="page"` + 3px primary 하단선.
- 아래로 스크롤하면 숨고 위로 스크롤하면 나타나는 비대칭 전환: 등장 `.4s cubic-bezier(.16,1,.3,1)`, 퇴장 `.3s cubic-bezier(.4,0,1,1)`.
- 375px: 로고 + `예약조회` 텍스트 링크 + 48×48 햄버거. 드로어는 초점 가두기, Escape 닫기, 닫힌 뒤 트리거로 초점 복귀.

### 4.2 푸터

- 2행: 이용약관·개인정보처리방침·문의 / 사업·데모 고지.
- 명시 카피: `이 화면은 캠핑장 예약 MVP의 기능 검증용 데모입니다. 결제는 실제 청구되지 않습니다.`
- 플로팅 top 버튼은 48×48, 푸터와 겹치지 않게 정적 영역으로 이동. 별도 퀵메뉴는 두지 않는다.

## 5. 컴포넌트 명세

### 5.1 버튼

| 변형 | 기본 | hover | focus-visible | active | disabled | loading |
|---|---|---|---|---|---|---|
| Primary | `#025997` 배경, 흰 글자 | `#014A7E`, arrow-wrap | 2px outline | `translateY(1px)` | `#F3F3F3/#BCBDC1` | 라벨 유지 + 16px spinner, `aria-busy=true` |
| Secondary | 흰 배경, 1px border, 잉크 | `#E8F3FE`, primary border | 동일 | 연블루 면 | 동일 | 동일 |
| Ghost | 투명, primary 텍스트 | 연블루 면 | 동일 | primary 8% 면 | opacity가 아닌 disabled 색 | 동일 |
| Destructive | 흰 배경, error border/text | error 8% 면 | error outline | error 12% 면 | 동일 | 동일 |

- 높이: desktop 52px, mobile 52px; compact 44px. 최소 너비 120px, padding-inline 20~24px, radius pill.
- 아이콘은 20px 선형(stroke 1.75px, round cap). 의미 없는 아이콘 단독 버튼 금지; 단독이면 `aria-label` 필수.
- 화살표 컨테이너는 `overflow:hidden`; hover 가능 기기에서만 `.5s cubic-bezier(.25,.46,.45,.94)` wrap.

### 5.2 검색·필터·날짜

- 통합 검색바: 데스크톱 4칸 `지역 / 체크인·체크아웃 / 인원 / 검색`, 높이 64px, 1px border, pill 외곽.
- 375px: 카드형 세로 조합. 각 행 56px, 마지막 검색 버튼 full-width. 하나의 거대한 pill 안에 작은 텍스트를 구겨 넣지 않는다.
- 입력 기본/hover/focus/filled/error/disabled 상태를 모두 제공.
- 오류는 2px 빨간 border로 바꾸지 않고 1px 유지 + 1px error outline. 하단 14px 오류문과 오류 아이콘을 함께 제공.
- 날짜 선택: `dialog` 기반 2개월(데스크톱), 1개월(모바일). 오늘, 선택 시작, 범위, 예약 불가, 포커스, 과거 날짜를 시각·텍스트로 구분.
- 필터 chip: 높이 40px, 기본 흰색/1px border; 선택 `#E8F3FE` + primary border + check; 해제 버튼은 44px 터치 영역.
- 적용된 필터 수는 Bai Jamjuree 숫자 badge로 표시. `필터 3개 적용됨`을 라이브 영역에 알린다.

### 5.3 캠핑장 카드

구성 순서: 이미지(4:3) → 지역·유형 → 캠핑장명(최대 2행) → 편의 태그 최대 3개 → 선택 날짜 가능 상태 → 1박 가격 + arrow.

- desktop: 이미지 100%×240px; mobile: 100%×220px.
- 카드 전체 링크 내부에 중첩 버튼을 넣지 않는다. 찜 기능은 MVP에서 제외.
- hover: border primary, 이미지 `scale(1.03)` `.5s`, arrow-wrap. 카드 전체 색 반전은 하지 않는다.
- 상태: `예약 가능` primary, `확인 필요` warning, `마감` text-600. 색+아이콘+텍스트를 함께 사용.
- 가격은 `₩68,000 / 1박`, 세금·추가비용 안내는 상세에서 명시.
- 로딩은 이미지와 4줄 skeleton. empty/error를 카드처럼 위장하지 않고 목록 전체 상태로 표시.

### 5.4 상세·예약 요약 카드

- desktop에서 380px sticky, `top: 104px`; 그림자 없이 1px border.
- 날짜, 인원, 사이트 타입, 부가 옵션, 합계의 행 구조. 금액 변경 시 70%→100% countUp 1s linear를 1회만 실행하고 숫자 폭을 고정한다.
- 합계 아래 `데모 결제 · 실제 청구 없음` 고지.
- 운영자 확인이 필요한 경우 CTA 위에 `예약 요청 후 담당자가 캠핑장에 확인합니다`를 항상 노출.
- 375px에서는 본문 아래 요약 + 하단 sticky `총액 / 예약 계속` bar. safe-area 포함 `padding-bottom: max(12px, env(safe-area-inset-bottom))`.

### 5.5 단계 표시기

`1 날짜·인원 → 2 옵션 → 3 예약자 정보 → 4 결제 시뮬레이션`.

- 현재 단계는 숫자 원 + `aria-current="step"`; 완료는 check, 미완료는 회색.
- mobile은 `2 / 4 옵션 선택` 한 줄과 얇은 진행바로 축약하되 단계명을 숨기지 않는다.
- 브라우저 뒤로 가기 시 입력값 유지. 단계 이동 시 `h1`으로 초점 이동.

### 5.6 피드백·상태 컴포넌트

| 상태 | 시각 | 필수 카피 | 다음 행동 |
|---|---|---|---|
| Loading | 연블루 트랙 + primary spinner 또는 skeleton | `예약 가능 날짜를 확인하고 있어요.` | 중복 제출 방지, 10초 후 지연 안내 |
| Empty | 장식 일러스트 없이 제목+설명 | `선택한 날짜에 예약 가능한 캠핑장이 없어요.` | `날짜 바꾸기`, `조건 초기화` |
| Error | error 아이콘·제목·원인 | `예약 가능 여부를 불러오지 못했어요.` | `다시 시도`, 입력 보존 |
| Success | success 아이콘·예약번호 | `결제 시뮬레이션이 완료됐어요.` | `예약 확인 보기`, `홈으로` |
| Pending | warning 아이콘 | `담당자가 캠핑장에 예약 가능 여부를 확인 중이에요.` | 예상 절차와 연락 방법 확인 |
| Cancel | error가 아닌 중립 면 + 취소 아이콘 | `예약 요청이 취소됐어요. 실제 결제는 발생하지 않았습니다.` | `다른 캠핑장 찾기` |

Toast는 보조 확인에만 사용하고 결제·취소 결과는 독립 페이지/대화상자로 제공한다. Toast는 `role=status`, 오류는 `role=alert`.

### 5.7 관리자 최소 컴포넌트

- KPI 3개: 오늘 요청 / 확인 대기 / 등록 캠핑장. 숫자는 70% countUp.
- 예약 표: 접수시각, 고객, 캠핑장, 날짜, 금액, 상태, `상세`.
- 상태 변경: `접수 → 캠핑장 확인 중 → 확정 / 예약 불가 / 취소`. 변경 전 최종 카피와 고객에게 보이는 결과를 확인.
- 캠핑장 폼: 이름, 지역, 주소, 소개, 기본가, 사이트 수, 편의시설, 부가 옵션, 대표 이미지, 노출 상태.
- 업체 로그인·업체 포털은 만들지 않는다. 관리자 한 명이 직접 등록/수정한다는 공고 범위를 따른다.

## 7. 모션 명세

### 7.1 허용 모션

| 이름 | 트리거 | 값 | 적용 |
|---|---|---|---|
| Header reveal | 섹션 top이 viewport 70% | `opacity 0→1`, `translateY(40px→0)`, `.8s cubic-bezier(.22,1,.36,1)` | 홈 섹션 제목 |
| Card reveal | viewport 70% | `opacity 0→1`, `translateY(30px→0)`, `.6s`, stagger `.15s` | 홈 큐레이션 첫 6장만 |
| Arrow wrap | hover | `.5s cubic-bezier(.25,.46,.45,.94)`, `x 0→120%→-120%→0` | 링크·카드 화살표 |
| CountUp | 70% 가시 또는 합계 변경 | 목표의 70%→100%, 1s linear, 폭 잠금 | 홈 통계 1회, 예약 합계, 관리자 KPI |
| Image hover | hover | `scale(1→1.03)`, `.5s` | 캠핑 카드 |
| Dialog | 열기/닫기 | opacity `.2s`; panel `y 12→0`, `.25s` | 날짜·필터·취소 확인 |
| Button press | pointer down | `translateY(1px)`, `.1s` | 버튼 |

IntersectionObserver는 요소별 1회 실행 후 해제한다. transform/opacity만 기본으로 사용하고 스크롤 이벤트는 passive + rAF throttle을 적용한다.

### 7.2 금지 모션

- wheel/touch `preventDefault` 기반 스크롤 하이재킹
- 200~350vh sticky scrub, 100vh snap 강제, 가로 스크롤 강제
- GSAP·Lenis·SplitText·Lottie 도입
- 자동재생 캐러셀·배경 영상·7개 영상 프리로드
- 입력·결제 화면의 등장 리빌, 가격 숫자의 반복 카운트업
- `transition: all`

### 7.3 reduced motion

`prefers-reduced-motion: reduce`에서는 모든 reveal을 최종 상태로 즉시 표시하고, arrow-wrap·countUp·image scale·spinner 외 장식 애니메이션을 제거한다. 로딩은 정적 진행 아이콘 + 텍스트를 유지한다. 네이티브 스크롤은 모든 뷰포트의 기본이다.

## 8. 이미지 디렉션

### 8.1 톤

- 색온도: 청록·파랑이 감도는 이른 아침/흐린 날 자연광. 과한 주황 노을과 카키 필터 금지.
- 피사체: 호숫가 텐트 부감, 숲길을 낮게 본 시점, 타프·버너·로프 초근접, 사람은 얼굴보다 손·준비 장면.
- 크롭: 주 피사체를 1/3선에 두고 UI 텍스트를 놓을 35~45% 음영 여백 확보.
- 인물 다양성을 유지하되 안전장비·불 사용 등 위험한 장면은 피한다.
- UI 위 텍스트가 있는 사진은 스크림을 적용해 대비 4.5:1 이상 확보.

### 8.2 페이지별 수량·비율

| 용도 | 수량 | 비율 | 처리 |
|---|---:|---:|---|
| 홈 히어로 콜라주 | 4장 | 4:5 1장 + 4:3 2장 + 16:9 1장 | 12px radius, 비대칭, 쿨톤 통일 |
| 홈 큐레이션 | 6장 | 4:3 | 카드별 서로 다른 자연 환경, lazy |
| 테마 풀블리드 | 1장 | 21:9 desktop / 4:5 mobile art-direction | 텍스트 영역 스크림 |
| 검색 카드 | 캠핑장당 1장 | 4:3 | 동일 크롭 기준 |
| 상세 갤러리 | 캠핑장당 5장 | 16:10 대표 + 4:3 보조 | desktop 2×2 비대칭, mobile swipe |
| empty/error | 0장 | — | 사진으로 실패 상태를 미화하지 않음 |

WebP/AVIF 우선, 대표 이미지는 1600px, 카드 이미지는 800px 파생본. LCP 1장만 eager, 나머지는 `loading=lazy`; 너비·높이를 명시해 CLS를 막는다.

## 9. UX 카피 원칙

- 감성 카피는 발견 화면에만: `물가 가까운 자리, 아침 안개까지 예약하세요.`
- 기능 카피는 구체적으로: `9월 12일–13일 · 성인 2명 · 예약 가능`.
- 데모 고지는 숨기지 않는다: `결제 시뮬레이션이며 실제 금액은 청구되지 않습니다.`
- 확정 전에는 `예약 완료` 대신 `예약 요청 접수`를 쓴다.
- 담당자 확인 구조를 그대로 알린다: `담당자가 캠핑장에 확인한 뒤 확정 상태를 알려드려요.`
- 가짜 실시간성을 금지한다. 실제 API가 없으면 `실시간 잔여 2자리` 같은 문구를 쓰지 않는다.

## 10. accessibility

- WCAG 2.2 AA 목표. 본문/컨트롤 텍스트 4.5:1, 큰 텍스트 3:1, UI 경계·포커스 3:1 이상.
- cyan 위 흰 글자 금지; cyan은 잉크 텍스트 또는 비텍스트 강조에만 사용.
- 키보드 순서는 DOM 순서와 시각 순서를 일치시킨다. 비대칭 홈 콜라주는 장식이면 빈 alt.
- 모든 터치 타겟 최소 44×44px; mobile 주요 버튼은 52px.
- 날짜 범위는 색뿐 아니라 `시작일/종료일/선택됨/예약 불가` 접근성 이름 제공.
- 폼 label을 placeholder로 대체하지 않는다. 오류 요약은 첫 오류로 연결되고 제출 후 초점을 이동한다.
- 결과 수, 필터 적용, 금액 변경은 과도하지 않은 `aria-live=polite`; 결제 실패만 `assertive`.
- 모달 초점 가두기·Escape 닫기·초점 복귀. 파괴적 취소는 확인 dialog.
- `aria-current`를 내비·단계에 사용. 상태 badge는 색 외에 텍스트와 아이콘 포함.
- 200% 확대에서 가로 스크롤 없이 주요 기능을 완료할 수 있어야 한다.

## 12. handoff / QA 기준

### 구현 인계

- `hephaestus`: 본 문서의 수치를 CSS custom properties로 정의하고 공통 컴포넌트 상태를 먼저 구현한다. 구현 난이도·라이브러리 선택은 개발 담당이 확정한다.
- `argos`: 1440×900, 1024×768, 375×812에서 레이아웃·키보드·터치·reduced-motion·상태 카피를 실측한다.

### 완료 체크

- [ ] primary/cyan 사용이 대비 규칙을 지킨다.
- [ ] Pretendard/Bai Jamjuree 역할이 섞이지 않는다.
- [ ] 카드 그림자 0, border 1px, radius 12px, 버튼/입력 pill이 일관된다.
- [ ] 기본/hover/focus/active/disabled/loading/empty/error/success/cancel 상태가 구현된다.
- [ ] `100vh`, wheel hijack, pin, GSAP, autoplay video가 없다.
- [ ] 375px에서 모든 터치 타겟이 44px 이상이며 하단 CTA가 safe-area를 침범하지 않는다.
- [ ] 결제·예약 카피가 실제 시뮬레이션과 담당자 확인 흐름을 정확히 설명한다.
- [ ] reduced-motion에서 콘텐츠가 숨은 채 남지 않는다.

## 13. needs_confirmation

1. 서비스명 `CAMP FLOW`는 문서용 가칭이다. 의뢰자 승인 전 로고·브랜드 자산으로 확정하지 않는다.

3. 사용자 계정 기능은 공고에 없으므로 예약번호+연락처 기반 `예약조회`를 제안한다. 개인정보 정책과 조회 인증 방식은 기획 담당 확인이 필요하다.
