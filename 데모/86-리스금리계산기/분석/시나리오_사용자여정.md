# 시나리오 · 사용자 여정 — 리스승계연구소 금리 계산기

> 리서치 에이전트(Opus) 초안(`_리서치_초안.md` 1~3·6장)을 바탕으로, 데모에서 실제로 눌러 볼 수 있는 순서와 기능별 존재 이유를 더해 정리했다. 모든 인물·번호는 가상이다.

## 1. 등장인물

| 인물 | 누구인가 | 원하는 것 | 불안해하는 것 | 겸하는 역할 / 비고 |
|---|---|---|---|---|
| **A. 리스 이용 고객** (개인·개인사업자·법인 담당자) | 유튜브 「리스승계연구소」 시청자. 리스 중이고, 견적서에 금리가 안 적혀 있어 궁금한 사람 | 내 계약의 진짜 금리, 손해 여부, 중도에 정리하면 얼마가 남는지 | 「내가 바가지를 썼나」, 위약금 폭탄, 정보만 남기면 영업 전화가 올까 | **동시에 B(승계 양도 희망자)가 될 수 있다.** 계산 결과가 나쁘면 바로 「승계 상담 신청」으로 넘어간다. 시안이 노리는 퍼널이 이것이다 |
| **B. 장기렌트 이용 고객** | 렌터카(하·허·호 번호판) 장기 이용자 | A와 같지만 「금리」라는 개념이 모호하다. 렌트료에 보험·세금이 포함돼 있다 | 렌트사 중도해지 위약금(잔여 렌트료의 일정 비율) | 시안 승계 리포트 예시(K8 · 229호2025)가 장기렌트 건이다 |
| **C. 메인 관리자** | 운영 대표(유튜버 본인 또는 상담 실장으로 추정). 시안 오류 화면에 개인 휴대폰 번호가 노출돼 있어 **1인 운영 가능성이 높다** (확인 필요) | 리드 한 곳 집중 · 승계 견적을 빨리 뽑기 · 고객에게 보낼 리포트 | 서브관리자가 고객을 빼돌리는 것, 개인정보 사고, 계산식(감가율·손익 산식) 유출 | 고객 DB 전권 · 엑셀 · 삭제 · 서브관리자 계정 발급 |
| **D. 서브 관리자** | 시안에 「서브관리자 등록」 탭이 있다. **외부 딜러·제휴 영업자**인지 **내부 상담 직원**인지에 따라 법적 성격이 갈린다 (확인 필요) | 자기가 데려온 고객 등록·상담 계산·리포트 발급 | 자기 고객을 메인이나 다른 서브가 가져가는 것, 수수료 정산 | 외부 업체라면 고객정보를 넘기는 행위가 **제3자 제공 또는 처리위탁**에 해당한다(F8) |
| **E. 승계 인수 희망자** (간접) | 승계 매물을 받는 사람. 이 시스템의 사용자는 아니지만 리포트의 「지원금/인수금」은 이 사람과의 거래 조건이다 | 싼 월납입·적은 초기비용 | 숨은 초과주행, 보증금 정산, 리스사 심사 탈락 | 다른 매물에서는 A가 될 수도 있다 |
| **F. 리스사·렌트사** (간접, 승인권자) | 승계를 심사·승인하는 금융사·렌터카사 | 신용 심사 통과자에게만 명의 이전 | 연체 계약의 승계 | 「계약 조건 변경 불가 · 만기 5주 전까지 심사 완료」 같은 규칙을 정한다 ([우리카드 승계 안내](https://nm.wooricard.com/dcmw/yh1/car/car04/M1CAR204S10.do)) |
| **G. 공유 링크 수신자** | 고객이 「링크 복사」로 보고서를 보낸 가족·배우자·지인. 또는 관리자가 보낸 리포트 링크를 받은 고객 본인 | 보고서 열람 | — | **로그인 없이 개인정보를 보는 사람.** 링크 자체가 열람 권한이다(F12) |

> 한 사람이 두 역할을 겸하는 지점은 세 곳이다. ① A·B 고객이 그대로 승계 양도 희망자가 된다. ② 메인 관리자가 상담원 역할도 한다. ③ 서브 관리자가 외부 영업자라면 「관리자」이면서 동시에 「제3자」다.

## 2. 전체 타임라인 (발견 → 판단 → 행동 → 대기 → 실행 → 사후)

| 단계 | 상황 | 쓰는 화면 (시안 쪽수) | 이 기능이 없으면 벌어지는 일 | 시안에서 비어 있는 것 |
|---|---|---|---|---|
| **발견** | 유튜브 영상 「리스 금리 직접 계산해 보세요」의 설명란 링크를 눌러 들어온다 | 스플래시 「LEASE TRANSFER LAB · 건너뛰기」(p.1) | 영상별 유입 성과를 모르면 어떤 콘텐츠가 리드를 만드는지 측정할 수 없다 | 유입 경로(UTM·영상 ID) 저장 칸이 없다 → 관리자 목록에 「유입」 열 제안 |
| **판단** | 계산하기 전에 차량번호·성함·전화를 내라고 한다. 망설인다 | 고객 정보 입력 + 「개인정보 제공에 동의합니다(필수)」(p.2~5) | 이 게이트가 곧 리드 DB다. 하지만 동의 설계가 틀리면 DB 전체를 영업에 쓸 수 없다(F8) | 수집 목적 고지 4항목, 광고 수신 선택 동의, 번호판 정규화(F13) |
| **행동 ①** | 계약서를 보며 취득원가·선납금·보증금·잔존가치·기간·월 리스료·시작일을 넣는다 | 계산기 리스/장기렌트 탭(p.6~9) | 서버 계산이 느리면 입력할 때마다 화면이 깜빡이고, 옛 응답이 새 결과를 덮어쓴다(F15) | 계약 유형(운용/금융 리스) 입력, 1회차 납입 시점 선택(F2), 렌트료 포함 서비스 비용(F3) |
| **행동 ②** | 결과를 본다. 「연 8.13%… 생각보다 괜찮네?」 | 결과·상환표·원금/이자 그래프(p.15) | **보증금을 넣어도 금리가 그대로라는 사실을 모른다.** 실제 부담은 13%대인데 「괜찮다」고 판단한다(F1) | 보증금 반영 여부 표시, 명목/실효 연이율 구분 |
| **행동 ③** | 보고서를 PDF로 저장하거나 배우자에게 링크를 보낸다 | 금리 분석 보고서 A4 3장·확대축소·인쇄·링크 복사(p.11~12) | iPhone에서 인쇄하면 A4 3장 레이아웃이 깨진다(F16). 링크가 영구라면 실명 보고서가 영영 열린다(F12) | 링크 만료·폐기, 실명/마스킹 정책 |
| **행동 ④** | 「승계 상담 신청」을 누른다 | 계산기 하단 CTA(p.6·9·19) | 계산만 하고 떠난 고객과 상담 신청 고객이 섞이면 상담 우선순위가 무너진다 | 상담 희망 시간대, 연락 수단 선택, 중복 신청 처리 |
| **대기** | 고객은 연락을 기다리고, 관리자는 「상담 미확인」 카운트를 본다 | 관리자 고객 DB(탭·미확인/확인·최신순/진행상태순)(p.10) | 같은 사람이 두 번 신청하면 두 줄이 생겨 서로 다른 상담원이 전화한다 | 중복 병합 규칙, 신규 접수 알림, 담당자 배정 |
| **실행 ①** | 관리자가 시세·정산서를 넣고 처리 방법별 손익을 뽑는다 | 승계 상담 계산(공고 2-2) | 금융리스에는 「반납」이 없다. 계약 유형을 모르는 계산기는 불가능한 선택지를 「추천」할 수 있다(F4) | 계약 유형별 선택지, 수수료 기준금액(F5), 일할 초과주행(F7) |
| **실행 ②** | 리포트 금액을 손봐 고객에게 링크를 보낸다 | 승계 리포트(p.13): 즉시 판매(추천)·차량 반납·일반 승계, 미래 승계시점 예상 가격 그래프 | 수정 이력이 없으면 나중에 「그때 200만원 준다고 했잖아요」 분쟁 때 근거가 없다 | 원 계산값 대비 수정값·수정자 이력, 리포트 버전 |
| **실행 ③** | 고객이 링크를 열어 보고, 30일 뒤 재견적을 신청한다 | 승계 리포트 · 재견적(30일 1회) | 재견적 기준일이 모호하면 고객과 관리자가 보는 「다음 신청 가능일」이 서로 다르다 | 30일 기산점 정의 |
| **사후** | 진행상태가 서류요청 → 상담완료 → (승계 성사/무산)으로 바뀐다. 고객이 삭제를 요청한다 | 진행상태·메모·삭제(기록 남김) | 삭제했는데 「삭제 기록」에 이름·전화가 남으면 파기가 아니다(F18) | 「취소/무산」 상태, 보유기간 만료 자동 파기, 삭제 사유 |

## 3. 역할별 시나리오 (데모에서 그대로 눌러 볼 수 있는 순서)

### A. 리스 이용 고객 — 「내 계약이 정말 괜찮은 걸까」
1. 유튜브 설명란 링크 → `index.html` 인트로(1.9초, 건너뛰기) → 배너 「지금 바로 확인하기」 → 차량번호 `207저7707` · 성함 · 전화 · 수집·이용 동의(필수)
2. `calc.html` — 취득원가 8,000만 · 보증금 2,400만(30% 칩 자동 표시) · 잔존가치 4,000만 · 48개월 칩 · 월 125만 → 0.45초 뒤 서버 계산
3. 결과 「연 **13.11%**」 + 「보증금을 빼지 않고 계산하면 연 8.13%로 낮게 보여요 — 왜 다른가요?」 → 두 방식 비교 시트
4. 「금리 분석 보고서 보기」 → A4 3장 · 확대 · 인쇄/PDF · 「링크 복사」(30일)
5. 배우자에게 링크 전송 → 배우자 화면은 「강\*서 귀하 · 207저77\*\*」 + 「전화번호 뒤 4자리로 확인」 → 전체 표시
6. 결과가 나쁘면 하단 「승계 상담 신청」 → 희망 처리 「잘 모르겠어요」 · 연락 「저녁」 → 접수 완료(관리자 목록 맨 위 · 「신규」 · 미확인 KPI +1)

### B. 장기렌트 이용 고객 — 「렌트에도 금리가 있나」
1. 차량번호 `229호2025` 입력 → 「‘호’ 번호는 렌터카(대여사업용)예요 · 장기렌트로 계산해요」 → 계산기가 장기렌트 탭으로 열림
2. 월 렌트료 649,660원 그대로 넣으면 연 8.88% → 「렌트료에 포함된 비용 · 예상값 넣기」(보험·세금·정비 서버 추정) → 연 **4.84%** + 「렌트료 전체로 역산하면 8.88%로 보이지만…」

### C. 메인 관리자 — 「들어온 문의를 하나도 흘리지 않기」
1. `admin/index.html` → ID·PW → OTP 6자리(외부 접속 추가 인증) → 고객 DB · KPI 「상담 미확인」
2. 「승계상담 신청」 탭 → 미확인 행의 「미확인」 → 「✓ 확인」 · 검색 `2929`(전화 뒤 4자리 블라인드 인덱스)
3. 행 클릭 → `admin/consult.html` — 계약 유형 「운용리스」 · 시세 4,680만 · 정산서 잔여 원금 4,412만 · 중도해지 15% → 처리 방법별 손익(즉시 판매 추천) · 수수료율 2.5% 입력 → 금액 1,490,000원 자동 · 금융리스로 바꾸면 「차량 반납」 비활성
4. 고객 제공 리포트 — 즉시 판매 금액을 −150만으로 수정(원값 보존) → 「고객 링크 발급(30일)」 → 링크 목록에 열람 수 표시 → 필요 시 「폐기」
5. 월말 — 엑셀 다운로드(사유 「통계·현황 보고」 · 전화 마스킹) → 접속기록 「점검 완료로 기록」

### D. 서브 관리자(딜러) — 「내 고객만」
1. `dealer01`로 로그인 → 본인 담당·등록 고객 7명만 · 이름 「문\*아」 · 전화 「010-\*\*\*\*-8172 보기」(누르면 열람 기록)
2. 「승계 상담 추가」로 전화 접수 고객 등록(구두 동의 체크) → 「서브관리자 등록」 탭
3. 남의 고객 URL 직접 접근 → 「이 고객을 볼 권한이 없어요」 · 관리자 관리·접속기록 → 403

### G. 공유 링크 수신자
- 만료(30일 경과)·폐기·잘못된 주소 → 시안 11쪽 「링크를 찾을 수 없어요」(존재 여부를 노출하지 않음) + 「내 금리 직접 계산해 보기」
