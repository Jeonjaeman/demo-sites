## 1. 명시된 니즈 / 숨은 니즈

### 명시된 니즈 (공고 원문 기준)
- 교사 전용 가입 + **고유번호증 업로드** + 관리자 **승인/반려** + 승인 시 **문자**
- 교구 수량·인원 기반 **복합 계산 폼** → 강사비·총액 **즉시 계산**
- **견적서 자동 발행 + PDF 생성**(직인·문서번호·발행일시) + 이메일 발송
- **견적서 재발행**(수정 요청, 2·3차) + **회차 전량 보존**(덮어쓰지 않음)
- **주문·예약**(명단 파일·배송 주소) → 진행·배송 완료 → **청구·결제 체크**
- 관리자: 회원 관리(정보 수정·서류 재업로드·삭제), 발급 내역(수동 재발송), **단가 기준 관리**
- 반응형(휴대폰에서 가입~견적 발행 완료), 업로드 파일 비공개 저장

### 숨은 니즈 (시나리오에서 도출)
| 단서 | 숨은 니즈 |
|---|---|
| "담당자가 매번 손으로 견적서를 만든다" | 사람이 아니라 **규칙(단가표·인원 구간)**이 계산해야 재현·일관성 확보 |
| "이력이 남지 않아 재발급도 수작업" | 회차를 **덮어쓰지 않고 append** → 감사·분쟁 시 근거 |
| "주문부터 청구·결제까지 한 곳에서" | 흩어진 엑셀·문자·메일을 **단일 상태 테이블**로 → 미수금 한눈에 |
| 지원사업 예산·마감 고정 | **일정 준수**가 계약 핵심 → 범위 우선순위가 곧 성패 |

## 2. 웹 리서치 — 치명적 발견 (그대로 만들면 실패하는 지점)

> 우선순위: `그대로 만들면 작동하지 않음` > `법 위반 소지` > `운영 중 반드시 터짐` > `있으면 좋음`

### ① 인원 구간별 강사비 = 절대/상대 기준 혼용 시 "역전" 발생 ★
"15명당 강사 1인"을 단순 비례로 짜면 **경계값(15/16, 30/31)에서 1명 차이로 강사비가 계단식 급증**한다. 16명이 15명보다 강사비 2배가 되는 구간 함정. → 데모는 **구간(tier) 테이블을 명시**(1~15/16~30/31~45/46~60)하고, **61명 이상은 자동 계산을 막고 "별도 협의"로 분기**해 잘못된 견적 발행을 원천 차단.
- 근거: 출강·강사 파견 견적의 통상 구조(구간 정액제). 비례식으로 짜면 소규모 학급에서 단가 왜곡.

### ② 견적서 회차 보존을 "덮어쓰기"로 구현하면 분쟁에서 진다 ★
"수정 요청 → 재발행"을 같은 레코드 update로 처리하면 1차 견적 근거가 사라진다. 지원사업·세금계산서 대상 거래에서 **발행 이력은 증빙**이다. → 데모는 `견적번호 + 회차(rev)` 구조로 **1·2·3차를 각각 별도 문서로 append**, 이전 회차는 상태만 `재발행`으로 바뀌고 **PDF·금액이 그대로 남는다**.

### ③ 한글 PDF는 클라이언트 라이브러리 기본 폰트로 안 나온다 ★
jsPDF 기본 폰트(Helvetica)는 한글이 **깨지거나 공백**으로 출력된다. 서버사이드도 동일(폰트 미탑재 시). → 데모는 **DOM을 html2canvas로 래스터화 → jsPDF에 이미지로 삽입**해 Pretendard 한글·직인 SVG를 **깨짐 없이** 출력(실제 구축은 서버 Puppeteer/wkhtmltopdf로 동일 원리). 검증: 794px 견적서 → A4 1페이지(210×191mm) 생성 확인.

### ④ 고유번호증 = 개인정보/기관정보 → "공개 저장"하면 위반
업로드 서류를 정적 경로에 그대로 두면 URL만 알면 열린다. → 비공개 저장·접근 제어를 **원칙으로 명시**(데모는 파일 자체를 저장하지 않고 파일명·메타만 다룸).

### ⑤ 결제(PG)는 이번 범위 밖 — "청구·결제 여부 기록"까지
공고 스코프: 온라인 결제 연동 제외, **수납은 오프라인**. → 데모는 결제를 **PG 위젯이 아니라 상태 기록**(청구 방법·일자 / 결제 완료일)으로 구현. 과범위·과금 오해 방지.

## 3. 레퍼런스 실측

### ① 도메인 레퍼런스 (무엇을 만들까 — 3곳)
| 소스 | 가져온 것 |
|---|---|
| **Toss 비즈(사업자 대시보드)** | 미수금/청구/결제를 상단 KPI로 요약하는 정보 위계, 상태 뱃지 색 규약(대기 amber·완료 green·정보 blue) |
| **Stripe Invoicing** | 문서(견적서) 상단 발행처/수신처 2단 배치, 합계 우측 정렬 테이블, 문서번호·유효기간 노출 문법 |
| **정부지원 교구 발주(에듀넷·나라장터 발주서)** | 품목·수량·단가·공급가·부가세 분리 표기, 직인 위치, "인" 표기 관행 |

### ② 디자인 레퍼런스 (어떻게 보이게 할까 — 갤러리/패턴)
| 소스·유형 | 가져온 것 |
|---|---|
| **Linear (갤러리 · 백오피스 패턴)** | 데이터 밀도 높은 표 헤더 대비(12px·muted·surface2 배경), 좌측 정렬 세그먼트 필터, sticky 요약 패널 |
| **WWiT · 패턴(폼/승인/빈 상태)** | 파일 업로드 filebox(점선→실선 has 상태), 승인 대기 화면, 빈 상태 2줄 처리 |
| 인터랙션(이식값) | 카운트업(easeOutCubic 620ms), 바 성장(700ms), 카드 hover translateY(-1px .15s), 토스트 슬라이드업 cubic-bezier(.22,.61,.36,1) |

> 수상작 실측을 라이브로 강제하지 못한 항목은 **패턴/갤러리 참고로 정직하게 표기**했습니다(근거 없는 "수상" 표기 지양). 색·타이포·이징 수치는 코드 상단 주석에 출처를 남겼습니다.
> **폰트**: 유료·커스텀 폰트는 메트릭만 이식 대상 — 본 데모는 Pretendard(오픈)로 통일.

### 4축 산출물
- **디자인 시스템**: 그린 단일 액센트(#1f8a4c) + 뉴트럴, 8px 스페이싱, radius 10~14, 상태 5색 토큰
- **UI/UX**: 좌 계산폼 + 우 sticky 요약 / 관리자 좌 KPI·차트 + 표, 빈 상태·에러 문구, 모바일 단일 컬럼 전환
- **인터랙션**: 카운트업·바 성장·리빌(IntersectionObserver stagger)·토스트·모달
- **그래픽 소스**: 직인 SVG(라운드 2중 원, serif), 이모지 아이콘(선 굵기 통일), canvas 도넛/바(dpr 대응)

## 6. 제안 스택 & 견적

### 제안 스택 (실제 구축 기준)
- 프론트: React/Next.js (SSR로 SEO·문서 안정성) — 데모는 무의존 바닐라 JS로 동일 UX 구현
- 백엔드: Node(NestJS) 또는 Django, PostgreSQL — 회원·견적 회차·주문 상태
- **PDF: 서버 Puppeteer(headless Chrome)로 HTML→PDF**(데모의 html2canvas+jsPDF와 동일 원리, 직인은 서버 합성)
- 연동: 알림톡/문자(발신번호 사전 등록), 메일(도메인 인증·발송 로그·재시도), 네이버 로그인
- 인프라: 관리형 호스팅 + 파일 비공개 스토리지(서명 URL)

**★ 예산 판단 근거 (지원사업 고정 예산 처리)**
공고 예산 1,200만원은 지원사업 배정액으로 **고정·증액 불가**이며, "이 안에서 무엇을 먼저 만들지 우선순위"를 요구합니다.
- 공수 산정 결과 **전 범위(B2B 전체 + 홈페이지 개편 + 연동 + 안정화)가 예산 안에 충분히 들어옵니다.** 따라서 **범위를 축소할 필요가 없다는 점**이 이 제안의 핵심 우선순위 답변입니다. (경쟁 제안은 예산에 맞춰 범위를 깎는 방향으로 갑니다.)
- 저장소 원칙에 따라 **공수 기준 금액(공수표)**을 그대로 제시하며, **절감률/예산 대비 문구는 쓰지 않습니다.**
- 지원사업 예산 집행 특성상 잔여분은 **범위 억지 확장이 아니라** ①테스트 2주·11/20 결함 대응 ②오픈 후 초기 안정화·유지보수 ③2차(네이버 예약 실연동·상품 등록, 콘텐츠 이관) **협의 집행**으로 처리 제안.

### 착수 순서(우선순위) — 10/14 완료 기준 주차별
1주차: 데이터 설계 + 회원/승인 → 2주차: 견적 엔진 + PDF + 회차 → 3주차: 주문/청구/결제 + 관리자 → 4주차: 홈페이지 개편 + 문자/메일/로그인 연동 → 5주차: 반응형/보안 + 배포 → 이후 테스트 2주·안정화.
