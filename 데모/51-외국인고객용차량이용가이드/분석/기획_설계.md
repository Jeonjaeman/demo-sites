# KEYRING 키링 — 기획·설계

> 외국인 고객용 차량 이용가이드 모바일 앱 개발 (위시켓, 협의·80일·지원 67) · 제안용 데모
> 회사·지점·차종·연락처 전부 가상 · 차량 이미지는 AI 생성(실존 모델 아님)

## 0. 공고 요약
- 렌터카 회사가 외국인 고객에게 **차종별 이용 가이드** 제공하는 모바일 앱 (Android/iOS + 기획·디자인 포함)
- **QR 스캔 → 해당 차종 가이드 자동 열림** (차종마다 QR·링크 각각 발급)
- 관리자가 등록한 **한국어 원고 → 영어·중국어·일본어 자동(기계) 번역 표시** — 언어별 수기 등록은 범위 아님, 번역 품질 저하는 발주처가 수용
- 가이드 = 게시글 형태(텍스트+이미지): 주의사항·차량 특징·비상 연락처
- **위치 지도**: 현재 위치 기준 주변 지점·반납 장소 표시 (경로 안내·내비 아님)
- **문의**: 기존 운영 중인 외국인 상담 채팅으로 **외부 연결** (신규 채팅 구축 아님)
- 관리자 페이지: 가이드 등록·수정·삭제 + 링크·QR 관리(발급 방식은 협의)
- 콘텐츠 거의 미준비(차종 1건 초안뿐) → **유연한 등록 구조** 요구 · 승인 단계 없음(협의)
- 스코프 밖 명시: 예약·결제·리뷰·내비·채팅 신규 구축·PDF·스페인어 등
- 우선순위: 일정 > 금액 > 완성도 · 계약 즉시 착수

## 1. 명시 vs 숨은 니즈
| 구분 | 내용 |
|---|---|
| 명시 | QR 진입·자동번역·지도·외부 채팅·관리자 |
| 숨은 ① | **현위치 지도 = 위치기반서비스사업 신고** — 개인위치정보 수집 시 LBS 신고·동의 필요. 몰랐다가 스토어 심사·법무에서 걸리는 지점 |
| 숨은 ② | 안전 관련 문구(연료 오주유·경고등)는 **오역 = 배상 분쟁** — "품질 수용"과 별개로 안전 항목 원문 병기 설계 필요 |
| 숨은 ③ | QR → 즉시 열림은 **웹이 가장 빠름** — 순수 웹뷰 앱은 구글 정책 4.3 반려 리스크 → 모바일웹 + 하이브리드 셸 구조가 정답 |
| 숨은 ④ | 번역 API 비용·캐시 — 조회마다 번역하면 종량 과금 폭탄. 원고 저장 시 1회 번역 후 캐시가 정석 |
| 숨은 ⑤ | QR 재인쇄 비용 — 가이드 수정 시 QR이 바뀌면 안 됨 → **차종 고정 링크 + 내용만 갱신** 구조 |

## 2. 웹 리서치 — 발견 (근거)
| 우선순위 | 발견 | 근거 |
|---|---|---|
| **법 리스크** | 현재 위치로 주변 지점을 보여주는 앱 = **위치기반서비스사업 신고** 대상, 개인위치정보 수집·이용 동의 필요. 렌터카 차량 위치 추적도 이용자 위치가 드러나 동의 필요 | [생활법령 — 개인위치정보 원칙](https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=1702&ccfNo=2&cciNo=1&cnpClsNo=1) · [LBS 사업 신고](https://www.lbsc.kr/front/content/contentViewer.do?contentId=CONTENT_0000081) · [캐치시큐 신고 가이드](https://www.catchsecu.com/archives/14060) → 데모: **동의 게이트 + 미저장 원칙** 구현, 신고 절차를 착수 전 확인 항목으로 |
| 운영 관행 | 기계번역 고지: 번역 배지·원문 병기·오류 정정 절차. 안전·법률 문구는 원문 병기 또는 이중 검토 | [국립국어원 — 기계 번역](https://www.korean.go.kr/nkview/nklife/2017_4/27_0403.pdf) 등 → 데모: 기계번역 배지 + **주의사항 원문 병기** |
| 스택 재활용 | 순수 웹뷰 앱 스토어 반려(정책 4.3) — 41 WRAPLY 리서치 재활용 → 모바일웹+하이브리드 셸 제안 | 41-안드로이드웹뷰 분석 문서 |

## 3. 화면 구성 — 사용자 스토리 4건 그대로
| 스토리(공고) | 데모 구현 |
|---|---|
| "QR 찍으면 그 차종 가이드가 바로" | 01 QR 진입(스캔 시뮬) + **#car= 딥링크 — 관리자 발급 QR을 휴대폰으로 찍으면 실제로 해당 차종이 열림** |
| "내 언어로 안내를 읽고 싶다" | 02 가이드 — KO/EN/中/日 스위처, 기계번역 배지, 안전 항목 한국어 원문 병기, 비상연락처 탭투콜 |
| "근처 반납 장소를 알고 싶다" | 03 지도 — **위치 동의 게이트**(동의 시 현위치 기준 거리 정렬, 거부 시 목록만) · 캔버스 지도 · "경로 안내 아님" 명시 |
| "원고 등록하면 QR이 바로" | admin — 등록·수정·삭제 + **실제 스캔되는 QR 즉시 발급**(qrcodejs) · 수정해도 QR 불변(재인쇄 불필요) |
| 문의 | 04 — 기존 상담 채팅 외부 연결(새 창) · 운영 시간 안내 |

## 4. 제안 스택·일정 (총 9,000,000원 · 60일 · VAT 별도)
- 구조: **모바일웹(핵심) + 하이브리드 셸(Android/iOS 스토어용)** — QR 진입 속도와 스토어 심사 리스크를 모두 해결
- 번역: 관리자 저장 시 1회 자동 번역 → 캐시 저장(조회 시 API 호출 없음 — 비용 고정) · 엔진(Google/Papago/DeepL)은 착수 시 품질 비교 후 협의

## 5. 레드팀 4종 검수
- **① 디자인**: 차량 3종 AI 생성 검수 — 프레임·번호판·로고 없음 통과. 클린 화이트+블루, 여행자용 큰 터치 타겟
- **② 인터랙션**: QR 스캔라인 애니메이션·화면 전환·바텀시트·토스트·탭투콜·언어 전환 즉시 반영
- **③ 실측 QA**: 4화면 × 폰 프레임 rect 전수 — 오버플로 0 · 콘솔 0
- **④ 요구사항 충족(클라이언트 관점)**: 공고 요구·스코프 밖·확인 필요 항목 전수 대조 — 요구 7항 전부 구현, 스코프 밖 7항 미포함 확인("경로 안내 아님"·"신규 채팅 아님" 문구를 화면에 명시), 협의 항목(QR 발급 주체·승인 단계·번역 엔진)은 지원서 확인 요청에 배치
