# PINDEX 핀덱스 — 시나리오·사용자 여정

> 기능 목록을 **시간순 사용 흐름**으로 다시 배치한 문서입니다.
> 이 건은 특이하게 "발주사 내부 인력"이 사용자 여정에 함께 등장합니다 —
> 프론트 파트너가 백엔드·PM과 어떻게 맞물리는지가 과업의 성패를 가르기 때문입니다.

---

## 1장. 등장인물

| 인물 | 누구인가 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **이수진 · 매물 탐색자** | 이사 갈 동네를 지도로 훑는 실사용자. 모바일 60%. | 지도를 움직이며 "이 동네 얼마인가"를 빠르게 감 잡기. | 지도가 버벅이는 것. 핀을 눌렀는데 정보가 부실한 것. **본 매물이 지도에서 사라지는 것.** |
| **박PM · 발주사 PM** | 공고를 쓴 사람. 화면정의서·프로토타입을 준비했습니다. | 9월 중순 오픈. 마일스톤(2주·4주)대로 진행. | 프론트가 중간에 "이건 백엔드가 해야 한다"며 멈추는 것. |
| **최백엔드 · 발주사 개발자** | API를 이미 완성했습니다. | 프론트가 명세대로 붙여 주는 것. 추가 요청이 적은 것. | **범위에 없던 프록시·검증 엔드포인트를 갑자기 만들어 달라는 것.** |
| **파트너(우리)** | 프론트엔드 담당. 기존 데모 코드를 인수합니다. | 경계가 명확한 상태로 착수. | 코드 상태를 못 본 채 견적을 확정하는 것. |

**한 사람이 두 역할을 겸하는가?**
박PM은 발주자이면서 **검수자**입니다. 그래서 "완료"의 기준을 착수 전에 문서로 못 박아야 합니다.
특히 2-3·3-2처럼 **프론트 단독으로 완료가 불가능한 항목**은 검수 기준을 미리 나눠야
"미완성" 판정이 나지 않습니다.

## 2장. 전체 타임라인 — 계약 전후

```
[계약 전]

D-1   NDA · 기존 코드/API 명세 열람  ★ 0차 검토
       └ 여기서 경계 3건을 확인하지 않으면 이후가 전부 흔들립니다

[1차 · 30일]
D+0   착수 (2026-08-03)
D+3   코드 인수 · 화면정의서 대조 · 경계 합의 완료
D+13  ▶ 마일스톤 1 — UI 퍼블리싱 + 지도 연동 (공고: 2주)
D+28  ▶ 마일스톤 2 — 공공 API + PG 결제 (공고: 4주)
D+30  계약 기간 종료 (2026-09-02)

[계약 기간 밖 — 13일]
D+31~D+43  ??? ← 공고에 오픈 희망일만 9월 중순으로 적혀 있고
                 이 구간의 범위 귀속이 정의돼 있지 않습니다
D+43  최종 오픈 희망일 (2026-09-15)
```

**여기서 이미 드러나는 문제** — 마일스톤 2(4주)와 계약 종료(30일) 사이가 2일뿐입니다.
QA·크로스브라우징·배포가 들어갈 자리가 없습니다. 그 작업이 13일 구간으로 밀리는데,
그 구간이 계약에 없습니다.

## 3장. 역할별 시나리오

### 시나리오 A — 매물 탐색자의 3분

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| A-1 | 지도를 연다. 서울 전역이 보인다 | 지도 + 클러스터 | 마커 2,400개를 한 번에 그리면 **첫 화면에서 33ms/프레임** — 스크롤·드래그가 끊깁니다 |
| A-2 | 관심 지역으로 확대 | 휠·드래그 · 뷰포트 컬링 | 화면 밖 매물까지 계산해 확대할수록 느려집니다 |
| A-3 | 클러스터를 누른다 | 클러스터 클릭 → 자동 확대 | 클러스터가 그냥 숫자면 다음 행동이 막힙니다 |
| A-4 | 가격이 붙은 핀을 본다 | 마커에 가격 직접 표기 | 아이콘만 있으면 하나씩 눌러 봐야 합니다 — 부동산 지도의 핵심 문법입니다 |
| A-5 | 필터를 건다 (매매·10~20억·5년 이내) | 필터 칩 (호갱노노 축) | 조건이 안 맞는 매물을 계속 눌러 봅니다 |
| A-6 | 핀을 눌러 요약을 본다 | 말풍선 오버레이 | 상세로 넘어갔다 돌아오는 왕복이 생깁니다 |
| A-7 | 목록에서 마음에 드는 매물을 누른다 | 목록 ↔ 지도 동기화 | 목록과 지도가 따로 놀면 "이게 어디지"가 반복됩니다 |
| A-8 | **눌렀는데 "지도에 표시되지 않습니다"** | 좌표 매칭 실패 경고 | 조용히 사라지면 **데이터가 없는 서비스**로 보입니다. 이 데모는 3.9%(96건)가 그렇습니다 |
| A-9 | 모바일에서 다시 본다 | 바텀시트 전환 (900px 이하) | 좌측 패널 376px가 모바일 화면을 다 먹습니다 |

### 시나리오 B — 유료 열람과 결제

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| B-1 | 상세 정보를 보려니 결제를 요구한다 | (공고 2-4) | — |
| B-2 | PG 결제창이 뜬다 | 프론트 결제 모듈 | — |
| B-3 | 결제 성공 → 콜백 | 성공/실패/취소 라우팅 | — |
| B-4 | **서버가 콜백 금액을 그대로 저장한다** | 관리자 [결제 검증] | 브라우저에서 금액을 0원으로 바꿔도 통과합니다. 데모에서 직접 바꿔 볼 수 있습니다 |
| B-5 | 서버가 PG 원장을 재조회해 대조한다 | 검증 있음 흐름 | 이게 있어야 B-4가 막힙니다. **백엔드 엔드포인트가 필요합니다** |

> **정의가 없는 것** — 공고에 **결제 대상이 무엇인지** 적혀 있지 않습니다.
> 유료 열람인지, 구독인지, 중개 수수료인지에 따라 화면과 법적 요구(정기결제 고지 등)가 달라집니다.

### 시나리오 C — 발주사 PM의 검수

| 단계 | 상황 | 쓰는 화면 | **이 기능이 없으면** |
|---|---|---|---|
| C-1 | 2주차 — UI와 지도를 확인 | 지도 화면 | — |
| C-2 | 4주차 — "공공 API 연동됐나요?" | 관리자 [프론트 경계선] | 프론트가 "그건 백엔드가…"라고 하면 **분쟁**입니다. 착수 전에 표로 합의해야 합니다 |
| C-3 | "3-2 안전한 토큰 관리는요?" | 실제 호출 시연 | 말로 설명하면 변명처럼 들립니다. **버튼을 눌러 키가 URL에 남는 걸 보여주면** 논쟁이 끝납니다 |
| C-4 | 오픈 일정을 확인한다 | 관리자 [일정] | 13일 공백을 계약 시점에 못 박지 않으면 무상 대응이 됩니다 |

### 시나리오 D — 발주사 백엔드 개발자

| 단계 | 상황 | **이 기능이 없으면** |
|---|---|---|
| D-1 | 프론트가 API 명세대로 붙인다 | — |
| D-2 | 프론트가 "공공 API 프록시가 필요합니다"라고 한다 | **4주차에 말하면 일정이 무너집니다.** 0차 검토에서 나와야 합니다 |
| D-3 | 프론트가 "결제 검증 엔드포인트가 있나요?"라고 한다 | 같은 이유로 착수 전 확인 항목 |
| D-4 | 매물 API 응답에 좌표가 없다는 걸 알게 된다 | 지오코딩 주체와 캐시 위치를 정해야 합니다 |

## 6장. 예외 상황 — 시나리오를 그리면 드러나는 구멍

| 상황 | 지금 정의가 없는 것 | 데모에서의 처리 |
|---|---|---|
| **좌표를 못 찾은 매물** | 목록에 남길지, 숨길지 | 남기고 경고 표시 + "지도 표시분만" 필터 제공 |
| **공공 API 일일 한도 초과** | 사용자에게 뭐라고 보여줄지 | 미구현 — **미팅 확인 항목** |

## 7장. 미팅에서 확인이 필요한 항목

1. **공공 API 프록시 엔드포인트** 가 백엔드에 있는가 (없으면 프론트 단독 완료 불가)
2. **결제 검증 엔드포인트** 가 있는가
3. **매물 API 응답에 좌표(lat/lng)** 가 포함되는가
4. **기존 데모 코드 상태** — 0차 검토로 확인 후 공수 확정
5. **배포 리전** — 해외면 공공 API가 막힐 수 있음
6. **결제 대상 품목** — 화면과 법적 고지가 달라짐
7. **9/2~9/15 13일의 범위 귀속**
8. **게시판 범위**
9. **검수 기준** — 2-3·3-2처럼 프론트 단독 완료가 불가능한 항목의 완료 정의
