## 0. 한 장 요약

**핵심 판단 3줄**
1. 이 공고의 진짜 과제는 "예쁜 사이트"가 아니라 **최소 인력 단체가 5년간 혼자 굴릴 수 있는 운영 도구**다. 평가자는 비전문가이므로 **눌러볼 수 있는 데모 + 전/후 수치**가 가장 강한 증거다.
2. 공고·RFP의 요구를 "흔한 방법"대로 만들면 **바로 깨지는 지점이 3곳** 있다. 구글 번역 위젯 종료, 쿼리스트링형 구 URL의 301 처리, 아이폰 HEIC 사진·EXIF 처리다. 경쟁 지원자 공개 댓글 3건에는 "이미지 최적화", "URL 구조 확인" 수준의 언급만 있고 이 구체적 함정은 보이지 않는다.
3. 동물단체 사이트라서 생기는 **법적 표시 의무가 3종** 있다. 구글시트 국외 이전 고지, 학대 영상 게시 시 목적 표시, 공익법인 기부금 공개·신고 링크다. 이 셋을 CMS 기능(자동 삽입 박스)으로 풀면 경쟁사와 확실히 갈린다.

**치명적 발견 8개** (상세는 2-5): ① 구글 웹사이트 번역 위젯 2026-10-01 지원 종료 ② 구 URL이 쿼리스트링형이라 일반 리디렉션 표로는 301 불가 ③ HEIC·EXIF 방향·GPS 처리 ④ 구글시트 = 국외 이전 고지 대상 + 만 14세 미만 동의 ⑤ 학대 현장 영상은 단체명·목적 표시가 있어야 게재 예외 ⑥ 공익법인 홈페이지 공개·연결 의무 + 모금 시 법정 게시 사항 ⑦ "숨김"의 구멍(공개 저장소 사진 URL·캐시·순차 번호) ⑧ 무료 플랜·약관 함정(Vercel Hobby 상업 이용, Supabase 비활성 일시정지, CDN 영상 제한)

**데모가 꼭 보여줄 5개 장면**: 관리자 사진 끌어놓기(HEIC 포함, 전/후 용량) → 상태 변경 시 변경일 자동 기록 → 숨김·사망 처리 후 "외부에서 확인" 시 404 → EN 버튼(이름은 번역 제외) → 구 주소 붙여넣기 시 301 대상 표시

### 1-2. 여정 ① 개체 생애주기 — 구조 → 치료 → 공개 → 심사 → 완료 → 후기

상태 모델(초안). RFP의 2축(보호 상태·입양 상태)을 유지하되, RFP가 정의하지 않은 상태는 `*`로 표시했다.

```
보호 상태 : [보호중] ──사망 처리(관리자만 열람)──▶ [사망]
입양 상태 : [비공개 준비*] → [모집 중] → [심사 중*] → [입양 완료]
             [입양 완료] ──파양·반환*──▶ [모집 중]   (이력은 덮어쓰지 않고 누적)
보조 표시 : 임보 중* / 해외 입양 예정* / 학대 현장 미디어 포함*
* = RFP 미정의 → 미팅 확인
```

| 단계 | 상태값 전이 | 변경일 기록 지점 | 쓰는 화면 | 이 기능이 없으면 벌어지는 일 |

### 1-5. 명시된 니즈 vs 숨은 니즈

- A안(DB 덤프 제공, 본문 정형): 후기 400 × 800 = 32만 + 기부내역 120 × 2,500 = 30만 + 언론 70 × 500 = 3.5만 + 공지·FAQ 100 × 2,500 = 25만 + 현역 개체 67 × 8,000 = 53.6만 + 완료 개체 요약 106 × 800 = 8.5만 → **약 153만 원** → 필수 한도 100만 원 초과분 약 53만 원
- B안(DB 없음, 웹 페이지 수집): 후기 400 × 3,000 = 120만 원을 포함해 **약 240~260만 원**
- 제안: FTP·DB 접근권을 착수 1주 내 확보하는 것을 전제(A안)로 두고, 초과분은 ① 단가 정산 ② 운영진 직접 이전(교육 겸) ③ 오래된 후기 아카이브 처리 중에서 선택. RFP의 "유지·정리·폐기" 매핑과 연결한다.
