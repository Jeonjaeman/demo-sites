## 2장. 리서치 — 그대로 만들면 터지는 지점

우선순위: `그대로 만들면 작동하지 않음` > `법 위반 소지` > `운영 중 반드시 터짐` > `있으면 좋음`

### ★ 발견 1 — HeyGen 무료 크레딧이 폐지됐습니다. 영상이 곧 비용입니다

"AI 툴로 저렴하게"라는 기대와 달리, **HeyGen은 2026년 2월부터 무료 API 크레딧을 없애고
초당 과금(pay-as-you-go)** 으로 바꿨습니다. 아바타 등급별 단가입니다.

| 등급 | $/초 | 45초 영상 | 월 22개 |
|---|---|---|---|
| Avatar III Digital Twin | $0.0167 | $0.75 | $17 (≈₩2만) |
| Avatar III Photo | $0.0433 | $1.95 | $43 (≈₩6만) |
| Avatar IV Photo | $0.05 | $2.25 | $50 (≈₩7만) |
| Avatar V / Studio | $0.0667 | $3.00 | $66 (≈₩9만) |

> 근거: [HeyGen API Pricing 2026 (G2)](https://www.g2.com/articles/heygen-api-pricing) ·
> [HeyGen Pricing 2026 (eesel)](https://www.eesel.ai/blog/heygen-pricing) —
> 2026-02 무료 크레딧 폐지, pay-as-you-go 최소 $5, 크레딧 12개월 만료.
> 웹 플랜은 Creator $29(600크레딧=아바타IV 30분)/Pro $49/Business $149.

요일별로 매일 숏폼을 자동 생성하면 월 20~40개, **재렌더까지 감안하면 비용이 빠르게 쌓입니다.**
그런데 공고는 이 비용을 언급하지 않습니다.

- **대응** — 대시보드 [HeyGen 비용 계산기]에서 영상 개수·길이·아바타 등급·**재렌더율**을 넣으면
  월/연 비용이 실제로 계산됩니다. 등급을 Avatar III로 낮추면 비용이 4배 가까이 줄어드는 것을
  수치로 보여줍니다. **어느 플랜을 감당할지 착수 전에 정해야 합니다.**

### ★ 발견 2 — 검수 없이 자동 영상화하면 틀린 대본에 돈이 나갑니다

공고가 2-3 에디터 검수를 **"중요"** 로 표시한 이유입니다. AI 초안은 사실 오류·과장이 섞입니다.
검수 게이트 없이 `draft → HeyGen` 을 바로 연결하면, **틀린 대본을 렌더한 뒤 다시 만들면서
초당 과금이 두 번** 나갑니다. 발견 1의 비용을 재렌더가 배로 늘립니다.

- **대응** — 파이프라인을 `draft → 에디터 승인 → video` 순으로 강제했습니다. **승인 전에는 영상
  단계로 넘어가지 않습니다.** 데모 [파이프라인]에서 승인 안 된 티켓을 영상화하려 하면 막힙니다.
  검수 게이트가 곧 비용 방어선입니다.

### ★ 발견 3 — AI가 만든 부동산 콘텐츠는 표시·광고 규제 대상입니다

공인중개사법 **제18조의2** — 중개대상물을 광고할 때 **중개사무소 명칭·소재지·연락처·등록번호·
개업공인중개사 성명**을 반드시 명시해야 합니다. AI 초안에는 이 명시사항이 없고,
"확실히 오른다" 같은 과장 표현이 섞이기 쉽습니다.

> 근거: [공인중개사법 §18의2 표시·광고 (CaseNote)](https://casenote.kr/법령/공인중개사법/제18조의2) ·
> [부당한 표시·광고 과태료 (머니투데이)](https://news.mt.co.kr/mtview.php?no=2023050118230360511) —
> 명시사항 누락 **최대 100만원**, 부당(과장·단정)광고 **최대 500만원** 과태료.

자동 발행이면 사람 눈을 거치지 않으므로 위반이 그대로 나갑니다.

- **대응** — 발행 전 [컴플라이언스 체크]가 텍스트를 **실제로 검사**합니다. 명시사항 누락과 금지
  표현을 잡아내고, 통과하지 못하면 발행을 막습니다. 데모 데이터 20건 중 **11건이 위반**으로
  잡혔고, 그대로 발행했다면 누적 과태료 위험이 **3,500만원**입니다. 이 검사를 통과한 콘텐츠만
  발행 단계로 갑니다.

### 발견 4 — n8n 워크플로우는 외부 API가 바뀌면 조용히 멈춥니다

이 시스템은 부동산 API·LLM·HeyGen·구글/노션 등 여러 외부 서비스를 엮습니다. 그중 하나가 응답
형식을 바꾸거나 인증이 만료되면 그 지점부터 멈추는데, **비개발자는 어디가 끊겼는지 모릅니다.**

> 근거: [n8n Cloud vs Self-Hosted (2026)](https://tekkpak.com/n8n-self-hosted-vs-cloud-comparison/) —
> 클라우드는 업데이트·보안이 관리형, 셀프호스팅은 발주사가 DevOps를 떠안음.

- **대응** — 각 단계에 실패 감지·텔레그램 알림을 넣고, 관리자 [파이프라인 상태]에서 어느 노드가
  실패했는지 보이게 합니다. **유지보수 매뉴얼을 산출물에 포함**합니다(공고 우대사항).

### 발견 5 — "올인원"이 아니라 "1차 MVP"입니다

공고가 스스로 "방대한 올인원이 아닌 1차 MVP"라고 못 박았습니다. 그런데 요구사항은 수집·생성·
영상·리포트·에디터로 넓습니다. **60일·1,000만원 안에 모두 프로덕션 품질로 넣으면 어느 것도
완성되지 않습니다.**

- **대응** — 수집→초안→검수→영상→발행의 **한 줄기(요일 1종)를 먼저 끝까지** 돌리는 것을 1차로
  제안합니다. 리포트·다채널 발행은 2차입니다. 데모의 파이프라인이 그 한 줄기입니다.

### 발견 6 — 맞춤 리포트가 투자 권유가 되면 규제 영역입니다

2-5의 "맞춤형 부동산 리포트"가 특정 매물 매수를 권유하는 형태가 되면 **유사투자자문·부당
표시광고** 문제가 생깁니다. "정보 제공"과 "투자 권유"의 경계를 문구로 관리해야 합니다.

- **대응** — 리포트를 사실 정보(실거래·청약 일정) 중심으로 구성하고, 단정적 수익 예측 표현을
  금지어로 걸었습니다. 컴플라이언스 체크가 리포트에도 적용됩니다.

### 잘 되어 있는 부분도 짚습니다

- **"1차 MVP"로 범위를 스스로 좁힌 것** — 자동화 프로젝트가 실패하는 가장 흔한 이유가 과욕인데,
  이걸 미리 막았습니다.
- **에디터 검수를 "중요"로 표시한 것** — HeyGen 비용 구조를 몰라도, 검수가 왜 필요한지는
  정확히 짚었습니다.
- **"한계점과 대안을 포함한 견적"을 요구한 것** — 기술을 모르는 발주사가 할 수 있는 가장 현명한
  요구입니다. 이 데모 전체가 그 답입니다.

## 5장. 제안 스택

| 레이어 | 제안 | 이유 |
|---|---|---|
| 오케스트레이션 | **n8n Cloud(1차) → 셀프호스팅(확장 시)** | 1차는 관리형으로 빠르게. 서버 운영을 프로젝트에 얹지 않음 |
| AI 초안 | **OpenAI/Claude API + 프롬프트 템플릿** | 요일별 주제 분기를 워크플로우로. 품질은 프롬프트가 좌우 |
| 에디터 | **Retool 또는 Airtable** (공고 명시) | 순수 커스텀 대신 노코드. 승인→트리거는 웹훅 |
| 영상 | **HeyGen API + 검수 게이트** | 초당 과금이므로 승인 후에만 렌더 |
| 데이터 | **Google Sheets/Notion(1차) · 구조화된 스키마** | 2차 연동 대비(공고 2-6). 상태·메타 필드 표준화 |
| 컴플라이언스 | **발행 전 검사 미들웨어** | 명시사항·금지어 검사를 발행 트리거 앞단에 |

**1차에서 반드시 지킬 것**
1. `draft → 승인 → video` 게이트를 워크플로우에 강제 (비용·품질 방어)
2. 발행 트리거 앞에 컴플라이언스 검사 (법적 방어)
3. 각 노드 실패 알림 + 유지보수 매뉴얼 (인수 대비)
4. DB 스키마에 2차 연동용 상태/식별자 필드 미리 포함
