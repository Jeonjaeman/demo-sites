### 4-2. 표면별 적용

**① 자사 관리자 (대시보드형 · 라이트)**
- 좌측 사이드바 260px + 헤더 72px(Linear) · 페이지 `#fafafa` / 카드 `#ffffff`
- KPI 4~5장: **라벨(12px 대문자 600 `#71717b`) 위 · 값(20px w600 `#121212`) 아래**, 증감 `#00bc7d` — Plausible 그대로. 숫자를 40px로 키우지 않는다
- 보고서 목록 표 컬럼(Certipedia 6컬럼을 도메인으로 치환):
  `고객사 · 보고서번호 · 시험 유형 · 제품명 · 발급일 · QR 상태 · 관리`
- 툴바: 검색 + `고객사`·`시험유형`·`기간`·`QR 상태` 필터(h32) — 시험법이 300건 규모(P&K 309개)라 **드롭다운이 아니라 검색형 필터** 필수
- 모션 약(절제): 100/160ms 상태 전환 + 차트 그리기 500ms만

**② 고객사 포털 (B2B 문서 포털)**
- 동일 토큰, 밀도만 완화(행 48→56, 본문 15px 유지)
- 진입 즉시 **자사 발급분만** 보이는 목록 + 보고서번호 검색(프리필 + "예시로 조회" 버튼)
- 보고서 상세: Certipedia 순서를 따르되 고객사용으로 — `상태 → 제품 → 보고서번호(mono) → 시험항목 칩 → 발급/유효 → 원문 PDF → QR 발급·다운로드(PNG/SVG/EPS)`
- QR 다운로드 시 **발급 이력이 화면에 즉시 append**(누가·언제·어떤 규격) — 공고의 "이력이 남아야 한다" 요구를 눈에 보이게

**③ QR 스캔 공개 조회 (모바일 우선) — 상단 구성안**

Certipedia 순서 + Credly 칩/실패화면 + stateofaidesign 모노 라벨을 결합.

**미해결 · 한계**
1. **CTKCLIP의 GDWEB 수상** — 언론 보도(한국섬유신문)는 GDWEB 홈 뉴스 목록에 존재하나, GDWEB `/sub/list.asp` 선정작 목록이 JS 필터 UI만 렌더되어 수상작 명단에서 직접 대조하지 못함. → **어워드가 아니라 「갤러리/국내 동종업」으로만 표기.**
2. **Credly 실제 발급자(earner) 검증 페이지** — 공개 URL이 UUID 기반이라 유효한 실물 배지 페이지에 도달하지 못함. 대신 ⓐ 배지 템플릿 상세와 ⓑ 검증 실패 화면을 실측했다. 따라서 "발급일/만료일/Verify 버튼" 블록의 실측 수치는 없다(구조는 Certipedia로 대체 확보).
3. **관리자 사이드바 폭 260px는 추정** — 로그인 없이 접근 가능한 실물 문서관리 백오피스를 찾지 못해, Linear `--page-inset 32px`와 Credly 4/12(380px) 사이에서 국내 밀도에 맞춰 정한 값. 실측값 아님.
4. **만료임박 상태색 `#8a5a00`/`#f6efe0`은 추정** — 레퍼런스 어디에도 amber 계열 상태색 실측값이 없어 대비비를 맞춰 산출했다.
5. Certipedia의 목록 `<table>` 요소는 `getBoundingClientRect()`가 0을 반환(가상/오프스크린 렌더) → **행 높이·셀 패딩 실측 실패**. 컬럼 구성은 텍스트로 확보했으나 표 치수는 Plausible 기준으로 대체했다.
6. 모든 사이트는 **1440×900 데스크톱 1개 뷰포트**에서만 실측했다. 모바일(375px) 브레이크포인트 동작은 관찰하지 않았다.
