# ATTEST 어테스트 — 보고서 QR 연동 관리 플랫폼 (데모 78)

화장품 인체적용시험 기관이 보고서를 등록하면 **불변 토큰 QR**이 발급되고, 고객사는 자기 계정에서 조회·다운로드하고, 소비자는 제품 QR로 진위를 확인하는 플랫폼 데모. 표면 4개.
**기관·고객사·제품·보고서·인물은 전부 가상 데이터입니다.**

| 표면 | 파일 | 설명 |
|---|---|---|
| 진입 | `index.html` | 역할별 로그인(기관·RA·마케터) + 소비자 QR 화면 링크 · 역할별 시야 표 |
| 기관 관리자 | `admin.html` | 대시보드 · 보고서(상태 머신·실증 게이트·공개 항목·개인정보 점검·버전) · 등록 · QR 이력 · 고객사 · 통계 · 감사로그 · 보안/인프라 · **인수인계 현황** |
| 고객사 포털 | `client.html?role=RA\|MKT\|ADMIN` | 내 보고서 · 공개 동의 · 원문(RA만) · QR 다운로드(인쇄 패키지·시뮬레이터·추가 발급) · 실증 D-15·ZIP · 문구 검사기 · 자사 스캔 통계 |
| QR 공개 조회 | `r.html?t=토큰` | 무인증 · 화이트리스트 · 상태 4종+미등록 랜딩 · 진위확인 · SHA-256 대조 · 신고 · KO/EN |

## 체험 시나리오 (입력 없이 클릭만으로)

1. **공개 화면** `r.html?t=7K9F2Q` — 하단 데모 독에서 활성 → 만료 → 정지 → 폐기 → 미등록을 차례로 (전부 404 없음) · 「정적 QR 비교」 · 진위확인 「확인」 · 「예시(일치) 붙여넣기 → 대조」 · 「신고 접수」 → 접수번호
2. **기관 관리자** — 보고서 목록에서 `SP-2026-0455`(실증 미충족) 클릭 → 발급 버튼 잠김 사유 확인 → 「요건 보정」 · `SP-2026-0417` → 공개 항목 체크 해제 → 새 탭 공개 화면에서 사라짐 확인 → 「v3 게시」 → QR 토큰 그대로·공개 화면 v3 배지 · 인수인계 현황 → ZIP · 30분 테스트 체크
3. **고객사 포털** — 역할을 마케터로 바꾸면 원문 PDF 버튼이 사라짐 · QR 다운로드 → 슬라이더 12mm(경고)/25mm(권장) · 「인쇄 패키지(ZIP)」 · 실증자료 → 「요청 접수」 D-15 → 「10일 전 시뮬」 D-5 → ZIP 생성 · 문구 검사기 예시 1(3건 검출)/예시 2(통과)
4. **실제 스캔** — 관리자·고객사 화면의 QR을 스마트폰으로 찍으면 배포된 공개 화면이 열립니다 (자체 인코더 · jsQR 디코드 검증)

## ⚠ 착수 전 확인 (미팅 안건)

1. 보고서 개정 빈도 · 소비자 공개 범위(기본 제안: 요약만) · 계약 종료 후 QR 안내 유지 기간(제안 3년)
2. 고객사 담당자 구성(역할 3종 필요 여부) · 시험번호 체계(연도 순환·중복)
3. 보고서 PDF의 피험자 정보 포함 여부 → 공개본 분리 방식
4. 구독 과금 단위(고객사/보고서/QR/스캔) → 지금 스키마에 반영
5. 기존 드라이브 QR 유통분 유무 → 레거시 인수 경로 · 발주사 명의 계정 개설 주체·도메인 문자열
