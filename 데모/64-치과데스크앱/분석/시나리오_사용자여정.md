# DENTDESK — 시나리오·사용자 여정
## 등장인물
데스크(전화 통화 중 한 손 조작·이중예약 불안) / 실장(수납 마감·미수 회수·숫자 불일치 불안) / 원장(매출·노쇼·직원의 환자 DB 유출 불안 — 이동 중 폰 조회) / 위생사(공고에 누락된 리소스 — 스케일링은 위생사+체어 소요) / 환자(문자 수신자 — 광고 취급·진료내용 노출 불안) / ★기존 청구·전자차트 프로그램(이 CRM과의 관계가 최대 변수)

## 여정 (없으면 벌어지는 일)
전화 접수(3초 내 빈 체어 — 없으면 통화 길어져 대기 전화 끊김) → 슬롯 확정(의사·체어·위생사 3중 가용성) → **동시 조작(옆 데스크가 같은 슬롯 — 이중예약)** → 리마인드(D-1 자동 — 노쇼 22%↓ 실측) → 당일 취소(대기 목록 없으면 체어 40분 공실=매출 증발, 공고에 대기 기능 없음) → 내원·접수 → 진료(← 기존 EMR 영역, 침범 시 의료법) → 상담(금액 안내 — 기록 없으면 직원마다 다른 금액=분쟁) → 수납(일부 결제=미수 발생·현금 10만↑ 영수증 의무) → 리콜 등록 → **6개월 후 리콜 발송(← 최대 법적 지뢰: 광고성)** → 월 마감(CRM 숫자≠실입금)

## 역할별 시야 차이 (권한 설계 — 공고의 2단계로는 부족한 지점)
환자 연락처: 전원 조회(업무) / **전체 목록 다운로드: 데스크 차단**(퇴사 유출 경로) / 진료·상담 이력: 데스크는 상담 메모만 / 수납 수정·삭제: 실장 승인(현금 조작 방지) / 통계: 원장 / **접속·열람 기록: 원장만** — 데모의 역할 스위처(데스크/실장/원장)가 이 차이를 실전환으로 보여줌

## 비는 구멍 (미팅 확인 — 1순위부터)
1. **기존 청구/전자차트가 무엇이며 예약을 그쪽에도 입력하는가** (SSOT 결정) 2. 진료 이력의 범위 — 병명·처치인가 상담 메모인가 (EMR 경계) 3. 기존 환자 수천 명 이관(형식·공수) 4. 리콜 주기 기준(스케일링=연도 리셋) 5. 노쇼 위약 정책(치협 기준·사전 고지) 6. 진료 항목 마스터(수가·급여/비급여) 관리 주체 7. 수납 수정 권한·이력 8. 알림톡 발신프로필·요금 명의 9. 점심·휴진·정비 블록 규칙 10. 위생사도 예약 리소스인가
