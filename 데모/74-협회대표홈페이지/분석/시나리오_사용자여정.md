## 1. 등장인물

| # | 인물 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| ① 발주기관 주무관 | 지자체·유산청 계약 담당. 업체가 낸 보증서가 **진짜인지 3분 안에** 확인하고 결재 증빙 확보 | 위조 보증서를 통과시키면 본인 책임. 전화 확인은 기록이 안 남음 |
| ② 조합원(수리업체 실무자) | 보증서를 **오늘 안에** 발급받아 제출. 사무직 1명이 계약·보증·세무 겸임 | 인증서가 안 먹힘 · 어느 메뉴인지 모름 · 마감이 오늘 |
| ③ 신규 진입 예정자 | 가입 조건·출자금·수수료를 **전화 없이** 웹에서 확인 | 잘못 알고 가입했다가 등록 반려 |
| ④ 조합 실무 담당자 | 민원 전화 축소 + 오픈 후 **본인이 직접** 공지·팝업 관리 | 개발 용어를 몰라 검수 불가. 개발사가 사라지면 아무것도 못 고침 |
| ⑤ 조합 관리자(전산 겸임) | 계정·권한·게시물이 사고 없이 운영 | 관리자 계정 탈취·자료실 개인정보 유출 — 책임이 본인 |
| ⑥ 일반 국민·언론 | 기관 개요·연락처 | (첫인상이 조합 신뢰도 그 자체) |
| ⑦ 기존 영업점 벤더 | 자기 시스템이 안 망가지는 것 | 제3자가 자기 시스템에 손대는 것 — **최대 외부 변수** |

★ 겸업: ②=③(시기만 다름), ④=⑤(담당자 1명). 관리자 권한 2단 분리는 필요하되, 화면 전환은 한 사람이 쓰기 쉽게.

## 2. 시간순 여정 3종 (여정마다: 상황 → 화면 → 없으면 벌어지는 일)

### 여정 A — 주무관의 보증서 진위 확인 (사이트 존재 이유 1순위)
발견(검색→메인, 상단 고정 조회 진입 없으면 전화) → 판단(30초 내 진입) → 행동(보증서의 번호·금액·일자 다중 입력 — 단독 입력이면 열거 공격) → 대기(실패 사유 구분 없으면 무조건 전화) → 실행(**조회 확인서 출력** 없으면 스크린샷 증빙 → 감사 때 무효) → 사후(3개월 뒤 하자 시점 **검증번호 재조회**).

### 여정 B — 조합원의 보증서 발급 (오늘 마감)
발견(조합업무>보증 구분) → 판단(구비서류·요율·처리시간) → 행동(**공동인증서 로그인** — 민원 1위: 브라우저 미등록·용도제한 인증서·팝업 차단) → 대기(**영업점 인계 브리지** — 이중 로그인 요구 시 민원) → 실행(영업점 업무, 범위 밖) → 사후(발주처 조회 = 여정 A 연결).

### 여정 C — 조합 담당자의 오픈 준비→일상 운영 (공고 최대 우려의 실체)
발견(**오픈 준비 체크리스트** 없으면 일정 지연 1순위) → 판단(**직접 수정 가능 영역 지도** 없으면 매번 개발사 문의) → 행동(공지·팝업·배너 편집 — 미리보기·되돌리기 없으면 공개 화면 파손) → 대기(버전 이력) → 실행(**게시 종료일 필수** 없으면 만료 팝업 방치) → 사후(자료실 업로드 — **개인정보 검사** 없으면 72시간 유출신고 사태).

## 4. 명시 니즈 vs 숨은 니즈

명시: 대외용 홈페이지 6메뉴 + 반응형 + 관리자(공지·자료실·배너·팝업) + 공동인증서→영업점 연계 + 신뢰 디자인(모션 지양) + 산출물 5종.

숨은: ① 요구사항을 대신 정의해 줄 사람(아이디어 단계) ② 10년 굴러가는 스택 + 책임질 사람 ③ CMS 범위는 사실 공지·팝업이 아니라 **메인 문구·업무 설명·연락처·조직도**까지 ④ 비개발자가 진행 상황을 눈으로 보는 장치 ⑤ 민원의 실체는 미감이 아니라 "못 찾겠다" = IA 우선 ⑥ 오픈 2주 전 담당자 CMS 실사용 가능(교육이 크리티컬 패스) ⑦ 연계 실패 시 플랜 B를 가진 파트너.
