# 서식나루 — 시나리오 · 사용자 여정

> 공고: 법률 종합서식 검색 및 관리 웹 프로그램 개발 (프리모아 · 2026.08.05 · 예상 850~1,000만 원 · 45일)
> 데모: `데모/71-법률서식사이트/서식나루/` · https://jeonjaeman.github.io/demo-sites/seosiknaru/

기능 목록을 시간순 사용 흐름으로 재배치해, 각 기능이 **왜 존재해야 하는지**와
**정의가 비어 있는 예외 상황**을 도출한 문서입니다.

---

## 1. 등장인물

| 인물 | 역할 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **김도현** (52) | 법무사 · 정회원 | 서식을 3초 안에 찾아 한글에서 바로 열기 | 서식명이 기억 안 남 · 구버전 서식으로 접수했다 반려되는 것 |
| **박은서** (29) | 김도현 사무소 직원 | 원장 계정으로 같이 쓰기 | 로그인하면 원장 접속이 끊긴다는 것 (→ 1인 1세션의 존재 이유) |
| **이지현** (38) | 발주사 운영자 (관리자) | 1만 건 등록·개정 반영·회원 관리 | 서식이 통째로 유출되는 것 · 누가 얼마나 받는지 안 보이는 것 |
| **발주사 대표** | 콘텐츠 보유자 (법무사 대상 사업) | 서식 자산의 수익화 | 고가 SDK 비용 · 유출로 자산 가치가 사라지는 것 |
| **신규 방문자** | 무료(일반) 회원 | 급한 서식 1건 | 결제 전에 품질을 확인하고 싶음 |

한 사람이 두 역할을 겸하는 지점: **김도현은 이용자이면서 사무소(프리미엄 시 5인) 계정의
관리자 역할**을 겸할 수 있다 — 프리미엄의 "사무소 계정" 기능이 존재하는 이유.

## 2. 시간순 여정 — 이용자 (김도현)

| 단계 | 상황 | 쓰는 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 발견 | "가압류 신청서, 채권 종류가 뭐였지" | 메인 검색(자동 제안) · 분야/절차 색인 | 서식명을 정확히 몰라 검색 실패 → 이탈 |
| 판단 | 이 서식이 맞는 판인지 확인 | 상세 미리보기 · 최종개정일 · 개정 이력 | 구버전으로 접수 → 법원 반려 |
| 행동 | 내려받아 한글에서 작성 | [한글 파일로 열기] HWP/HWPX/PDF | 웹 편집기 없인 아무것도 못 하는 시스템 |
| 막힘 | 파일이 한글로 안 열림 | 고객지원 "한글 연동 설정" 가이드 | 문의 전화 폭주 → 운영 비용 |
| 반복 | 같은 사건에서 서식 5~6종 사용 | 서식함(사건별 폴더) | 매번 재검색 → 이탈, 락인 실패 |
| 대기 | 법령·예규 개정 | 개정 알림 → 최신본 받기 | 개정 사실을 모른 채 구버전 사용 |
| 사후 | "지난달 뭘 받았지" | 최근 내려받기 이력 · CSV | 한도 분쟁 시 근거 없음 |

## 3. 시간순 여정 — 운영자 (이지현)

| 단계 | 상황 | 쓰는 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 구축 | 1만 건 HWP 원본 등록 | 엑셀 대량 등록 · 컬럼 매핑 | 1건씩 등록 → 1만 건에 수개월 |
| 분류 | 분야·절차·태그 부여 | 카테고리 트리 · 검색 태그 매핑 | 검색 품질 붕괴 ("서식명을 모르는 사용자"가 못 찾음) |
| 개정 | 규칙 개정 → 서식 교체 | 서식 수정 · 개정 이력 기록 | 회원이 구버전 접수 → 신뢰 상실 |
| 회원 | 라이선스 기간 부여·연장 | 회원·등급 관리 | 만료 회원이 계속 이용 → 매출 누수 |
| 감시 | 유출 징후 확인 | 로그 대시보드 · 이상 징후(단시간 대량·다중 IP) | 한도 내 반복 유출을 못 봄 → 자산 소실 |
| 조치 | 의심 계정 차단 | 이용 차단 · 한도 정책 설정 | 사후 대응 불가 |

## 4. 역할별 시야 차이 (권한 설계의 핵심)

같은 데이터를 역할에 따라 다르게 본다:

| 데이터 | 이용자(김도현) | 운영자(이지현) |
|---|---|---|
| 내려받기 기록 | **내 것만** — 오늘 18/50, 이력 목록 | **전 회원** — 계정별 집계, 이상 징후 플래그 |
| 서식 | 열람·다운로드 (등급 범위 내) | 등록·수정·삭제·대량 등록 |
| 한도 | 잔여량 표시 (차감 결과만) | 정책 수치 자체를 설정 |
| 세션 | 내 접속 기기 1대 표시 | 다중 IP 로그인 시도 감지 목록 |
| 등급 | 내 등급과 혜택 | 회원별 라이선스 기간 부여·차단 |

## 5. 명시된 니즈 vs 숨은 니즈

**명시**: 초고속 검색 · 한글 연동 · 라이선스 관리 · 대량 유출 방지 · 대량 등록.

**숨은 니즈** (공고 문구에서 추론, 데모에 반영):
- "기획 상태: 필요기능 정리" → 화면 설계부터 함께해 줄 파트너가 필요 → **데모로 화면 설계를 선제시**
- "고가의 웹 HWP 편집기 대신" → 예산 민감 + 기술 대안 판단 능력을 원함 → 지원서에서 **그 판단이 옳은 기술적 근거**를 설명
- "익숙한 UX" → 이용자(법무사)의 연령대·업무 습관 고려 → **관보식 밀도 대신 큰 활자·명확한 위계**
- "관리자 대량 등록으로 고객사가 직접" → 등록 화면의 사용성이 곧 구축 일정 → **컬럼 매핑·검증 단계 UI**

## 7. 비는 구멍 — 미팅에서 확인할 것

1. **결제 방식** — 공고에 결제가 없다. 등급(라이선스)은 있는데 결제·갱신은 수동인가,
   PG 연동인가? PG면 통신판매업 신고·수수료(의뢰자 부담)가 따라온다.
2. **서식 저작권** — 법원 공식 서식 외 "법무사회 표준·자체 서식"의 저작권/출처 표기
   기준. 유출 시 법적 대응을 전제로 한다면 워터마킹(다운로드 파일에 계정 정보 삽입)
   필요 여부.
3. **엑셀 대량 등록 스키마** — 1만 건 원본의 파일명 규칙·분류 체계가 정리되어
   있는가? 컬럼 매핑 설계가 구축 일정의 최대 변수다.
4. **개정 감시 주체** — 법령·예규 개정을 누가 모니터링해 서식을 갱신하는가?
   (운영 인력 계획 — 시스템은 알림·이력만 제공 가능)
5. **세션 정책의 예외** — 사무소 내 같은 IP에서 PC 교체 시에도 세션 해제인가?
   점심시간 자동 로그아웃 등 보안 정책 수위.
6. **HWPX 호환 범위** — 이용자 PC의 한글 버전 분포(2010 이하가 있으면 HWP 필수
   제공, 데모는 HWP 기본 제공으로 반영).
7. **탈퇴·만료 회원의 로그 보존 기간** — 유출 추적 목적과 개인정보 보호법상 파기
   의무의 균형(데모 약관에는 6개월로 가안 명시).
8. **인프라 선택** — "서버 비용 고객사 부담"이므로 월 비용 규모(클라우드 vs 호스팅)를
   착수 전에 합의해야 한다. 1만 건 HWP(수 GB)의 스토리지·백업 포함.
