  서식함·1인 1세션 로그인)과 관리자(서식 DB·대량 등록·회원 라이선스·로그·한도

- 핵심 요소   1만 건 규모 통합 검색(서식명·사건유형·근거 법령)과 응답 시간 표기,
  분야 10종·절차 6단계 색인, HWP/HWPX/PDF 다운로드와 일일 한도 실차감, 중복
  로그인 차단 모달, 관리자 이상 징후 감지(단시간 대량·다중 IP), 내려받기 이력
  CSV 추출, 엑셀 대량 등록 컬럼 매핑

[3] BIZSEED — 신규사업자 데이터 수집·검색
https://jeonjaeman.github.io/demo-sites/bizseed/

- 진행 과정   공공 데이터 수집 파이프라인을 리서치하다 국세청 API가 신규 사업자
  "목록"을 제공하지 않는다는 결함을 발견해, 합법적 대체 수집 경로와 검증 화면을

- 특징        수만 건 목록을 다단 필터로 즉시 좁히는 화면이라, 1만 건 서식
  검색의 속도·필터 설계와 같은 성격입니다. 공고의 우대 사항(대용량 데이터 검색
  속도 최적화)에 해당하는 작업입니다.
- 핵심 요소   다단 필터 즉시 반영, 수집 파이프라인 단계별 검증 표시, 중복·결측
  자동 검출, CSV 추출(엑셀 한글 깨짐 대응 BOM 처리)

https://jeonjaeman.github.io/demo-sites/classpulse/

- 핵심 요소   필터 조합별 실시간 재집계, 소규모 셀 자동 마스킹, 가중치 토글 시

[공통 진행 방식]

① 요구사항을 기능 목록이 아니라 사용 흐름(누가, 언제, 왜)으로 재구성하고
② 웹 리서치로 그대로 만들면 실패하는 지점을 먼저 찾아
③ 같은 성격의 서비스를 실측한 뒤
④ 발견한 문제를 문서가 아니라 동작하는 기능으로 구현하고
⑤ 브라우저 실측(콘솔 에러 0건·모바일 375px·기능 직접 호출)으로 검증합니다.

서식나루 데모도 같은 과정을 거쳤습니다. 검증 중 검색 결과 표의 고정 헤더가
필터 칩 영역에 가려지는 문제와 파일 형식 표기가 옆 열을 침범하는 문제를 실측으로
잡아 교정했습니다. 이번 프로젝트도 같은 과정으로 진행합니다.
