# AHA! 문법 — 시나리오·사용자 여정

> 샘플 유닛·데이터는 데모용입니다.

## 1. 등장인물
| 인물 | 원하는 것 | 불안한 것 |
|---|---|---|
| 학생 (초·중등) | 게임처럼 가볍게, 막히면 힌트 | 어려운 설명·긴 텍스트·틀리면 혼나는 느낌 |
| 강사(운영자) | 유닛을 직접 만들고 바로 배포 | 개발사에 수정 요청하는 비용·시간 |
| 원장(발주자) | 자체 학원 파일럿 → 타 학원 라이선스 | 1차에 과투자·2차 확장 시 재개발 |
| (2차) 도입 학원 | 체험 후 도입 | — 이번 범위 아님 |

## 2. 학생 여정 (유닛 1개 · 공고 흐름 그대로)
| 단계 | 화면 | 이 설계가 없으면 |
|---|---|---|
| 시작 | 유닛 목록(로그인 없음) | 계정 관리 = 불필요한 비용·개인정보 부담 |
| 몰입 | 커버("탐정처럼 단서를") | 문법 수업 거부감 |
| 참여 | 예시 이모지 선택 | 수동적 시청 — 발견 학습 실패 |
| 추론 | 질문 체인 + 선택 게이팅 | 클릭만 연타하고 지나감 |
| 실수 | **오답 → 1줄 힌트 + 정답 표시 후 진행** | 막혀서 이탈 or 정답 재시도 암기 |
| 이해 | 설명(HUNT) → Aha! 카드 | 발견이 정리로 연결 안 됨 |
| 적용 | 응용 3~4 (랜덤화) | 순서 암기로 통과 (공고가 명시한 우려) |
| 완성 | 백지테스트 안내 + AHA NOTE 인쇄 | 인출 연습 없이 "본 것 같은 느낌"으로 끝 |

## 3. 강사(운영자) 여정 — CMS
| 단계 | 화면 | 데모 동작 |
|---|---|---|
| 유닛 기획 | 등록 폼(프리필) | 공고 폼 필드 전부 — 이모지 팔레트로 예시 구성 |
| 게시 | 게시 버튼 | 승인 없이 학생 앱 목록 즉시 반영 |
| 검수 | 미리보기 | 실제 학생 화면 새 탭(#unit= 딥링크) — 공고 간소화안 |
| 다음 유닛 | 복제 | 기존 유닛 복제 후 수정 — 제작 시간 단축 |
| 관리 | 검색·수정·삭제 | 제목/키워드 검색 |

## 4. 비는 구멍 (착수 미팅 확인)
1. **추론 질문 개수** — 폼은 "추론 질문" 단수 표기지만 레퍼런스는 9개 체인 → 데모는 복수 등록 지원. 유닛당 권장 개수 확정 필요
2. **응용 문항 유형** — 레퍼런스에는 "모두 고르기"형도 있음 → 1차 범위는 단일 선택형 기준인지 확인 (모두 고르기는 +α)
3. **백지테스트 시트 문항** — 고정 템플릿(데모)인지 유닛별 커스텀인지
4. **유닛 공개 범위** — "강사가 지정한 유닛" = 전체 공개 목록인지, 반별 지정인지 (1차는 전체 목록으로 해석)
5. **PWA 오프라인 범위** — 홈 화면 추가만인지, 오프라인 학습까지인지 (데모는 설치 요건까지)
6. **2차 대비 데이터 구조** — 도입 학원 계정·체험 만료를 고려한 유닛/기관 분리 설계 (1차 공수에 반영해 재개발 방지)
7. **호스팅** — 자체 도메인 여부·운영 주체
