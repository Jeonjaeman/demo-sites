# AHA! 문법 — 기획·설계

> 아하(Aha) 문법 — 개발 견적요청 및 진행계획서 v2.0 (1차 MVP) 대응 · 제안용 데모
> 샘플 유닛 콘텐츠는 데모용 예시 — 실서비스 콘텐츠는 운영자가 CMS로 등록

## 0. 발주 문서 요약
- **질문형(추론형) 영어 문법 학습 웹앱 + 강사용 CMS** — 개발자는 '틀'만, 콘텐츠는 운영자가 CMS로 직접
- 1차 목적: 자체 학원 학생 지원(수익화 아님) · 2차: 타 학원 라이선스(추후 별도 발주)
- 지정 레퍼런스: eloquent-bombolone netlify 샘플 앱 — "UI 톤과 인터랙션의 기준"
- 이번 발주 = 1차 MVP만: 학생 웹앱 + CMS(등록/게시)
- 학생 웹앱: 학습 흐름 = 질문→그림/예시 선택→추론 질문→선택형 답변(**오답 시 1줄 힌트만 제공 후 진행**)→설명→Aha! 정리→응용 3~4개→백지테스트 안내 · 이미지 대신 **이모지/고정 아이콘** · 로그인·개인 데이터 없음 · **재학습 시 선택지 랜덤화** · 가능하면 PWA
- CMS: 유닛 등록 폼(제목·핵심질문·예시(이모지)·추론질문·선택지·오답힌트·설명·Aha 문장·응용 3~4) · 게시 즉시 반영 · 복제 · 검색 · 미리보기=학생 화면 새 탭

## 1. 지정 레퍼런스 전수 실측 (★ 재현하고 능가한다)
브라우저로 열어 **20개 화면(.screen) 전체 흐름과 카피를 해부**:
| 축 | 실측값 |
|---|---|
| 색 | bg #F4F7FB · 잉크 #1F2937 · 네이비 #14213D · 블루 #2F66D0 · 오렌지 CTA #FF9F1C |
| 타이포 | 챕터 타이틀 42px/800(블루) · 로고 36px/700 · 본문 카드 중심 |
| 컴포넌트 | .option 선택지 카드(r16·화이트) · .btn-accent(오렌지 r14 h51) · .btn-primary(선택 전 disabled 게이팅) |
| 구조 | 커버 → ASK 1~9(예시 선택→YES/NO 추론 체인) → AHA 발견 → HUNT → APPLY 4종(맞는 표현·모두 고르기·영어의 시선·질문 찾기) → 백지테스트 시트(이름/날짜/문항 4/Teacher Check/PASS·다시 듣기) → AHA NOTE 인쇄 |
| 카피 톤 | 반말 코칭체("탐정처럼 단서를 찾아보자") · "온라인은 발견을 돕고, 이해의 완성은 선생님과의 설명에서" |
| 레이아웃 | max-width 760px · 단일 컬럼 · 섹션 전환형 |

**능가 포인트(공고 신규 요구 반영)**: 진행바 · 오답 1줄 힌트 시스템(레퍼런스에 없음) ·
선택지 랜덤화 · 유닛 목록(다유닛) · CMS 전체 · PWA — 톤은 실측값 그대로 이식.

## 2. 리서치 — 교육학적 근거 (지원 논리)
| 발견 | 근거 |
|---|---|
| 귀납적(발견) 문법 학습은 연역과 최소 동등, 일부 연구에서 유의미하게 우수 — 패턴 자기 발견이 기억·전이에 유리 | [ERIC 비교 연구](https://files.eric.ed.gov/fulltext/EJ1345730.pdf) · [Guided Discovery](https://bridge.edu/tefl/blog/guided-discovery-for-esl/) |
| 백지 인출(retrieval practice)은 재학습 대비 장기 기억 강화 — 백지테스트 마무리 설계의 근거 | [Forward testing effect](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC3983480/) · [KCI 반복인출 연구](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002370881) |
| 발견 학습은 "정보의 양·순서 설계"가 성패 — 유닛 스키마(추론 체인·힌트)가 그 설계 장치 | Guided Discovery 문헌 |

## 3. 구현 — 요구 → 데모 매핑 (레드팀 ④ 체크리스트)
| 공고 조항 | 판정 | 데모 근거 |
|---|---|---|
| 웹앱(브라우저)·태블릿 터치+마우스 | ✓ | 반응형 단일 컬럼·큰 터치 타겟 |
| 학습 흐름 8단계 | ✓ 전부 | 커버→예시 선택→추론 체인→선택형(오답 시 **1줄 힌트만 제공 후 진행** — 재시도 없음)→설명(HUNT)→Aha! 카드→응용 3~4→백지테스트 안내 |
| 이모지/고정 아이콘 (업로드 없음) | ✓ | 예시·팔레트 전부 이모지 — 업로드 로직 없음 |
| 로그인·개인 데이터 없음 | ✓ | 저장하는 개인 데이터 0 (화면에 명시) |
| 재학습 랜덤화 | ✓ | 유닛 시작 시 전 문항 선택지 셔플(정답 추적) — "처음부터 다시"로 즉시 확인 |
| PWA (가능하면) | ✓ | manifest + 최소 서비스워커 — 홈 화면 추가 |
| CMS 등록 폼 (전 필드) | ✓ | 제목·챕터·대표 이모지·핵심질문·예시(이모지 팔레트)·추론(질문/선택지/정답/힌트, 추가 가능)·설명·Aha·틀린 예·응용 3~4(3개 미만 차단) |
| 게시 즉시 반영 (승인 없음) | ✓ | 게시 → 학생 앱 목록 즉시 (localStorage — 실서비스 DB) |
| 복제 | ✓ | 샘플·등록 유닛 모두 복제 가능 |
| 검색 (제목/키워드) | ✓ | 제목·설명·핵심질문 검색 |
| 미리보기 = 학생 화면 새 탭 | ✓ | `#unit=id` 딥링크 새 탭 (공고 간소화안 그대로) |

## 5. 레드팀 4종 검수
- **① 디자인**: 레퍼런스 실측값 그대로 이식(색·radius·CTA·760px) — "레퍼런스를 아는 사람이 봐도 같은 계열"이 기준. 이모지는 공고가 명시한 콘텐츠 수단이므로 사용 (UI 장식 아님)
- **② 인터랙션**: 선택지 stagger 진입·정답 pop/오답 shake·힌트 슬라이드·Aha 카드·진행바 그라디언트·게이팅(선택 전 다음 비활성)
- **③ 실측 QA**: 오버플로 0 · 콘솔 0 · 자동 완주(커버→finish 20턴 내)·오답 힌트 노출·게이팅 확인
- **④ 요구사항 충족(발주 문서 조항별)**: 위 3장 표 11항 전항 ✓ — "오답 시 1줄 힌트만 제공 후 진행"을 문구 그대로(재시도 없음), "미리보기=새 탭 간소화안" 그대로 구현
