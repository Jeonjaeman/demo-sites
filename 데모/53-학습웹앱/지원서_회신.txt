견적서만 드리는 대신, 요청서의 1차 MVP 범위를 그대로 동작하는 데모로
먼저 만들었습니다. 참고 레퍼런스(넷리파이 샘플 앱)를 20개 화면 전부
열어 실측했고, 그 UI 톤과 인터랙션 기준을 그대로 이어서 만들었습니다.

  학생 웹앱 (학습 흐름 8단계 전부 동작)
  https://jeonjaeman.github.io/demo-sites/aha/
  CMS (등록·게시·복제·검색·미리보기)
  https://jeonjaeman.github.io/demo-sites/aha/admin.html

  데모의 샘플 유닛 2개는 앱 '틀' 확인용 예시입니다. 요청서 원칙 그대로
  실제 콘텐츠는 운영자가 CMS로 직접 등록하며, CMS에서 게시하면
  학생 앱에 즉시 나타나는 것까지 데모에서 확인하실 수 있습니다.

[1] 요청서를 이렇게 이해했습니다 (핵심 3가지)

1. "오답 시 1줄 힌트만 제공 후 진행" — 문구 그대로 구현했습니다.
   오답을 고르면 재시도 없이 1줄 힌트와 정답 표시 후 다음으로 진행됩니다.
   막혀서 이탈하지도, 정답을 다시 눌러 외우지도 않는 구조입니다.
   (일부러 틀려보시면 데모에서 바로 확인됩니다)

2. 선택지 랜덤화는 유닛 시작 시점에 전 문항을 섞습니다.
   "처음부터 다시"를 누를 때마다 순서가 바뀌어, 요청서가 우려하신
   "순서 암기로 통과"가 구조적으로 막힙니다.

3. 2차(타 학원 라이선스)를 고려해 데이터 구조를 잡겠습니다.
   1차 범위는 요청서 그대로 지키되, 유닛 데이터에 기관 구분이 들어갈
   자리를 미리 설계해 두면 2차(도입 학원 계정·90일 체험 만료) 때
   재개발 없이 확장됩니다. 1차 공수에 추가 비용 없이 반영하겠습니다.

참고로 이 학습 설계는 교육학적으로도 근거가 있습니다 — 귀납적(발견)
문법 학습은 연역식과 최소 동등하거나 우수하다는 연구가 있고, 마무리의
백지테스트는 인출 연습(retrieval practice)으로 장기 기억에 가장 효과적인
방식입니다. 세미나에서 타 학원을 설득하실 때 쓰실 수 있는 논리입니다.

[2] 1차 MVP 범위 반영 현황 (데모에서 확인)

  학습 흐름 8단계                ✓ 질문→예시 선택→추론→선택형(오답 1줄
                                   힌트)→설명→Aha!→응용 3~4→백지테스트
  이모지/고정 아이콘 (업로드 없음) ✓ 업로드 로직 자체 없음
  로그인·개인 데이터 없음          ✓ 저장 데이터 0
  재학습 랜덤화                   ✓ 시작 시 전 문항 셔플
  PWA (홈 화면 추가)              ✓ manifest+서비스워커
  태블릿 터치 + 마우스             ✓ 반응형·큰 터치 타겟
  CMS 등록 폼 (전 필드)           ✓ 이모지 팔레트·추론/응용 동적 추가
  게시 즉시 반영 (승인 없음)       ✓ 게시→학생 앱 목록 즉시
  복제 / 검색                     ✓
  미리보기 = 학생 화면 새 탭        ✓ 요청서 간소화안 그대로
