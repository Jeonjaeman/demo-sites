[프로젝트 개요]
- 광고대행사 매칭 플랫폼 1차 MVP 구축

[프로젝트 배경 및 목표]
- 소상공인과 광고대행사를 연결하는 역경매형 매칭 플랫폼입니다. 소상공인이 광고 요청서를
  등록하면 카테고리가 일치하는 광고대행사가 제안서를 제출하고, 소상공인이 제안서를 비교하여
  대행사를 선정하는 구조로 서비스를 운영합니다.

[과업 범위]
1. 수행 범위
- 상세 기획: 요청서-제안서 매칭 플로우 설계, 광고 카테고리(대/소분류) 체계 설계, 화면별 필드
  단위 기획
- UI/UX 디자인
- 프런트엔드/Client 개발
- 백엔드 개발
- 서버/DB/인프라 구성

2. 상세 기능 요구 사항

2-1. 소상공인(클라이언트) 기능
- 회원가입 및 로그인: 이메일 인증 기반의 일반 회원가입 및 로그인 기능. 카카오/네이버 소셜
  로그인은 2차 확장 기능으로 별도 개발
- 마이페이지: 내 정보 조회·수정 및 등록한 요청 내역 조회 기능
- 광고 요청 등록: 필드 단위 요청서 작성 기능(상세 필드는 2-4 참조)
- 제안서 목록 조회 및 비교: 가격순, 평점순 정렬 및 카테고리, 예산 조건 필터 기능
- 대행사 프로필 조회: 포트폴리오, 리뷰, 평점, 사업자 인증 여부 확인 기능. 리뷰는 1차 오픈 시
  관리자가 수동으로 등록
- 대행사 최종 선정 및 매칭 확정: 소상공인 계정에서만 매칭 확정 액션을 트리거할 수 있도록 제한
- 알림 수신: 이메일 및 카카오 알림톡을 통한 알림 발송(앱 미개발에 따라 푸시 알림은 2차 확장
  기능으로 제외)

2-2. 광고 대행사 기능
- 회원가입 및 로그인: 사업자등록증 인증 절차를 포함한 회원가입 및 로그인 기능
- 대행사 프로필 등록 및 관리: 포트폴리오 및 전문 분야 등록 기능
- 광고 요청 목록 조회 및 필터링: 카테고리, 예산 등 조건별 필터 기능
- 제안서 작성 및 제출: 상세 필드는 2-5 참조
- 선정 결과 알림 수신: 매칭 확정 여부에 대한 알림 수신 기능

2-3. 관리자(어드민) 기능
- 회원 관리: 가입 승인 및 사업자 인증 심사 기능
- 카테고리 관리: 광고 카테고리 대분류 및 소분류 등록·수정 기능
- 매칭 관리: 요청서-제안서 매칭 현황 모니터링 기능
- 신고 관리: 어뷰징 대응을 위한 최소 수준의 신고 접수 및 처리 기능
- 리뷰 관리: 1차 오픈 시 관리자가 리뷰를 수동으로 등록하는 기능(정식 리뷰 작성 기능은 2차 확장)
- 통계 조회: 엑셀 다운로드 형태의 기초 통계 제공(별도 통계 대시보드 개발은 2차 확장)

2-4. 광고 요청서 등록 화면
- 광고 카테고리(대분류): 단일 선택, 필수, 검색광고/SNS광고/콘텐츠(블로그·바이럴)/영상(유튜브)/
  홈페이지·디자인 중 선택
- 광고 카테고리(소분류): 대분류에 종속된 단일 선택, 필수
- 업종: 단일 선택 및 직접 입력 병행, 필수
- 마케팅 목적: 다중 선택, 필수, 매출 증대/브랜드 인지도/신규 고객 유입/재방문 및 리텐션 중 선택
- 예산 범위: 구간 선택, 필수, 월 50만원 이하/50~100만원/100~300만원/300만원 이상
- 희망 진행 기간: 단일 선택, 필수, 1개월/3개월/6개월/협의 후 결정
- 상세 요청 내용: 텍스트 입력(최대 1,000자), 필수, 작성 가이드용 placeholder 제공
- 참고 자료 첨부: 이미지 또는 PDF 파일 업로드(최대 3개), 선택
- 지역: 주소 검색 입력, 선택, 매장 방문이 필요한 업종 대상
- 제안서 접수 마감일: 날짜 선택, 필수, 등록 시점 기준 7일 후로 기본 설정
- 연락처 공개 동의: 체크박스, 필수, 매칭 확정 시에만 연락처가 공개됨을 명시
- 운영 정책: 요청서 1건당 수신 제안서 상한을 5건에서 10건 사이로 설정하여 대행사 과당 경쟁 및
  소상공인의 선택 피로도를 방지

2-5. 대행사 제안서 제출 화면
- 견적 금액: 숫자 입력, 필수, 월 단가 또는 총액 기준으로 입력하며 VAT 별도임을 표기
- 실행 전략(제안 요약): 텍스트 입력(최대 800자), 필수
- 세부 실행안: 텍스트 입력 및 파일 첨부(상세 기획서 PDF), 선택
- 예상 소요 기간: 단일 선택, 필수, 착수 시점부터 성과 발생 예상 시점까지의 기간
- 포트폴리오 첨부: 파일 또는 링크 첨부, 필수(최소 1건), 유사 업종 사례 우선 노출
- 담당 매니저 정보: 텍스트 입력, 필수, 이름/직급/경력 연차 포함
- 제안 유효기간: 날짜 입력, 필수, 등록 시점 기준 7일로 기본 설정
- 운영 정책: 대행사 등급(신규/인증/우수)에 따라 제안서 노출 우선순위를 차등 적용하여 초기
  입점사 확보 인센티브로 활용

2-6. 매칭 프로세스 및 권한 정책
- 소상공인의 요청서 등록, 카테고리 일치 대행사 그룹에 대한 알림 발송, 대행사의 제안서 제출,
  소상공인의 제안서 목록 비교, 대행사 프로필 확인, 매칭 확정, 연락처 상호 공개의 순서로
  프로세스를 구성
- 매칭 확정 액션은 소상공인 계정에서만 트리거 가능하도록 제한하며, 대행사가 임의로 매칭을
  확정할 수 없도록 하여 어뷰징을 방지
- 매칭 확정 시 소상공인과 대행사 양측의 연락처 및 담당자 정보가 상호 공개되며, 이후 계약 및
  상담은 플랫폼 외부에서 진행

- (기타 필수 공통 사항)
- 정산 절차는 1차 MVP 범위에서 제외하며, 매칭 확정 이후 수수료 정산은 계좌이체 및 수기
  인보이스를 통한 오프라인 방식으로 임시 운영
- 카카오 알림톡 API 및 이메일 발송 시스템을 연동하여 요청서 등록 알림, 대행사 그룹 알림,
  선정 결과 알림을 발송

[기술/제조 스택]
- 플랫폼 형태: 반응형 웹(Responsive Web) 단일 플랫폼으로 구현하며, Android/iOS 네이티브 앱은
  1차 범위에서 제외
- 프런트엔드: React 또는 Next.js 기반 개발
- 백엔드: Node.js(NestJS) 또는 Django 기반 개발
- 데이터베이스: PostgreSQL 또는 MySQL 등 관계형 데이터베이스 사용
- 인프라: AWS 또는 네이버클라우드(NCP) 환경에서 구성
- 알림 연동: 카카오 알림톡 API 및 SendGrid와 같은 이메일 발송 서비스 연동
- 파일 저장소: S3 또는 이에 준하는 오브젝트 스토리지 사용
- 향후 확장 참고: 2차 확장 시 Android/iOS 앱은 Flutter 기반 크로스플랫폼으로 개발 예정이므로,
  해당 확장 대응이 가능한 개발사를 우대

[주요 일정]
