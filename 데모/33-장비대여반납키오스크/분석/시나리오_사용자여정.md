# ALLEND 올렌드 — 시나리오·사용자 여정

장비 목록을 **시간순 사용 흐름**으로 재구성한 문서입니다.
> ⚠ 모든 인물·장비·데이터는 가상입니다.

---

## 1. 등장인물

| 인물 | 누구 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| **시각장애 이용자** (65세, 저시력) | 복지관에서 태블릿을 빌리려는 어르신 | 화면을 못 봐도 **혼자** 빌리고 싶다 | "직원을 불러야 하나", "카드번호가 음성으로 새어나갈까" |
| **청각·지체장애 이용자** (휠체어) | 행사용 마이크를 빌리려는 방문자 | 화면에 **손이 닿고**, 터치 없이 **물리버튼**으로 조작 | "화면이 너무 높다", "터치가 안 눌린다" |
| **비장애 이용자** | 노트북을 잠깐 빌리려는 학생 | **빠르게** 대여·반납 | "줄이 길다", "무인이라 헷갈린다" |
| **운영 담당자**(기관 직원) | 재고·내역 관리, **접근성 검증 통과** 책임 | 재고 정확성·**납품 검증 통과** | "지급 디자인이 검증을 통과할까", "탈락하면 누구 책임" |
| **개발사(우리)** | SW 납품 | 명확한 범위·규격 | "디자인·HW가 지급인데 접근성 책임까지 떠안나" |

**역할 겸임 주의**: 운영 담당자는 **재고 관리자**이자 **접근성 검증 대응 주체**입니다.
두 역할이 겹치는 지점이 관리자 화면의 "검증 진단"입니다.

## 2. 시간순 여정 — 시각장애 이용자(대여)

| 단계 | 상황 | 쓰는 화면 | 이 기능이 없으면 |
|---|---|---|---|
| 발견 | 키오스크 앞에 섬 | 홈 | 무엇을 눌러야 할지 모름 → 이탈 |
| 판단 | 화면이 안 보임 | **음성안내 ON** | 직원 호출 없이는 이용 불가(= 차별) |
| 행동 | 터치 위치를 모름 | **물리버튼 모드** — 이전/다음으로 초점 이동, 음성이 현재 항목 낭독 | 터치만이면 시각장애인 조작 불가 |
| 선택 | 태블릿 고름 | 분류→장비→기간 | 초점 순서 없으면 원하는 항목 도달 불가 |
| 대기 | 결제 진행 | 결제(카드) — **카드번호 음성 미낭독** | 개인정보 음성 유출 = 검증 위반 |
| 실행 | 대여 완료 | 완료 — 대여번호 **음성 안내** | 반납 시 번호를 못 외움 |
| 사후 | 반납 | 대여번호 키패드(**5번 촉각 돌기**) 또는 최근 대여 | 촉각 기준점 없으면 번호 입력 불가 |

## 2-b. 휠체어 이용자(반납)

| 단계 | 상황 | 쓰는 화면 | 없으면 |
|---|---|---|---|
| 접근 | 화면이 높음 | **화면낮춤(휠체어)** — 콘텐츠 하단 정렬 | 화면 정보 1220mm 초과 시 도달 불가 |
| 조작 | 손 힘이 약함 | 큰 터치타깃(≥12mm) · 물리버튼 | 작은 버튼은 작동력 초과로 못 누름 |
| 반납 | 마이크 반납 | 반납 확정 → 재고 복구 | 상태 갱신 안 되면 다음 사람이 품절로 오인 |

## 3. 역할별 시야 차이 (= 권한 설계 핵심)

같은 "재고 데이터"를 역할별로 다르게 봅니다.

| 데이터 | 이용자 화면 | 관리자 화면 |
|---|---|---|
| 재고 | "남은 수량 / 품절" (빌릴 수 있나) | 9종 전체 바·가용률·**키오스크 실연동** |
| 대여 내역 | 내 대여번호만 | 전체 내역·**CSV 반출**·상태 |
| 접근성 | 툴바로 **이용** | **검증 진단**(지급 디자인이 기준을 통과하나) |
| 카드번호 | 마스킹·미낭독 | 마스킹만 저장(원문 미보유) |

## 4. 기능별 존재 이유 (전수 매핑)

| 기능 | 왜 있나(어느 인물의 불안을 없애나) |
|---|---|
| 음성안내(TTS) | 시각장애 이용자가 **혼자** 이용 → 직원 호출=차별 방지 |
| 물리버튼 로빙 포커스 | 터치 불가 이용자가 **전 기능 도달**(공고 "터치 없이 조작") |
| 고대비/글자확대 | 저시력·고령 이용자 가독성(명도대비 4.5:1·글자 12mm) |
| 화면낮춤 | 휠체어 이용자 화면 도달(1220mm 이하) |
| 카드번호 마스킹·음성 예외 | 개인정보 화면표시·낭독 금지(검증 위반 방지) |
| 응답시간 표시·연장·해제 | 조작이 느린 이용자 이탈 방지(타임아웃 금지 원칙) |
| 대여번호 키패드 5번 돌기 | 촉각 기준점으로 시각장애 입력 지원 |
| 재고 실연동 | 관리자·다음 이용자에게 정확한 가용 상태 |
| **검증 진단** | 운영 담당자가 **지급 디자인의 검증 통과 여부를 착수 전 확인** |
| **책임 분계표** | 개발사·기관이 **접근성 책임 경계를 계약 전 합의** |

## 5. 비는 구멍 (미팅에서 정의 필요)

시나리오를 그리자 정의가 없는 예외가 드러났습니다.

1. **연체·미반납** — 대여 기간 초과 시? 보증금 차감? 알림 수단(무인이라 SMS 연동 주체)?
2. **파손·분실 반납** — 반납 시 상태 확인은 무인으로 불가 → 직원 확인 프로세스 필요.
3. **재고 원천** — 재고가 키오스크 내부 값인가, 상위 자산관리 시스템 API인가? 동시 대여 충돌 처리 주체?
4. **결제 실패·부분 취소** — 카드 승인 실패, 대여 후 즉시 취소 시 환불.
5. **접근성 검증 탈락** — 지급 디자인·HW가 기준 미달일 때 재작업 주체·비용·일정.
6. **다국어** — 공공기관 특성상 외국인 이용? (현재 데모는 국문)
7. **점자·수어** — 청각장애용 수어 영상, 시각장애용 점자 라벨은 HW·콘텐츠 영역.
8. **오프라인/장애 복구** — 네트워크 끊김 시 대여 가능 여부, 로컬 큐.

> 이 구멍들은 **화면이 아니라 정책·계약**으로 메워야 합니다. 데모는 발견을 화면으로 보였고,
> 결정은 미팅에서 이뤄져야 합니다.
