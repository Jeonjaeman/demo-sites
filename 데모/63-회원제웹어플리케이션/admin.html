RLS 성능 시뮬레이터 — 70명에선 안 보이고 4,000명에서 죽습니다

naive한 auth.uid() 정책은 행마다 함수를 재평가합니다. Supabase 공식 실측 배율(11,000ms→10ms, 인덱스 100배)을 계수로 회원 규모별 예상 응답을 계산합니다.

정책 진단기 — 무한 재귀(42P17) 좌우 대조

등급을 profiles에서 서브쿼리하는 정책을 profiles 자신에 걸면 자기를 다시 호출합니다. 실행해 보세요.

naive — profiles 서브쿼리

CREATE POLICY read_profiles ON profiles FOR SELECT USING ( (SELECT grade FROM profiles -- ← 자기 자신 WHERE id = auth.uid()) >= 1 );

수정 — JWT 클레임 (Custom Access Token Hook)

CREATE POLICY read_profiles ON profiles FOR SELECT TO authenticated USING ( ((SELECT auth.jwt()) -> 'app_metadata' ->> 'grade')::int >= 1 -- 테이블 조회 없음 );

유출본 역추적 — 워터마크 토큰 → 열람자 특정

커뮤니티 자료실에서 다운로드하면 파일에 토큰이 각인됩니다. 유출본에서 읽은 토큰을 입력하면 발급 이력에서 열람자가 특정됩니다. (방금 커뮤니티에서 다운로드했다면 그 토큰을 넣어 보세요 — 데모 프리필: WM-K7Q2XN)

인프라 설정 — 리전 하나가 법적 의무를 만듭니다

Supabase는 해외 서비스지만 서울 리전을 고르면 국외이전에 해당하지 않습니다. 리전은 생성 후 변경이 번거로우므로 착수 1일차에 확정합니다.

플랜·백업·월 비용 — "자동 암호화 백업"은 유료 플랜 전제

무료 플랜에는 자동 백업이 없고 7일 미사용 시 프로젝트가 일시정지됩니다. 공고의 비기능 요구를 충족하려면 Pro가 전제이며, 이는 의뢰자 부담 항목입니다.

소셜로그인 검수 — 개발이 끝나도 검수를 통과해야 열립니다

카카오는 Supabase 네이티브지만 이메일 수집은 비즈앱 전환(사업자등록번호)이 선행됩니다. 네이버는 기본 프로바이더가 아니라 Custom OIDC로 직접 연동하며 검수에 3~4영업일이 걸립니다. 의뢰자 담당 항목이 표시됩니다.

활동 로그 — UI 기능이 아니라 법정 접속기록(1년 보존)

누가 언제 어떤 회원 정보를 열람했는지까지 남아야 법정 요건을 충족합니다. 관리자 본인의 열람도 기록 대상입니다. 보존기간 내 삭제는 차단됩니다.
