# INCIRCLE — 시나리오·사용자 여정
## 등장인물
가입 신청자(승인 언제·내 정보 어디로 불안) / 1등급(왜 못 보나) / 2등급(워터마크에 내 이름=유출자 몰림 불안·열람 감시 불안) / 3등급 자료 제공자(캡처 유출·탈퇴자 보유 불안) / 관리자=발주자 1인(IT 경험 없음 — 매일 승인?·신고 법적 처리?·개발자 이탈 후 유지 불안)
★ 관리자와 3등급이 동일인일 가능성 높음 → 요구에 없는 **뷰 스위칭(회원 시야 미리보기)**이 필수 — 데모의 「계정 상태 전환기」가 이것.

## 여정 (없으면 벌어지는 일)
발견(안이 안 보임→신청 안 함: Skool식 About 표면) → 신청(수집 항목=네이버 검수 기재 의무) → **대기(이탈 1순위 — 공개 라운지 1종+SLA)** → 승인/거절(거절 통보·재신청 규칙 없으면 관리자 카톡으로 문의 직행) → 첫 진입(70명 콜드스타트) → 활동 → 등급 상승(기준 비공개면 문의 폭주: 자동 승급 규칙 공개) → 보호 열람(워터마크·이력, **단 유튜브 임베드엔 적용 불가**) → 유출 사고(오버레이 워터마크면 추적 불가→역추적 화면) → 신고(44조의2: 양측 통지·공시·D-30) → 제재/탈퇴(게시물 3안) → 확장(4,000명에서 naive RLS 사망)

## 역할별 시야 차이 (RLS 설계 축)
같은 posts 테이블을 6주체가 다르게: 비로그인=공개 1종 미리보기 / **대기=로그인 됐지만 0건(핵심)** / 1등급=3종 / 2등급=5종+워터마크 열람 / 3등급=6종+다운로드 / 관리자=블라인드 원문 포함하되 **개인정보는 마스킹된 채**(서버측 마스킹의 1순위 수혜자는 관리자 화면). 등급은 72칸 매트릭스(6판×3급×4액션)로만 정의됨.

## 비는 구멍 (미팅 확인)
