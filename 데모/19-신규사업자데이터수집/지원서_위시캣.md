# 위시캣 지원서 — 신규 사업자 데이터 수집 및 DB 저장 프로그램 개발

> 아래 내용을 위시캣 지원 폼에 붙여넣으세요. 데모 링크는 ASCII 별칭이라 폼에서 잘리지 않습니다.

---

안녕하세요. 공고를 검토하다 **그대로 개발하면 1차 수집부터 막히는 지점**을 발견해서, 대안까지 반영한 데모를 먼저 만들어 왔습니다.

- 관리자 콘솔 데모: https://jeonjaeman.github.io/demo-sites/bizseed/

**먼저 짚어드릴 3가지 (착수 전 확인 필요)**

1. **국세청 API로는 신규 사업자 "목록"을 받을 수 없습니다.** 해당 API는 사업자등록번호를 입력하는 진위확인·상태조회 전용이라 목록을 내려주지 않습니다. → 주 소스를 **행정안전부 LOCALDATA 인허가 데이터**로 재설계했습니다. 209종 업종의 **일 변동분**을 API로 받을 수 있어 "어제 신규 개업" 목록이 그대로 나옵니다. 국세청 API는 휴·폐업 검증 단계로 붙입니다.
2. **연락처의 상당수는 크롤링 없이 확보됩니다.** 인허가 원천에 소재지 전화번호가 포함된 업종이 많아, 크롤링은 미확보 건에만 도는 보조 배치로 줄였습니다. 개발 공수·서버 비용·차단 리스크가 함께 내려갑니다.
3. **두낫콜 대조가 빠져 있습니다.** 전화권유판매는 방문판매법 §42에 따라 월 1회 이상 수신거부 확인 의무가 있고, 위반 시 과태료가 최대 1,000만원입니다. 이 대조가 없으면 완성된 리스트를 영업에 쓰기 어렵습니다. → 파이프라인 마지막 단계에 넣었습니다.

※ 요구사항의 "IP 우회"는 정보통신망법상 침입죄가 인정된 판례가 있어, 우회 모듈 대신 **준법 수집**(robots 준수·요청 간격 제한·실패 코드 기록)으로 설계했습니다.

**데모에서 바로 확인되는 것 (요구사항 전 항목):**

- 대시보드 — 일자별 수집 건수, 연락처 확보율, 6단계 파이프라인, 배치 실행 로그 (요구사항 2-3)
- 사업자 목록 — 상호·주소·사업자번호 검색 + 업종/지역/연락처 유무 필터, 엑셀(.xlsx) 다운로드
- 실패 사유 코드 — E101~E301 코드별 건수와 재시도 큐 (요구사항 2-2)
- 파이프라인 — 스케줄러 5개 잡, 소스 3종 상태, 수동 실행 시 로그 실시간 출력
- DB 스키마 — 6개 테이블 정의서 화면 (산출물 그대로)
- 개인정보 안전조치 — 연락처 기본 마스킹, 반출 감사 로그, 보관기간 자동 파기

**유사 프로젝트 경험**

같은 방식으로 작업한 데이터 수집·관리 도구들입니다. 모두 직접 만든 것이고 지금 바로 열어 보실 수 있습니다.

- **교직문화 설문 수집·시각화** — https://jeonjaeman.github.io/demo-sites/classpulse/dashboard/
  응답 1,284건을 실제로 집계하는 대시보드. 소규모 집단이 개인 식별될 수 있는 문제를 자동 마스킹으로 차단했습니다.
- **연구용 대화 데이터 수집 플랫폼** — https://jeonjaeman.github.io/demo-sites/labchat/admin/
  수집 데이터를 CSV로 반출하는 구조. 동시 접속 시 데이터가 유실되는 저장 방식을 잡아내 SQLite로 재설계했습니다.
- **키워드·리드 수집 백오피스** (본 데모) — https://jeonjaeman.github.io/demo-sites/bizseed/

세 건 모두 **수집 → 정제 → 적재 → 반출** 파이프라인과 관리자 화면이 핵심이라, 이번 과업과 구조가 같습니다.

**저희가 잘하는 것**

- 웹디자이너 출신이라 **화면 설계에 강합니다.** 이런 수집 프로그램은 결국 관리자가 매일 보는 한 화면에서 성패가 갈립니다. 데모처럼 "오늘 몇 건 걸 수 있나"가 한눈에 보이는 콘솔을 만듭니다. 관리자 매뉴얼·화면 설계서(산출물)도 직접 제작합니다.
- **피드백 반영이 빠릅니다.** AI 도구를 반복 작업(화면 퍼블리싱·스키마 정의·테스트 데이터 생성)에 활용해, 수정 요청을 대개 **당일 반영**합니다. 이 데모도 그 방식으로 단기간에 만들었습니다.
- 오픈 후 **월 단위 운영 지원**도 가능합니다. 수집 대상 사이트 구조가 바뀌면 크롤러가 멈추므로, 이런 프로젝트는 인수인계로 끝나지 않습니다.

**견적**

| 항목 | 내용 |
|---|---|
| 단가 | 일 100,000원 |
| 기간 | 40일 |
| **총액** | **4,000,000원** (VAT 별도) |

공고 기간은 30일이지만, **1주차에 데이터 소스 실증을 넣기 위해 40일로 잡았습니다.** 국세청 API로는 신규 사업자 목록을 받을 수 없다는 점(위 1번)을 실제 수집으로 먼저 확인해야, 남은 일정에서 헛수고가 없습니다.

**공수 산정 근거**

| 작업 | 일수 |
|---|---|
| 데이터 소스 실증 · 스키마 설계 · 요구사항 확정 | 7일 |
| LOCALDATA 수집 배치 · 중복 제거 · 국세청 검증 연동 | 9일 |
| 연락처 보강(준법 크롤링) · 실패 코드 · 재시도 큐 | 7일 |
| 두낫콜 대조 · PII 마스킹 · 보관기간 파기 배치 | 5일 |
| 관리자 화면 · 필터 · 엑셀 반출 · 감사 로그 | 8일 |
| 안정화 · 산출물 3종 · 인수인계 | 4일 |
| **합계** | **40일** |

포함: 상세 기획(수집 주기·대상·스키마) · 수집 스크립트 · 공공 API 연동 · 스케줄러 · DB 설계/구축 · 관리자 화면 · 엑셀 다운로드 · **두낫콜 대조 및 개인정보 안전조치** · 산출물 3종(테이블 정의서 · 관리자 매뉴얼/화면 설계서 · 원본 소스)

> 공고 예산 1,000만원 기준으로는 여유가 있어, **남는 범위를 리스크 대응에 배정**했습니다. 두낫콜 대조와 PII 마스킹은 공고에 없던 항목이지만 이게 빠지면 수집한 리스트를 영업에 쓰기 어렵습니다. 추가 비용 없이 포함합니다.

**의뢰자 부담 영역 (견적 외 실비):**

- 클라우드 서버·DB 호스팅 비용 (월 실비, 초기 기준 월 5~10만원 수준)
- 공공데이터포털·LOCALDATA API 키 발급 (무료, 신청 절차는 저희가 대행)
- 도메인·SSL (관리자 화면 외부 접속이 필요한 경우)
- 두낫콜 조회 연동 시 발생하는 절차·비용 (사업자 명의 필요)
- 수집 데이터의 활용 범위에 대한 법적 판단 및 책임

일정은 1주차 **데이터 소스 실증**(LOCALDATA 실수집으로 확보율 검증) → 2~3주차 수집·검증·보강 배치 → 4주차 두낫콜 대조·개인정보 안전조치 → 5주차 관리자 화면·엑셀 → 6주차 안정화·산출물·인수인계로 진행합니다.

1주차 실증 결과(실제 연락처 확보율)를 보고 크롤링 범위를 함께 조정하는 방식을 제안드립니다. 확보율이 높게 나오면 크롤링 비중을 줄여 그만큼 안정성에 쓸 수 있습니다.

먼저 1주차 실증 결과(실제 확보율)를 보고 크롤링 범위를 조정하는 방식을 제안드립니다. 미팅에서 데모를 함께 보며 논의드리고 싶습니다. 감사합니다.
