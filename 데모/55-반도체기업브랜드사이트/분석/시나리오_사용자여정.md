# REONIX — 시나리오 · 사용자 여정

> 기능 목록이 아니라 "이 사이트를 누가 왜 보는가"로 재구성. 모든 인물·데이터는 가상.

## 1. 등장인물

| 인물 | 누구인가 | 원하는 것 | 불안한 것 |
|---|---|---|---|
| 구매 담당 (국내 대기업 협력사) | 벤더 후보 실사 전에 웹 검색 | 회사가 실재하고 기술이 있는지 5분 안에 판단 | 영세해 보이면 벤더 등록 품의가 안 올라감 |
| 해외 바이어 | 전시회 명함으로 사이트 방문 | 제품군·서비스 범위·인증 확인 | 낡은 사이트 = 품질 관리도 낡았다는 인상 |
| 채용 지원자 (엔지니어) | 면접 전 회사 조사 | 성장하는 회사인지, 설비 수준 | 정보 없는 회사는 지원 우선순위에서 밀림 |
| 의뢰자(발주사) 대표 | 사이트를 "회사의 얼굴"로 | 영업 미팅 전에 먼저 보여줄 수 있는 수준 | 템플릿 티 나는 결과물에 100만원 쓰는 것 |

## 2. 핵심 통찰 — B2B 제조업 사이트는 "전환"이 아니라 "검증"용

방문자는 구매하러 오지 않는다. **거래해도 되는 회사인지 검증**하러 온다.
따라서 메인이 해야 할 일은 딱 세 가지:
1. **규모감·정밀함의 인상** (히어로 영상·핀 스크럽 같은 프로덕션 퀄리티) — 첫 7초
2. **제품·서비스·산업 커버리지** 한 화면 훑기 (sec3~sec5)
3. **신뢰 신호** (R&D·인증·연혁·채용 = 살아있는 회사) (sec6~sec8)
레퍼런스(한빛산업)가 정확히 이 구조이고, 데모는 이를 반도체 제조로 재해석했다.

## 3. 시간순 여정

| 단계 | 상황 | 화면 | 없으면 |
|---|---|---|---|
| 도착 (0~7초) | 검색/명함으로 진입 | sec1 팹 영상 + 대형 타이포 | 스톡 이미지 히어로 → "여느 중소기업" 인상에서 시작 |
| 훑기 (7~30초) | 스크롤 시작 | sec2 스크럽(브랜드 한 문장) → sec3 산업 | 정적 나열이면 스크롤 이탈 |
| 검증 1 (30초~) | "우리 품목 하나?" | sec4 제품 5열 — 호버로 상세 | 제품 정보가 얕으면 이탈 → 경쟁사 검색 |
| 검증 2 | "제조만? 서비스도?" | sec5 서비스 3종 | 수탁/테스트 단독 수주 기회 유실 |
| 신뢰 확인 | "기술력 있는 회사인가" | sec6 R&D · sec7 Merit | 인증·연구 신호 없으면 벤더 실사 통과 불리 |
| 행동 | 문의 or 채용 지원 | sec8 배너·(실작업: 문의 폼) | CTA 없으면 방문이 성과로 안 이어짐 |

## 4. 메뉴 구조 (실작업 시 페이지 트리 = 메가 메뉴 그대로)

About Us(6) · Products(5군 × dep3) · Industries(3군) · Service(3군) · R&D(3) · Resources(3) · Careers(1)
— 데모 메가 메뉴의 dep2/dep3가 곧 사이트맵 제안이다. 공고의 "사이트맵 구성" 요구에 대한 답.

## 5. 기능별 존재 이유

| 기능 | 존재 이유 |
|---|---|
| 풀 비디오 히어로 | 첫 7초의 규모감 — B2B 검증 심리의 출발점 |
| sec2 핀 스크럽 확장 | 브랜드 문장을 "읽게 만드는" 장치. 스크롤을 멈추지 않게 함 |
| 제품 flex 확장 | 5개 제품군을 한 화면에 — 호버만으로 상세 미리보기 |
| 서비스 배경 스왑 | 텍스트 리스트를 공간감 있는 경험으로 |
| 메가 메뉴 | 사이트 전체 규모를 미리 보여주는 지도 = 회사 규모감 |
| 메뉴 클릭 토스트 | 데모 범위(메인만)를 정직하게 알림 — 완성 착시 방지 |
| 뷰포트 밖 영상 정지 | 영상 3개 동시 재생으로 인한 저사양 기기 발열·프레임 저하 방지 |

## 6. 비는 구멍 — 착수 전 확인

1. **회사 실자산**: 로고·CI·실제 설비/제품 사진 보유 여부 (없으면 AI 생성·일러스트로 대체 — 데모 방식)
2. **연혁·조직도 원고**: 공고에 "타임라인·다이어그램 출력" 요구 — 원고와 조직 정보는 의뢰자 제공 필요
3. **제품 스펙 표**: 품목 수·스펙 항목 수에 따라 상세 페이지 템플릿 설계가 달라짐
4. **문의 메일 수신 주소·스팸 대책**: 서버리스 폼 사용 시 수신 주소 확정, 자동응답 여부
5. **지도**: 네이버/카카오/구글 중 택1 (해외 바이어 고려 시 구글 병기 권장)
6. **다국어**: 공고에 없음 — 반도체 B2B 특성상 영문 페이지 수요 확인 (2차 범위 제안)
7. **도메인·호스팅 계정**: 산출물 "도메인 연결 완료" 요구 — 계정 소유는 의뢰자 명의 권장
