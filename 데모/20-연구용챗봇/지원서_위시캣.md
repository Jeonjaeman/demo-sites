# 위시캣 지원서 — 연구용 챗봇 웹 서비스 구축 OpenAI API 연동

> 아래 내용을 위시캣 지원 폼에 붙여넣으세요. 데모 링크는 ASCII 별칭이라 폼에서 잘리지 않습니다.

---

안녕하세요. 요구사항을 검토하다 **연구 데이터가 통째로 날아갈 수 있는 지점**을 발견해서, 대안까지 반영한 데모를 먼저 만들어 왔습니다.

- 참가자 화면 데모: https://jeonjaeman.github.io/demo-sites/labchat/
- 연구자 콘솔 데모: https://jeonjaeman.github.io/demo-sites/labchat/admin/

**먼저 짚어드릴 3가지 (착수 전 확인 필요)**

1. **Streamlit + 단일 CSV는 동시 참가자에서 데이터가 유실됩니다.** 커뮤니티와 이슈 트래커에 단일 CSV를 DB처럼 쓰면 동시 사용자 환경에서 동작하지 않는다는 점, 참가자 간 데이터가 섞이는 사례가 보고되어 있습니다. 모집 공고 직후 참가자가 몰릴 때 하필 데이터를 잃게 됩니다. → **CSV 산출물 형식은 그대로 두고 저장 계층만 SQLite로 바꿉니다.** 파일 하나로 관리되는 건 동일하고(별도 DB 서버 불필요), 쓰기가 트랜잭션으로 직렬화되어 유실이 없습니다.
2. **모델 버전을 고정하지 않으면 실험 중간에 자극이 바뀝니다.** `gpt-4o` 같은 별칭을 쓰면 OpenAI가 백엔드를 갱신할 때 앞 참가자와 뒤 참가자가 다른 조건에서 응답한 셈이 되어, 데이터를 논문에 쓰기 어려워집니다. → **날짜 스냅샷을 고정**하고 응답마다 모델 ID·temperature·seed·프롬프트 버전을 함께 저장합니다. 방법론 절에 그대로 옮겨 적으실 수 있습니다.
3. **참가자 사전 동의(IRB) 절차가 요구사항에 없습니다.** 대화 데이터 수집은 인간대상연구에 해당하고, 온라인 진행이라는 이유로 동의가 면제되지 않습니다. → **첫 화면을 온라인 동의 절차로 구성**했습니다(목적·수집항목·보관기간·철회권 고지, 동의 시각과 버전 기록).

※ 그 외 단순 무작위 배정의 집단 불균형(→ 가변 블록 무작위화), 새로고침 시 대화 소실(→ 매 턴 즉시 저장), 자유 대화 속 개인정보 유입(→ 저장 직전 자동 마스킹)도 함께 반영했습니다.

**데모에서 바로 확인되는 것 (요구사항 전 항목):**

- 참가자 ID 입력 → 형식 검증 + 1인 1회 참여 제한 (요구사항 2-1, 2-3)
- ChatGPT UI를 실측 카피한 채팅 화면 + 스트리밍 응답 (요구사항 2-1)
- 4개 집단 배정 — **같은 질문이라도 조건에 따라 답변 스타일이 실제로 달라집니다** (A 조언만 / B 공감+조언 / C 조언+근거 / D 전부)
- 연구자 콘솔 — 집단별 프롬프트 편집(저장 시 버전 자동 기록), 참가자 목록, 대화 로그 뷰어 (요구사항 2-3)
- **CSV 다운로드는 실제 파일이 받아집니다** — 10개 컬럼, UTF-8 BOM으로 엑셀 한글 정상 (요구사항 2-2, 2-3)

**저희가 잘하는 것**

- 웹디자이너 출신이라 **화면 완성도에 강합니다.** 참가자가 어색함을 느끼면 대화 데이터의 질이 떨어지므로, "ChatGPT 디자인 참조"는 이 프로젝트에서 미관이 아니라 데이터 품질 문제입니다. 데모는 ChatGPT의 CSS 변수를 실측해 그대로 옮겼습니다.
- **피드백 반영이 빠릅니다.** AI 도구를 반복 작업에 활용해 수정 요청을 대개 **당일 반영**합니다. 연구는 프롬프트와 문항이 마지막까지 바뀌므로 이 부분이 중요합니다.
- 모집 시작 후에도 **연락이 닿습니다.** 실험 기간 중 문제가 생기면 즉시 대응합니다.

**견적**

| 항목 | 내용 |
|---|---|
| 단가 | 일 100,000원 |
| 기간 | 21일 |
| **총액** | **2,100,000원** (VAT 별도) |

공고 기간은 14일이지만, **파일럿 회차와 IRB 동의 절차를 넣기 위해 21일로 잡았습니다.** 모집을 시작한 뒤에는 되돌릴 수 없어서, 실제 참가자 5명으로 리허설하는 기간이 반드시 필요합니다.

**공수 산정 근거**

| 작업 | 일수 |
|---|---|
| 설계 확정(동의서·프롬프트·데이터 스키마) | 3일 |
| 참가자 챗 UI · OpenAI 스트리밍 연동 | 5일 |
| 블록 무작위 배정 · 세션 복구 · PII 마스킹 | 4일 |
| 연구자 콘솔(프롬프트 버전 관리 · 집단 균형 · CSV 반출) | 5일 |
| **파일럿 테스트**(참가자 5명 리허설) 및 보정 | 2일 |
| 산출물 2종 · 인수인계 | 2일 |
| **합계** | **21일** |

포함: 화면 설계 · 참가자 챗봇 · OpenAI API 연동(스트리밍·**모델 스냅샷 고정**) · 4개 집단 배정 · **SQLite 저장 계층**(동시 접속 유실 방지) · **IRB 온라인 동의 절차** · 연구자 콘솔(프롬프트 편집·버전 기록·CSV 반출) · 산출물 2종(실행 소스 코드·사용 가이드)

> 공고 예산 300만원 기준으로 여유가 있어, **남는 범위를 데이터 손실 방지에 배정**했습니다. 저장 계층 교체·세션 복구·파일럿 회차는 공고에 없던 항목이지만, 이게 빠지면 모집 초기에 데이터를 잃습니다. 추가 비용 없이 포함합니다.

**의뢰자 부담 영역 (견적 외 실비):**

- **OpenAI API 사용료** (참가자 수 × 대화 턴 수에 비례하는 종량 과금) — 예산 상한 설정과 사용량 모니터링은 개발 범위에 포함합니다
- 서버 호스팅 비용 (월 실비, 단일 VM 기준 월 2~5만원 수준)
- 도메인·SSL (외부 참가자 모집 시 필요)
- IRB 심의 신청 및 승인 (연구자 소속 기관 절차) — 동의 화면 문구는 승인받으신 내용으로 반영해 드립니다
- 집단별 시스템 프롬프트 초안 및 연구 시나리오 (공고의 클라이언트 준비 사항)

일정은 1~3일 설계 확정(동의서·프롬프트·스키마) → 4~8일 참가자 챗봇·스트리밍 → 9~12일 배정·저장 계층·세션 복구 → 13~17일 연구자 콘솔·CSV → 18~19일 **파일럿 테스트(참가자 5명 리허설)** → 20~21일 산출물·인수인계로 진행합니다.

일정을 14일로 맞춰야 하신다면 파일럿 회차를 빼고 조정할 수 있습니다. 다만 **모집 시작 후에는 되돌릴 수 없으므로** 리허설을 넣어 두시길 권해 드립니다.

본 모집을 시작한 뒤 문제를 발견하면 되돌릴 수 없으므로, 파일럿 회차를 일정에 넣어 두는 것을 권해 드립니다. 미팅에서 데모를 함께 보며 논의드리고 싶습니다. 감사합니다.
