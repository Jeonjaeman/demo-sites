# LABCHAT 랩챗 — 연구용 실험 챗봇 플랫폼 (데모)

학술 연구용으로 참가자를 **4개 실험 집단에 무작위 배정**하고, 챗봇과의 대화를 수집해
**CSV로 반출**하는 MVP의 제안용 데모입니다.

> 원 요청: [연구용 챗봇 웹 서비스 구축 OpenAI API 연동.txt](./연구용%20챗봇%20웹%20서비스%20구축%20OpenAI%20API%20연동.txt) (예산 300만 · 14일 · 기획 상태 "아이디어만 있는 상태")

## 체험 시나리오 (데모 포인트)

1. **연구 동의** — 3개 항목을 모두 체크해야 다음으로 넘어갑니다. 동의 시각과 동의서 버전이 기록됩니다.
2. **참가자 ID** — `P1042` 형식 검증, 같은 ID로 두 번 참여하면 차단됩니다.
3. **조건 배정** — 가변 블록(4/8) 무작위화로 A~D 중 하나에 배정됩니다. 새로고침 후 다시 하면 다른 조건이 나옵니다.
4. **챗 대화** — ChatGPT UI 그대로. 응답이 한 글자씩 스트리밍됩니다. **같은 질문이라도 배정 조건에 따라 답변 스타일이 실제로 달라집니다** (A 조언만 / B 공감+조언 / C 조언+근거 / D 공감+조언+근거).
5. **PII 마스킹** — 대화에 전화번호나 이메일을 넣어 보세요. 저장 시 자동 마스킹된다는 안내가 뜹니다.
6. **최소 턴 제한** — 6턴을 채우기 전에는 종료 버튼이 잠겨 있습니다.
7. **연구자 콘솔** — 집단 균형(±1명), 프롬프트 편집 시 버전 자동 기록, **CSV 다운로드는 실제 파일이 받아집니다** (10개 컬럼, UTF-8 BOM으로 엑셀 한글 정상).

## ⚠️ 착수 전 반드시 확인이 필요한 항목

리서치 결과, 공고의 스택을 그대로 구현하면 **모집 초기에 데이터를 잃습니다.**

- **Streamlit + 단일 CSV는 동시 참가자에서 유실됩니다** — 커뮤니티·이슈 트래커에 단일 CSV를 DB처럼 쓰면 동시 사용자 환경에서 동작하지 않는다는 점과, 참가자 간 데이터가 섞이는 사례가 보고되어 있습니다. → **CSV 산출물 형식은 유지한 채 저장 계층만 SQLite로 교체**했습니다.
- **모델 스냅샷을 고정하지 않으면 실험 중간에 자극이 바뀝니다** — `gpt-4o` 별칭 대신 날짜 스냅샷(`gpt-4o-2026-05-13`)을 고정하고 응답마다 모델·temperature·seed·프롬프트 버전을 저장합니다.
- **참가자 사전 동의(IRB) 절차가 없습니다** — 온라인이라는 이유로 동의를 면제받을 수 없습니다. 첫 화면을 동의 절차로 구성했습니다.
- 그 외 단순 무작위 배정의 집단 불균형, 새로고침 시 세션 소실, 자유 대화 속 개인정보 유입을 함께 반영했습니다.

자세한 근거와 대안은 [분석/기획_설계.md](분석/기획_설계.md) 2장을 참고하세요.

- **[Qualtrics](https://www.qualtrics.com/)** — 연구자 콘솔 톤. 배경 `#EDF2F4` · 퍼플 `#601AE5` · pill 버튼(999px) fw600
- **[Prolific](https://www.prolific.com/)** — 참가자 온보딩 타이포 (56/64, ls −1.4px, fw500) · 블루 `#0F2BC9`

인터랙션: 스트리밍 타이핑 + 캐럿 · 3점 바운스 인디케이터 · 메시지 진입 애니메이션 · 집단 균형 바 · 자동 높이 컴포저(Enter 전송 / Shift+Enter 줄바꿈)

## 기술 구성 (데모)

- 순수 HTML/CSS/JS 정적 사이트 — 빌드 불필요, 반응형
- 블록 무작위 배정·동의 기록·중복 참여 차단은 localStorage로 지속
- CSV는 Blob으로 **실제 파일 생성** (쉼표·따옴표 이스케이프, UTF-8 BOM)
- 챗봇 응답은 조건별 문장 조합 + 키워드 라우팅 (실서비스: OpenAI API 스트리밍)
- 모든 참가자·대화·수치는 **가상 데이터**입니다

실서비스 제안 스택: Streamlit(유지) + SQLite(저장 계층) + OpenAI Python SDK (기획_설계.md 5장 참조)
