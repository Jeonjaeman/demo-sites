[1] 중고차 수출 영업관리 + 바이어 입찰 (본 공고 대응 데모)
https://jeonjaeman.github.io/demo-sites/excaro/
https://jeonjaeman.github.io/demo-sites/excaro/sales/
https://jeonjaeman.github.io/demo-sites/excaro/buyer/

- 진행 과정
  공고 분석 → 제도·API 리서치(국토부 자동차종합정보 API의 소유자
  동의 요건과 운영 심의 절차, 카마트 시세의 B2B 계약 구조, 알림톡
  템플릿 심사 리드타임) → 도메인·디자인 레퍼런스 실측 → 세 표면
  (소비자 랜딩·영업팀 어드민·바이어 어드민) 구현 → 브라우저 실측
  검증까지 진행했습니다. 검증 중에 발견한 버그(사진 카운터가 숫자가
  아닌 문자열로 누적돼 "1"+"1"="11"이 되던 문제, 입력 중 리렌더로
  포커스가 튀던 문제)도 수정해 두었습니다.

- 특징
  이 프로젝트의 핵심은 화면이 아니라 "정보를 누구에게까지 보여줄
  것인가"입니다. 고객정보·비교견적·폐차견적을 CSS로 숨기면 개발자
  도구로 전부 보이고, 바이어가 차주에게 직접 연락하는 순간 중개
  구조가 무너집니다. 그래서 프론트에서 가리는 대신 바이어 응답
  객체에서 해당 필드를 아예 제거했습니다. 바이어 화면 콘솔을 열어
  직접 확인하실 수 있습니다.

- 핵심 요소
  마감 3시간 내 입찰이 들어오면 5시간 자동 연장되는 소프트 클로즈
  (스나이핑으로 낙찰가가 내려가는 것을 막는 경매 표준 방식), 서버
  시각 기준 마감 판정과 마감 후 입찰 거부, 영업팀·바이어 두 화면을
  나란히 열면 입찰이 실시간으로 흐르는 동기화, 동의 체크 전에는
  조회가 잠기는 국토부 API 동의 게이트, ERP 전송 멱등키·재시도,
  블라인드 입찰(내 순위만 표시)과 재입찰 2회 제한.

[2] 학원 통합 관리 시스템 (실운영 구축 · 권한 3단계)
https://jeonjaeman.github.io/dojang-live/

- 진행 과정
  데모가 아니라 실제 계약해 운영까지 올린 프로젝트입니다. 기존
  노션·자동화도구 조합의 문제(학생별 공개 링크의 유출·검색 노출

  만들었습니다. Supabase RLS와 서버 함수로 권한을 데이터베이스
  계층에 두어, 프론트를 우회해도 남의 데이터가 나오지 않습니다.

- 특징
  이번 프로젝트의 팀장·직원·바이어 3단계 권한과 정확히 같은 문제를
  다뤘습니다. 강사는 담당 반만, 학부모는 자기 자녀만, 내부 메모는
  비노출 — 역할 전환 데모로 실제 다른 화면이 나오는 것을 확인할 수
  있습니다. 권한을 화면 조건문이 아니라 응답 계층에서 처리한다는
  원칙이 [1]의 바이어 정보 차단과 동일한 설계입니다.

- 핵심 요소
  출결 키오스크(번호/QR·서버 시각 기준 지각 자동판정 — 클라이언트
  시계를 신뢰하지 않는 구조가 이번 입찰 마감 판정과 같습니다),
  결제 내역 매칭 시 동명이인은 자동 처리하지 않고 수동확인 대기로
  두는 오매칭 방지, 알림톡 발송 파이프라인과 이력, 통계 실계산과
  CSV 산출, 학부모용 무로그인 24시간 만료 토큰 링크.

[3] 신규 사업자 리드 자동수집 파이프라인 (외부 API 연동)
https://jeonjaeman.github.io/demo-sites/bizseed/

- 진행 과정
  "매일 신규 개업 사업자를 자동 수집한다"는 요구를 받고, 착수 전
  국세청 API 명세를 실제로 확인했습니다. 그 결과 해당 API는 사업자
  번호를 넣어 상태를 조회하는 용도일 뿐 신규 사업자 목록 자체를
  제공하지 않는다는 것을 확인했고, 1차 수집원을 지자체 인허가
  공개데이터로 바꾸는 대안을 설계에 반영했습니다.

- 특징
  이번 프로젝트에서 국토부 API와 카마트 API를 다루는 방식이 정확히
  이 경험입니다. 연동은 "붙인다"가 아니라 "무엇을 주지 않는지를
  먼저 확인한다"가 먼저입니다. 국토부는 소유자 동의와 운영 심의,
  카마트는 B2B 계약 리드타임이 실제 병목이라 두 건 모두 일정에
  선행 배치하고 폴백 경로를 함께 설계했습니다.

- 핵심 요소
  6단계 수집 파이프라인과 스케줄러 잡 상태, 실패 사유 코드(E101~
  E301)별 집계와 재처리, 개인정보 마스킹 기본값과 해제 시 감사
  로그 기록, 두낫콜 대조로 발신 금지 건 분리, 현재 필터 조건 그대로
  나가는 엑셀 반출과 반출 이력, DB 스키마 정의서를 화면으로 제공.

[4] 세미나 예약·결제 플랫폼 (정원 동시성 처리)
https://jeonjaeman.github.io/demo-sites/seminar56/
https://jeonjaeman.github.io/demo-sites/seminar56/admin/

- 진행 과정
  전국 56개 지역을 순회하는 세미나의 모객·예약·결제·알림 자동화
  플랫폼입니다. 요구대로 지역 페이지를 복제하면 공통 문구 한 줄
  수정에 56곳을 고쳐야 한다는 점을 계산해 보여주고, 커스텀 포스트
  타입 단일 템플릿 구조를 대안으로 제시했습니다.

- 특징
  좌석 정원과 입찰은 같은 동시성 문제입니다. 가상계좌를 선택하면
  입금 전 24시간 좌석을 홀딩해야 하는데, 이 홀딩분을 정원에서
  빼지 않으면 초과 예약이 발생합니다. 잔여 = 정원 − 확정 − 입금
  대기로 계산하고 0이 되면 버튼이 실제로 잠깁니다. 이번 프로젝트의
  동시 입찰·마감 처리에 그대로 적용되는 설계입니다.

- 핵심 요소
  슬라이더 조작 시 실시간 재계산되는 수익 계산기, 3단계 예약 폼
  (필수값 누락 시 실제 차단), 알림톡 템플릿 심사 상태 관리(승인·
  심사중·반려와 반려 사유 노출 — 이번 프로젝트에서 심사 공백을
  SMS 폴백으로 메운 근거), 환불 처리와 UTF-8 BOM CSV 실파일 산출.
