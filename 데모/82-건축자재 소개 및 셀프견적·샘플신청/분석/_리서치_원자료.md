> **한 줄 결론**: 이 공고의 실패 지점은 "계산기를 못 만든다"가 아니다.
> ① "사이즈 입력 → 개수"는 **공식이 아니라 제품 데이터 문제**다. 같은 MCM이라도 판 크기가 575×286부터 2600×1300까지, 박스당 5~20장으로 다르고, 줄눈·패턴·창문 공제에 따라 결과가 1~2박스씩 달라진다. 계산 기준이 코드에 박히면 신제품마다 개발자가 필요하다 — 의뢰자가 공고에 적은 우려 그 자체다.
> ② 포미스톤은 **외장재**다. 방화마감 의무 건축물(3층 이상·높이 9m 이상 등)의 외벽에 덧붙이면 **대수선**이고, 현장에서 단열재 등과 결합하면 **실물모형시험** 대상이다(법제처 2023.6.27 해석). 해외 A1 인증은 국내 시험성적서가 아니다. 셀프견적이 "외벽 48㎡ → 3박스"만 내주고 끝나면 안 된다.
> ③ 바이브 코딩 + 무료 호스팅의 기본값이 **운영을 멈춘다**. Vercel 무료는 상업 이용 금지, Supabase 무료는 1주 비활성 시 정지·백업 없음, Cloudflare Pages는 파일당 25MiB라 카탈로그 PDF가 안 올라간다. AI로 만든 앱의 약 10%가 DB 권한 미설정으로 고객 주소가 열려 있었다(Lovable).
> ④ 해외 제조사 홍보 문구(음이온·탄소 58% 감축·A1 불연)를 번역해 옮기면 **표시광고·환경성 표시** 위반 소지가 있다(2024.5 페인트 6사 '라돈 저감' 광고 시정명령).

### F01. "사이즈 입력 → 개수"는 공식 하나로 안 된다 — 판형·박스·줄눈·패턴·개구부가 제품 데이터다

- **등급**: P1 (그대로 만들면 틀린 숫자를 낸다)
- **내용**
  - PHOMI MCM 제품군은 판 크기와 박스 단위가 제품마다 다르다 [확인 — 검색 요약, ArchiExpo 본문은 403]: Rockface 880×580×4mm·20장/박스·10.21㎡ · Savana 2600×1300×3~8mm·5장/박스·16.90㎡ · Concerto 8장/박스·5.76㎡ · Spider 5장/박스·17.00㎡(박스 외형 2650×1350) · Mist는 575×286과 1150×575 **두 판형**. 태국 판매처는 60×120·60×135·120×240cm 판형을 판매 [확인 ✓ HomePro]. 두께는 대체로 2~4mm [확인 — 검색 요약].

  - 개구부(창·문) 공제 여부만으로 1박스(16.9㎡) 차이가 난다 [계산 7-4 예시 2].

### F02. 바이브 코딩 산출물의 전형적 실패 — 데이터가 코드에 있고, 관리자가 없거나, 관리자가 열려 있다

  1. **계산 = 데이터 검증까지** — 박스 외형 오입력 경고, 판형 1:N, 줄눈·패턴·개구부·부자재 (F01).
  2. **외장재의 법적 분기** — 외벽 선택 시 건물 높이를 묻고 견적에 '방화 검토' 플래그 (F05).
  3. **문구 통제** — 근거 없는 '불연·친환경'은 게시되지 않는 편집기 (F06).
  4. **운영비 0원 + 의뢰자 명의** — 상업 허용 무료 구성 + 유료 전환 기준 (F03·F17).
  5. **사진 권리** — 출처·동의 없으면 공개되지 않는 사례 등록 (F08).

### 7-2. 계산식

입력: 벽 i (가로 a_i, 세로 b_i, m) · 개구부 j (가로 w_j, 세로 h_j, 수량 q_j) · 시공 위치(실내/외벽) · 패턴 p · 판형 v

1. 총 면적 `A_gross = Σ a_i × b_i`
2. 공제 면적 `A_open = Σ w_j × h_j × q_j` — 설정값 "공제 최소 면적 t" 미만 개구부는 제외 (기본 t = 0, 전부 공제) [제안]
3. 순 면적 `A_net = A_gross − A_open` — `A_open > 0.8 × A_gross`면 "개구부 입력을 확인해 주세요" 경고
4. 모듈 면적 `m = (W + g) × (H + g) / 10⁶` — g는 위치별 줄눈(실내 g_in / 외벽 g_out)
5. 필요 장수 `N = ceil( A_net × (1 + L_p) / m − 1e-9 )` (부동소수 오차 보정)
6. 박스 수 `B = ceil( N / n )` · 남는 장수 `B × n − N` · 주문 면적 `B × n × W × H / 10⁶`
7. 부자재 `ceil( A_net × c_min / 포대 kg )` ~ `ceil( A_net × c_max / 포대 kg )` (범위로 표기)
8. 출력: 순 면적 · 로스 포함 면적 · 장 · 박스 · 남는 장수 · 부자재 · **계산 근거**(적용 로스율·줄눈·공제 면적·판형) · 외벽 방화 플래그(F05) · 계산에 쓴 제품 데이터의 수정일(견적 의뢰 시점 재현용)

설계 판단 [제안]
- 로스율은 **순 면적에 곱한다**. 개구부 주변 재단 손실은 로스율 안에 포함된 것으로 본다(표준품셈 할증률도 재료량 기준).
- **대형 판(장당 1㎡ 초과)** 은 자투리 재사용이 어려워 면적법이 과소 산출될 수 있다 → 결과 아래 "판 배치 기준 참고 M장"(열 = ceil(가로/W'), 행 = ceil(세로/H'), 두 방향 중 작은 값)을 함께 보여 주고 "대형 판은 현장 실측 후 확정" 문구를 붙인다.
- 결과는 항상 **장·박스·㎡ 세 단위를 동시에** 보여 준다(공고의 "개수"가 장인지 박스인지 모호).

### 7-4. 계산 예시 (데모 프리필 — 제품명은 가상)

**예시 1 — 거실 아트월** · 가상 「스톤시트 S-1260」 1200×600 · 8장/박스(5.76㎡) · 실내 줄눈 0 · 일자 10%
- A = 4.2 × 2.4 = **10.08㎡** → × 1.10 = 11.088 → ÷ 0.72 = 15.40 → **16장 → 2박스**(남는 0장, 주문 11.52㎡) [계산]
- 로스 없이 계산하면 14장 → 같은 2박스. 박스 단위가 로스를 흡수한 경우.
- 접착제 10.08 × 1.5~2.5 = 15.1~25.2kg [계산]

**예시 2 — 주택 외벽 정면 덧방** · 가상 「대형시트 L-2613」 2600×1300 · 5장/박스(16.90㎡) · 외벽 줄눈 2mm → m = 2.602 × 1.302 = 3.3878㎡ · 일자 10%
- A_gross = 8.0 × 6.0 = 48.00㎡ · 창 1.2×1.5×3 = 5.40㎡ · 현관 0.9×2.1 = 1.89㎡ → **A_net = 40.71㎡** [계산]
- 40.71 × 1.10 = 44.781 → ÷ 3.3878 = 13.22 → **14장 → 3박스**(남는 1장) [계산]
- **개구부를 공제하지 않으면** 48 × 1.10 = 52.8 → 15.59 → 16장 → **4박스** → **1박스(16.9㎡) 과주문** [계산]
- 판 배치 기준 참고: 가로 4열 × 세로 5행 = 20장(개구부 미반영) → "대형 판은 현장 실측 후 확정" [계산]
- 2층·높이 6m 단독주택 → 외벽 방화마감 의무 기준(3층 이상·9m 이상)에 해당하지 않음 안내. 같은 입력에 '3층'을 넣으면 F05 안내 카드가 뜬다.

**예시 3 — 벽돌형 포인트월** · 가상 「브릭 B-2406」 240×60 · 60장/박스(0.864㎡) · 실내 줄눈 10mm → m = 0.25 × 0.07 = 0.0175㎡ · 일자 10% · 면적 10㎡
- 10 × 1.10 = 11 → ÷ 0.0175 = 628.6 → **629장 → 11박스**(660장, 남는 31장) [계산]
- **줄눈을 무시하면** 11 ÷ 0.0144 = 763.9 → 764장 → **13박스** → **2박스(약 21%) 과다** [계산]

**데이터 오입력 예시** — 판 3.40㎡ 제품(Spider와 같은 구성)에 박스 외형 2650×1350(3.578㎡)을 판 크기로 넣으면 필요 장수가 약 5% 적게 나온다(3.40 ÷ 3.578 = 0.950). 관리자 저장 시 5장 × 3.578 = 17.89㎡ vs 입력 ㎡/박스 17.00 → 5.2% 차이 → 경고 [계산].

### 7-5. 입력·데이터 검증 규칙

- 벽 치수 0.1~50m · 단위 토글(m/cm) · 1,000 이상 입력 시 "mm로 입력하셨나요?" 확인.
- 개구부 합이 벽 면적의 80%를 넘으면 경고. 같은 벽에 개구부가 벽보다 크면 차단.
- 관리자: |n × W × H / 10⁶ − ㎡/박스| ÷ ㎡/박스 > 2% → 경고 · 로스율 0~50% · 줄눈 0~20mm · 박스당 장수 정수.
- 견적 의뢰 저장 시 계산 입력값 + 사용한 제품 데이터 스냅샷 저장 → 나중에 제품 데이터가 바뀌어도 그 견적의 계산을 재현.

## 12. 의뢰자 기획의 잘된 부분

1. **우려를 정확히 짚었다.** "오픈 후 우리가 직접 갱신할 수 있나"가 이 프로젝트의 성공 기준이다. 대부분의 의뢰자는 오픈만 생각하는데, 이 의뢰자는 운영을 먼저 걱정했다.
2. **메뉴 구성안과 메뉴별 참고 레퍼런스를 이미 준비했다.** "아이디어만"이라고 했지만 IA의 뼈대는 있다. 첫 미팅 시간을 자료 해석이 아니라 결정에 쓸 수 있다.
3. **시공사례 ↔ 사용 자재 ↔ 연계 사례를 요구했다.** 국내 건자재 사이트들이 시공사례를 1차 메뉴로 두는 이유(사례 = 판매 증거)를 정확히 담았다(F13).
4. **셀프견적을 견적 의뢰로 이어지게 했다.** 계산이 끝이 아니라 상담 유입으로 연결되도록 설계한 점이 좋다.
5. **첫 미팅을 대면으로 잡았다.** 자재는 실물을 봐야 판형·두께·박스 구성을 정확히 받을 수 있다. 계산기 데이터 확보에 유리하다.
