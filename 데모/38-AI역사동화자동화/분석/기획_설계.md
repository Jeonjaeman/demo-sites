# YEODAM 여담 — 기획·설계

여주 관광 체험 플랫폼 **본구축 전 PoC** — AI 역사동화 자동 생성 · 삽화 · PDF 전자책 파이프라인
브랜드: **YEODAM 여담**(여주 + 이야기譚) · 별칭 `/yeodam`
> ⚠ 모든 텍스트·삽화·이력은 가상 예시입니다.

---

## 0. 한 줄 요약

공고는 "AI로 역사동화·삽화·PDF를 자동 생성하는 파이프라인의 **품질과 소요 시간을 검증**"하는 PoC를 원합니다.
그런데 이 파이프라인은 **아동 대상 + 역사 콘텐츠 + AI 생성 + 정부지원사업**이 겹치는 자리라,
"잘 만든다"보다 **네 가지 지뢰**를 먼저 밟지 않는 것이 PoC의 성패입니다 —
① AI 생성물의 **저작권 불성립**, ② AI의 **역사 왜곡(환각)**, ③ **아동 개인정보·안전**, ④ 삽화 **캐릭터 일관성**.
이 데모는 넷을 전부 **동작하는 기능**으로 구현했습니다 — 승인 팩트 DB 기반 **사실 검증 게이트**(환각 시 PDF 발행 차단),
**아동 안전 가드레일**, **저작권 대응 생성이력**, **레퍼런스 고정 캐릭터 일관성**. 그리고 삽화가 병목임을
**단계별 계측**으로 실증합니다.

## 1-b. 숨은 니즈 (공고 문장에서 도출)

- "본 구축에 앞서 … 품질과 소요 시간을 검증" + 우선순위 **1순위 산출물 완성도** →
  이 PoC는 곧 **본구축 수주 심사용 제안서**. 데모의 완성도가 곧 다음 계약.
- "정부지원사업 … 세금계산서·행정서류 필수" → **산출물 저작권 귀속**이 계약 리스크.
- "여주 역사 콘텐츠 원천 데이터(클라이언트 제공)" → 생성은 **원천으로 그라운딩**해야 하고,
  그렇지 않으면 AI가 역사를 지어냄(환각). 원천 대조 장치가 필요.
- "월 단위 유지보수·고도화 예정" → 프롬프트·팩트 DB를 **운영자가 직접 관리**할 수 있어야 함.

## 2. 웹 리서치 — 치명적 발견 (근거 URL)

### 발견 ① (치명) AI 단독 생성물은 **저작권이 성립하지 않을 수 있음** — 정부지원이라 귀속도 문제
한국 저작권법·판례상 저작권은 **인간의 창작적 개입**이 있어야 인정됩니다. AI가 단독 생성한 동화·삽화는
보호받지 못할 수 있어, 여주시가 전자책을 배포·2차 이용할 때 **무단복제 방어가 불가**할 위험이 있습니다.
문체부 「생성형 AI 저작권 안내서」는 **생성 과정 기록·인간 기여 구분**을 등록·분쟁의 근거로 봅니다.
게다가 **정부지원 산출물**은 국가연구개발혁신법 등에 따라 귀속(발주처-개발사 공동 등)이 정해집니다.
- 문체부 생성형 AI 저작권 안내서(정리): https://ditoday.com/gai-copyright/
- 정부용역 SW 산출물 저작권 귀속: https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002356426
- 국가연구개발혁신법(성과 귀속): https://www.law.go.kr/LSW/lsInfoP.do?lsId=013774
→ 데모: 실행마다 **프롬프트·모델·시각·인간 검수**를 생성이력에 기록(관리자 CSV). "AI가 다 만든 게 아니라
  승인 팩트로 그라운딩하고 사람이 검수했다"를 데이터로 남겨 저작권·귀속 대응.

### 발견 ② (치명) AI는 **역사를 지어냄(환각)** — 아동 대상이라 더 위험
생성형 AI는 출처·연도·사실을 그럴듯하게 지어냅니다(hallucination). 아동은 비판적 검증 능력이 부족해
**틀린 역사를 그대로 흡수**합니다. "세종대왕이 명성황후에게…"처럼 시대가 어긋난 문장이 동화에 섞이면
여주의 공식 콘텐츠로 배포되어 교육적 오류가 됩니다.
- 학생의 생성형 AI 사용과 환각 위험(CDT): https://cdt.org/insights/students-use-of-generative-ai-the-threat-of-hallucinations/
- 역사 교육 AI 가이드라인(AHA): https://www.historians.org/resource/guiding-principles-for-artificial-intelligence-in-history-education/
→ 데모: **승인 여주 팩트 DB**(인물·활동 세기·장소·유물)로만 그라운딩하고, 생성문을 대조하는
  **사실 검증 게이트** — 근거 없는 연도, 승인 밖 인물, **세기 차 큰 인물 공존**(예: 세종 15C × 명성황후 19C)을
  검출하면 **승인 전 PDF 발행을 차단**. '환각 주입' 토글로 실제로 잡아내는 것을 실증.

### 발견 ③ 아동 **개인정보·안전** — 개인정보보호법 §22의2
만 14세 미만 아동의 개인정보 처리는 **법정대리인 동의**가 원칙입니다(이름 정도는 최소정보일 수 있으나,
아동 대상 서비스는 보호 강화 대상). 또 생성물이 아동에게 부적절하지 않도록 **유해표현 필터**가 필요합니다.
- 개인정보보호법 제22조의2(아동의 개인정보 보호): https://casenote.kr/법령/개인정보_보호법/제22조의2
→ 데모: 이름은 **브라우저 로컬에서만 사용·서버 미저장**, 법정대리인 안내, **가드레일 필터 실동작**.

### 발견 ④ (기술) 삽화 **캐릭터 일관성** — 페이지마다 주인공 얼굴이 바뀜
AI 삽화의 최대 난점은 장면마다 주인공이 달라지는 것입니다. seed/reference로 해결합니다.
- 캐릭터 일관성(레퍼런스 기법): https://carat.im/blog/character-consistency-update
→ 데모: **기준 캐릭터 시트를 레퍼런스로 고정**하고 모든 장면을 그 참조로 생성 —
  표지·영릉·도자기·명성황후 생가에서 동일한 아이+여우가 유지됨(실제 생성 에셋으로 실증).

### 기술 함정 — 한글 PDF
클라이언트 PDF 생성 시 **한글 폰트 임베딩**이 까다롭습니다.
→ 데모: 각 페이지를 **캔버스로 래스터라이즈**(한글은 브라우저 폰트로 그려짐)한 뒤 JPEG로 PDF에 임베드 →
  폰트 임베딩 문제 없이 **외부 라이브러리 0개**로 오프라인 PDF 생성.

## 4. 화면 구성

### 사용자 파이프라인 (`index.html`)
1. **입력** — 아이 이름 + 여주 관광지 다중 선택 + 개인정보 안내 + `환각 주입(데모)` 토글
2. **파이프라인 계측** — 6단계(초대장·동화·사실검증·가드레일·삽화·PDF) 실측 타이머 + 비용 + **병목(삽화)** 강조
3. **안전 게이트** — 역사 사실 검증 / 아동 가드레일 결과(통과·실패)
4. **동화 뷰어** — 표지+페이지, 삽화+텍스트, 페이지 넘김(back-out)
5. **PDF 발행** — 실제 PDF 다운로드(게이트 통과 시만) + 저작권 이력 기록 안내

### 관리자 콘솔 (`admin.html`)
- **프롬프트 테스트 환경** — 3종 프롬프트 수정 → 결과 즉시 테스트
- **여주 팩트 DB + 사실 검증기** — 승인 목록 + 문장 직접 검사
- **소요시간·비용 시뮬레이터** — 페이지 수 슬라이더 → 삽화 병목 실증
- **아동 가드레일** — 사전 편집·테스트
- **생성 이력·저작권** — 프롬프트·모델·시각·검수 기록 + CSV
- **캐릭터 일관성** — 레퍼런스 + 장면 에셋

## 5. 제안 스택 & 일정 (견적)

**스택 제안**: 프론트 React/Vite + 백엔드 Node(or FastAPI). 텍스트 OpenAI(GPT), 삽화 이미지 생성 API(레퍼런스 고정),
PDF는 서버 렌더(Puppeteer) 또는 클라이언트 캔버스(본 데모 방식). **핵심은 모델이 아니라 그라운딩·검증·이력 레이어**.

## 6. 착수 전 확인(미팅 안건)

1. **여주 원천 콘텐츠 범위·정확성** — 팩트 DB로 정제할 원본(인물·연도·장소)의 출처·검수 주체.
2. **산출물 저작권 귀속** — 정부지원 산출물의 IP 귀속·2차 이용 범위를 계약에 명시.
3. **아동 개인정보** — 이름 외 수집 항목 여부, 법정대리인 동의 절차(실서비스).
4. **삽화 비용 상한** — 페이지 수·해상도·재생성 정책(원가 대부분). 캐싱·사전제작 여부.
5. **모델 스냅샷** — 텍스트/이미지 모델 버전 고정(재현성) 및 교체 시 회귀 검증.
