### 1-2. 문서 행간의 숨은 니즈

- **"구글 폼·스프레드시트로 하는데 분석·취합이 번거롭다"** → 진짜 불편은 파일 관리가 아니라 **매년 같은 수작업을 반복하는 것**입니다. 그래서 "설문을 웹으로 옮기기"보다 **문항을 자산으로 관리하고 결과가 자동으로 쌓이는 구조**가 핵심입니다.
- **"응답자 개인이 식별되지 않도록"** (개인정보 유의사항) → 이 한 줄이 이 프로젝트에서 가장 무거운 요구입니다. 교장·교감은 학교당 1명이라 지역·학교 단위로 쪼개는 순간 개인이 특정됩니다. 요구사항의 "지역별 집계"와 정면으로 충돌하므로, 시스템이 자동으로 막아 주지 않으면 사고가 납니다.
- **"매년 10~12월 실시, 2년 가까이 축적"** → 이미 과거 데이터가 있습니다. **연도 간 비교 가능성**(문항 동일성)이 확보되지 않으면 축적 데이터의 가치가 사라집니다.
- **"IT 프로젝트 관리 경험 없음" + "아이디어만 있는 상태"** → 기술 검토 전 초안이므로, 개발사가 통계·개인정보 쟁점을 먼저 정리해 드려야 합니다.
- **30일 / 300만원** → 범위 확장 여지가 없습니다. 화면 수를 늘리기보다 **틀리면 조사 전체가 무효가 되는 지점**(익명성·대표성)에 공수를 집중하는 편이 맞습니다.

## 2. 웹 리서치 — 의뢰자가 놓친 부분 (전부 데모에 반영)

### ① 학교·직위로 쪼개면 응답자가 특정됩니다 (치명적)

요구사항은 지역·학교급별 집계를 요구합니다. 그런데 **교장·교감은 학교당 각 1명**이므로, 직위 필터와 지역 필터를 겹치면 그 수치는 곧 특정 개인의 응답입니다. 익명 조사에서 이는 신뢰 붕괴로 직결되고, 다음 회차 응답률까지 떨어뜨립니다.

통계적 노출 통제(cell suppression)에서는 **최소 셀 크기 5~10명**을 두고 미달 시 수치를 억제하는 것이 표준이며, 다른 셀에서 역산 가능한 값도 함께 가리는 **보완 억제**를 적용합니다.

**대안 (데모 적용):** 최소 응답 수 **5명**을 시스템에 강제했습니다. 필터 결과가 미달이면 수치 대신 "표본 부족(비공개)"으로 자동 대체되고, CSV 반출·KPI·차트에 일괄 적용됩니다. 데모에서 **직위를 '교장'으로 두고 지역 기준 교차표**를 보시면 5개 지역 중 4개가 자동 비공개 처리됩니다.

### ② 자발적 응답의 단순 평균은 "전국 교사 의견"이 아닙니다

구글 폼처럼 링크를 배포해 받는 방식은 **자기선택 편향**이 있습니다. 관심 있는 교사가 더 많이 응답하고, 지역·학교급·직위 비율이 모집단과 어긋납니다. 이 상태의 단순 평균을 전국 결과로 발표하면 대표성을 지적받습니다. 표준적 보정 방법은 **사후층화 가중(post-stratification)** 입니다.

**대안 (데모 적용):** 교육통계 모집단 비율(지역·학교급·직위)을 기준으로 사후층화 가중을 산출하고, 대시보드에서 **켜고 끌 수 있는 토글**로 넣었습니다. 누르면 수치가 실제로 달라집니다. 극단 가중은 0.3~3.0으로 트리밍했고, CSV에도 가중 적용 여부가 함께 기록됩니다.

### ③ 문항이 바뀌면 연도별 추이가 깨집니다

"매년 반복되는 문항을 시스템에서 관리"가 요구사항인데, 문구가 조금만 바뀌어도 이전 연도와 같은 것을 측정했다고 보기 어렵습니다. 추이 그래프를 그대로 이으면 잘못된 해석을 유도합니다.

**대안 (데모 적용):** 문항마다 **코드와 최초 도입 연도**를 관리하고, 신설·개정 문항은 **추이선을 끊어서** 표시합니다. 데모의 Q5(교권 보호, 2023 신설)는 2023년부터만 선이 그려집니다.

### ④ 리커트 응답을 원형 차트로 그리면 비교가 안 됩니다

문항별 원형 차트나 일반 누적 막대는 기준선이 제각각이라 **문항 간 긍·부정 균형을 눈으로 비교할 수 없습니다.** 리커트 척도 시각화의 표준은 중립을 가운데 축에 두는 **발산형 누적 막대(diverging stacked bar)** 입니다.

**대안 (데모 적용):** 중립("보통이다")을 정확히 중앙축에 정렬하고 부정은 왼쪽, 긍정은 오른쪽으로 뻗는 발산형 막대로 구현했습니다. 업무 부담(Q4) 문항의 막대가 왼쪽으로 2배 길게 뻗는 것이 한눈에 보입니다.

### ⑤ 중복 응답 통제와 익명성의 딜레마

구글 폼은 같은 사람의 반복 응답을 막기 어렵습니다. 그렇다고 로그인을 붙이면 익명성이 흔들립니다.

**대안 (데모 적용):** **학교 코드 + 1회용 참여 토큰.** 참여 여부만 별도 테이블에 기록하고 응답 데이터와 연결하지 않아, 중복은 막으면서 익명성은 유지됩니다.

### ⑥ 중도 이탈 응답의 회수

구글 폼은 제출 버튼을 눌러야 저장되므로, 중간에 창을 닫으면 그때까지의 응답이 모두 사라집니다.

**대안 (데모 적용):** **문항 이동 시마다 자동 저장**하고, 같은 토큰으로 재접속하면 이어서 응답합니다. 데모에서 문항 3번에서 중단 후 새로고침하면 그 지점부터 복구됩니다.

## 4. 화면 구성

```
index.html (교사 응답)
├─ 1. 참여 확인   — 학교 코드 + 1회용 토큰 · 익명 조사 고지
├─ 2. 응답자 정보 — 지역·학교급·직위·경력·성별 (교장/교감 선택 시 익명 안내)
├─ 3. 리커트 문항 — 8문항, 한 화면 한 문항, 키보드 1~5, 이동 시 자동 저장
├─ 4. 주관식     — 500자, 학교명·이름 자동 마스킹 고지
└─ 5. 완료       — 응답 요약

dashboard.html (관리자)
├─ 개요       — KPI 4종 · 문항별 발산형 누적 막대 · 집단별 종합평균
├─ 교차분석    — 집단 × 문항 교차표(히트맵) · 소규모 셀 자동 비공개
├─ 연도 추이   — 2020~2026 라인 · 신설 문항 선 분리 · 연도별 표본 수
├─ 문항 관리   — 8문항 · 코드/도입연도 · 비교 가능 범위 표시
└─ 검토 항목   — 리스크 6건 + 각 항목별 적용한 대안
공통: 5개 필터 · 사후층화 가중 토글 · CSV 반출 · 인쇄 레이아웃
```

## 5. 실서비스 제안 스택

- **Next.js + PostgreSQL** — 응답 화면은 SSR로 가볍게, 집계는 SQL 뷰로 처리. 연도별 파티션으로 축적 데이터 관리
- **스키마 핵심**: `questions`(코드·도입연도·버전) ↔ `survey_rounds`(회차) ↔ `responses`(익명) ↔ `answers`. 참여 토큰은 `participation_tokens`에 분리 저장해 응답과 연결하지 않음
- **집계 계층**: 마스킹은 애플리케이션이 아니라 **집계 뷰에서 강제**(n<5면 NULL 반환) — 화면·CSV·API 어디로 나가도 동일하게 적용
- **가중치**: 교육통계 모집단 테이블을 연 1회 갱신, 회차별 가중치를 미리 계산해 저장
- **반출**: CSV는 UTF-8 BOM(엑셀 한글), 인쇄는 `@media print` 전용 레이아웃

30일 일정: 1~5일 요구사항 정의서·문항 확정·스키마 설계 → 6~13일 응답 화면(자동저장·토큰) → 14~23일 대시보드(집계 뷰·마스킹·가중·차트) → 24~27일 CSV/인쇄·문항 관리 → 28~30일 **파일럿 응답 테스트**·산출물·매뉴얼
